001 v1 主动读了 14.5–21.5秒@4fps 和3–10秒@2fps。001 v2 成功读了0–3秒@3fps、15.5–18秒@4fps、18–21.5秒@3fps的单帧大图。002 v2 读了10–14秒@4fps和16–20秒@4fps的拼图。真实读图次数可变，包含自主选择窗口与因工具反馈调整请求，不是写死两次 LLM 调用。

002 v1的回看只复读概览已有帧，因此虽有工具调用，独立帧仍为46；后续修复：相同尺寸重复概览帧不再满足完成前细看条件，必须取得新帧、单帧大图或裁图。未把重复回看虚报成更多视频覆盖。

## 内容核验与保留问题

独立开发子 agent 直接查看拼图并补解码原始大图。此为 AI 辅助复核，不是篮球专家或人工标注真值。下面保留可由具体画面核对的问题。

- **001**：约20.5秒记分牌由 DAL 103–HOU 107 更新到105–107，18秒后白衣方在底线持球并发球。比分刷新有延迟，不能因18.75秒前未变就推断未命中。v1摘要同时说得分和抢篮板，v2改为突破近筐得分后底线发球，因果更一致。是否有突破分球或挡拆关系未看清，不应强行命名；v2仍未提供足够深入的战术解释。
- **002**：比分由60–63更新到62–63，支持两分；v1/v2都说三分，属于可核实错误。约17.5–18.5秒出手且防守人起跳干扰，v2却把出手提前到13–14.5秒，得分提前到14.5–16.5秒。v2同时写命中和对手抢篮板，仍有因果矛盾。素材从已经开始的进攻中途起拍，“完整攻防回合”过度断言；“压哨”应区分进攻时限与节末。
- 002在8–12秒攻入禁区受挤压后转移的过程被概括成外线导球，说明“能调用工具”并不等于“能挑出正确战术重点”。

原始输出保存在此目录的四份 `.json` 和四份 `.md` 中；未手工修正模型结果冒充成功。JSON仅抽取 status、plan、usage、provider、elapsedSeconds，不含密钥、本机绝对图像路径或图像 base64。`status=completed` 是结构化生成完成，不能据此认定解说可直接采用。

## 结论与下一步

增量实现达到了可运行、主动回看、生成带时机文字的试验目标；内容准确性和战术深度尚未通过。全片只给6帧确实不足以覆盖这些样片，但更多帧和循环本身也不能保证正确。

下一步应在同一工具接口上比较视觉模型，并用少量人工核实的事件时间/得分类型检查输出；优先解决002的事实和时间错误，再决定是否接网页。对现有绘图模块没有足够证据要求重写，本轮没有改动其生成或渲染流程。
