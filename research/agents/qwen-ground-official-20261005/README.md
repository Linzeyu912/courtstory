# Qwen 地面轨迹：官方两片真实实测

2026-10-05，America/New_York。范围仅为专用 Qwen 地面轨迹 Agent；基于 main `1e26b63450cfd601b2d410f435807c05b1d981e8`。用户认可回放并授权发布，本次修复、动态回放及轻量示例已作为 `b503573` 推送 main，见[发布交接](../../../handoffs/chuali-zi/2026-10-05-1430-qwen-replay-publication.md)。早期实测交接中的“未提交”保留当时状态。

## 结论

真实 `qwen3.8-max` 已能完成取帧、看图、修改锚点、拟合、回看 2D／原图回投、继续修正的循环。首版的任务创建错误、思考模式配置偏差、重复上下文和图片数量问题已修复。最终两次调用分别用时 174.5 秒／10 轮、101.9 秒／7 轮。

视觉效果仍不能判为全面通过：001 的小样本脚底定位改善；002 与原始定位大致相当，且把仍然可见的 1155 帧误列为未知。模型对腾空、落地和出画边界的判断不稳定。候选继续作为待复核建议，不据此宣称全场米制精度。

## 实际发现与修复

1. **任务创建失败**：首次 `_persist()` 早于工作线程建目录，触发 `FileNotFoundError`。现在先创建任务目录，再原子保存。
2. **思考开关未送到 API**：SDK 的 `reasoning: false` 只描述模型，没有发送 `enable_thinking: false`。使用 `reasoning: true`、`thinkingFormat: 'qwen'`，让 Agent 的 off 模式落实为 API 开关。改后再次完成文本、原图、函数调用、工具图片续读四步探针。官方依据：[深度思考文档](https://help.aliyun.com/zh/model-studio/deep-thinking)，核验日期 2026-10-05。
3. **上下文过大**：每条观测重复带相机诊断；001 首轮读取上下文后的请求约 116.5k 输入 token，精简后约 32.1k。保留真实逐帧时间、矩阵、人工锁点和不确定性，完整诊断仍在本地任务记录中。
4. **一次请求太多裁图**：模型请求 10–12 张裁图，但工具最多返回 8 张。现在在解码前检查，并在工具说明给出模式对应上限；失败原因进入审计。
5. **坐标估计不稳**：新增 `imagePoint` 输入，在程序内处理米制换算；带 `assetId` 时同时处理裁剪、标题、缩放和拼图格坐标。实测发现只自动换算仍不足，模型会认错鞋底位置，因此又给裁图加每 50 像素的刻度，并在回投图同时画原点和候选点。
6. **总结不可靠**：早期输出声称“标定缺失已插值覆盖”，与实际保留断段的数据不符。提示词已纠正，最新输出能报告这些断段；动作和未知区间判断仍须查看画面，不能仅信文字总结。

代码入口见[工程说明](../../../engineering/docs/qwen-ground-trajectory-agent.md)。没有更换 Qwen 模型，也没有调整检测、身份跟踪或球场算法来制造改善。

## 对照结果

另取每片 5 帧，由本轮执行者看原图估计鞋底地面参照位置，比较原投影、现有 light 平滑及 Qwen 版本的**原图像素偏差中位数**。参照点没有发给 Qwen；样本很少、与取证帧时间相邻，且包含单脚支撑／双脚中点的定义差异，只有调试价值，不是人工标注准确率或独立米制误差。

下表按同一版本实际仍有坐标的帧配对比较；缺测不能通过排除难帧获得“精度提升”。

| 样本／版本 | 可比较帧 | 同组原始 | 同组 light 平滑 | Qwen | 判断 |
|---|---:|---:|---:|---:|---|
| 001 v1：直接米制 | 5/5 | 38.6 px | 38.6 px | 60.1 px | 比原始更差 |
| 001 v2：原图像素 | 5/5 | 38.6 px | 38.6 px | 30.2 px | 局部改善 |
| 001 v4：图片坐标＋刻度 | 5/5 | 38.6 px | 38.6 px | 29.3 px | 局部改善，尚非全片验收 |
| 002 v1：直接米制 | 5/5 | 41.4 px | 41.4 px | 47.4 px | 比原始更差 |
| 002 v2：原图像素 | 5/5 | 41.4 px | 41.4 px | 62.1 px | 标题换算与鞋底定位偏差 |
| 002 v3：自动还原图片坐标 | 4/5 | 44.4 px | 44.2 px | 65.6 px | 换算正确仍不能保证看图正确 |
| 002 v4：图片坐标＋刻度 | 4/5 | 44.4 px | 44.2 px | 44.3 px | 接近原始，1155 被错误标未知 |

最终 001 为 `ready`，7 个锚点，296 个有效点，4 帧原标定缺失保持不填。最终 002 主动以 `partial` 结束，4 个锚点、2 段未知，只保留 163 个有效点；这不是网络失败，但也不表示视觉质量合格。它把 [1145, 1200) 标成未知，而 1155 帧的白色 1 号仍清楚可见，因此不能直接采用这段结果作为完成品。

全部 7 次有候选的运行、2 次被中止的早期运行、真实 token 用量、锚点、未知范围、API 探针和诊断数值在 [results.json](results.json)。token 包含大量缓存读取；费用没有估算，不能把 SDK 占位费率解释为免费。没有删除效果变差的中间轮次。

仓库的 [replay/](replay/) 已包含本次最终候选的两份轻量逐帧数据及索引，服务默认读取。拉取代码与官方两片 LFS 后，在现有工作台选择“Qwen 实测回放”，或打开 `http://127.0.0.1:8876/trajectory-replay`，无需配置 API key 或重新测试。

已有其他本轮本地结果时运行 `python research/agents/qwen-ground-official-20261005/export_replay.py`，然后以 `--trajectory-replay-root artifacts/player-review-replays` 启动服务查看。导出和播放不调用模型；重新导出需要本机完整实测结果。详细控制与边界见[工程指南](../../../engineering/docs/qwen-ground-trajectory-agent.md#查看官方实测的动态对照)。

左右分别为原视频与 2D 球场，支持同步时间轴、慢放、逐帧、原始／候选开关和关键帧跳转。两片都只显示本轮的单人实测区间，保留无标定与未知缺口。第二片可点“检查误删”查看源帧 1155。新增界面没有改变上面的质量结论，也未自动采用候选。

### 再次运行模型测试

先按工程指南安装 Python／Node 依赖并拉取两片 LFS。`QWEN_KEY` 从进程环境读取；本地 `.env` 可用 `QWEN_KEY` 或 `QWEN_API_KEY`，不会写入报告。以下命令会调用真实 API：

```bash
python research/agents/qwen-ground-official-20261005/run.py 001 --label repeat
python research/agents/qwen-ground-official-20261005/run.py 002 --label repeat
python research/agents/qwen-ground-official-20261005/evaluate.py --labels repeat
```

只准备视频、标定和输入时加 `--prepare-only`，不调用 Qwen。Windows 使用已装依赖的 `.venv/Scripts/python.exe`。复跑脚本保留本次固定场景和 AI 参照；模型有随机性，历史 v1–v4 代表当时不同实现阶段，当前代码重跑不会逐字重现旧输出。

下一步应优先用少量真人逐帧标注确定地面点的定义，并测未知区间的误删率；再扩到更多球员和更长片段。当前证据不足以支持自动全段替换原始轨迹。
