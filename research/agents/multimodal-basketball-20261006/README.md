**建议先对照 Gemini 3.8 Flash 与现有 Qwen3.8-Max，加入 Qwen3.8-Omni-Flash 检验声音的价值，再用 GPT-6 Astra / GPT-6.1 Sol 或 Claude Opus 5.5 复核关键帧与战术解释。** 如果需要本地研究，优先考察 Qwen3.8-27B。此顺序综合了视频接口、现有工程、成本和评测可操作性，不是篮球准确率排行榜。

## 研究范围与证据等级

通过 Exa 在“旗舰与接口、开放权重、篮球专项证据”三个方向进行 8 次检索，返回 45 条结果，按 URL 大小写与末尾斜线规范化后为 43 个不同 URL；重复或无关结果没有当成独立证据。对入选内容读取官方模型页、API 文档、价格页、原作者仓库或论文正文；OpenAI 部分另用官方文档检索和正文读取。[来源登记](sources.json)记录实际采用的来源，不保存整篇第三方网页副本。

- **官方规格**说明可以传什么、如何调用和如何收费，不证明篮球场景准确率。
- **厂商评测**只说明对应测试设置下的结果，不能把不同版本、帧数、字幕、工具和推理预算的分数直接排成总榜。
- **篮球论文评测**更接近项目，但本次找到的专项论文没有覆盖全部最新旗舰。
- **仓库实测**只代表已有两片、单人、约 5 秒区间的 Qwen 地面定位实验；不能外推为战术理解能力。
- **本文建议**是基于上述证据的工程判断，后续需同片验证。

## 篮球专项证据告诉我们什么

[BasketballBench / BasketballSkills 原论文](https://arxiv.org/html/2608.23435)构建了 7,980 个问题、10 类任务，材料包含 2,501 段回合级转播片段。其 Q8 同时要求事件类型与参与球员正确。Table 3 的部分结果如下，数值按论文的 0–100 标度记录：

| 论文中的模型 / 系统 | 只看事件类型的 F1 | 同时要求参与者正确的完整事件 F1 |
| --- | ---: | ---: |
| GPT-5.4 | 59.6 | 29.8 |
| Gemini 3.5 Flash | 51.8 | 27.0 |
| Claude Sonnet 5 | 43.9 | 14.3 |
| BasketballSkills 专项工具系统 | 60.9 | 45.9 |

**解释：看到“有人传球”与说对“谁传给谁”是两种难度。** 专项系统的价值主要体现在把事件与参与者对齐，不只是生成更长的解说。

边界必须一并保留：这是作者报告，未在本机复现；视频按 2 fps 测试，模型版本早于本文推荐的多款新旗舰。完整事件 F1 不是“挡拆 / 电梯门 / 西班牙挡拆”等战术分类准确率，不能据此宣称某个最新模型篮球能力已经排名第一。作者还报告给目标球员加真值框可改善识别；那是使用正确目标提示的实验，自动跟踪未必达到同样收益。

[Sports-QA 论文](https://link.springer.com/article/10.1007/s11263-026-02734-1)也强调，职业体育需要细粒度动作和时间关系理解。它与纯文字体育知识问答不同；知道篮球术语，不等于能在转播中定位相应动作。

## 对现有项目的判断

已有 [Qwen 官方两片实测](../qwen-ground-official-20261005/README.md)使用 `qwen3.8-max`，每片测试一名球员、约 5 秒。001 局部诊断改善，002 仍误把可见球员帧标成未知；参照、身份和标定未经人工真值确认。**当前证据支持“模型可参与反复看图的工具循环”，尚不支持“自动定位已可靠”，也没有验证战术识别。**

建议把下一轮任务分开：

1. **画面事实**：谁持球、谁掩护、谁切入、球传给谁、何时出手；每项附时间与画面证据。
2. **战术解释**：根据已确认的事件和人物关系解释空间变化与防守反应；区分确定观察、可能解释和无法判断。战术命名允许多个合理答案，不推断看不到的教练意图。
3. **精确几何**：逐帧脚点、持久身份、球场映射继续由现有工具与人工核对承担；不能以流畅文字或平滑轨迹替代定位验证。

这是研究建议，不改现有工程主线，不要求重新训练或立即更换 Qwen。

赛事落地单独判断：仓库 [2026-10-05 正式要求核验](../../../requirements/portal-access-20261005.md)记录 CPU + Bedrock、GPU 配额 0，以及 Quick Start 的 `global.anthropic.claude-sonnet-4-6` 和 `qwen.qwen3-vl-235b-a22b` 示例。这些与本文的最新云 API 名称不是同一件事。厂商写“支持 AWS / Bedrock”，不等于本队账号、赛事区域和权限已经具备；本轮未重新核对账户可用模型或改变赛事规则结论。

应记录每回合总输入、缓存、输出 / 思考 tokens、总耗时与工具轮次；模型单价低不一定每个正确回合更便宜。现有 Qwen 的 174.5 秒 / 101.9 秒是多轮轨迹任务耗时，不能直接与一次视频总结的延迟相比。

## 建议的同片验证：尚未执行

先用两段官方片做协议检查，再从已有人工复核库中挑选 10 段完整回合，覆盖持球挡拆、无球掩护、手递手、空切、弱侧轮转、遮挡和切镜。具体样本待人工确认，不预设官方两片包含哪些战术。

| 评测项 | 做法 | 判断指标 |
| --- | --- | --- |
| 公平的视觉比较 | 各模型使用相同时间戳和原图来源的帧序列；首次可从 2 fps 起，关键动作窗口再对照 8–12 fps，并记录裁剪 / 缩放 | 事件顺序、漏事件、错事件、参与者准确率；帧率为实验建议，非厂商精度保证 |
| 原生视频的实际收益 | Gemini、Qwen 视频接口另跑；固定片段与问题，记录实际采样 / token / 思考配置 | 相对统一帧序列的质量、成本与延迟变化；不与不同信息量输入混排 |
| 身份帮助多少 | 原画面与带已核对 P1–P10 编号 / 目标框两组配对 | 同一事件的参与者错误是否下降；提示组与自动身份结果分开 |
| 声音帮助多少 | Gemini / Qwen Omni 分别用有声和静音片 | 是否增加有效证据，是否被错误、滞后解说诱导；成绩不只看复述解说 |
| 战术解释质量 | 先给可观察事实，再解释掩护、换防、夹击、协防和机会形成；由懂篮球的人核对 | 术语正确、证据充分、参与者正确、无依据断言少；争议答案保留 |
| 时间与可解析性 | 所有输出有片段内时间、角色、事件、证据帧和不确定项 | 时间误差、合法结构比例；合法 JSON 不算内容正确 |

人工参照至少包括事件时间、参与者与可见依据。模型之间意见一致不当作真值；少量样本只用于淘汰明显不适配的方案。若没有第三方 API 条件，先用现有 Qwen 建立这套评测，保留后续可对照的输入与答案。

## 采集中的版本问题

- 旧 `docs.anthropic.com` 搜索结果仍出现 Opus 5 / Sonnet 5，而实际读取的 `platform.claude.com` 当前目录已是 5.5；本报告采用后者和 2026-09-28 发布说明交叉核对。
