# 球员姓名识别与脚底按需显示：方法调研和建议

日期：2026-10-07 11:22，America/New_York（UTC-04:00）。状态：需求理解、仓库核查及外部方法调研完成；本文为建议，尚未实现或验收，不代表团队选型。

## 需求理解

目标是将画面中的每名场上球员对应到真实姓名，遮挡或临时跟踪号变化后仍维持正确身份，并把姓名绘制在脚下随人移动。所有球员均参与识别和追踪；显示时可以全部关闭、全部显示、按球队或按球员选择，切换显示不触发重新识别。

本轮先讨论方法。后续建议先做离线短片闭环，利用整段视频中稍后出现的清晰证据；若要求直播，则不能利用未来帧，首次尚未获得身份依据时需要暂时显示未知。二者的准确率、时延和展示行为须分别评估。

## 现有材料能复用什么

| 已有能力 | 实际边界 | 建议复用方式 |
| --- | --- | --- |

## 建议主线：球队、号码、名单确定姓名，时间关系维持身份

### 1. 先限定比赛与候选名单

确定两支球队、比赛日期／赛季，取得对应比赛的名单或官方比赛记录，并记录来源。记分牌上的左右顺序不能直接等同于画面里白衣／蓝衣的归属，需用球衣文字、队标等可见依据建立映射。日期暂未确定时保留候选范围，不能拿当前球队名单套历史视频。

现有 2K 包的赛季履历可辅助查姓名；评分页面的球队、号码标签不能覆盖真实名单。数据包里的 `player_id` 是规范化姓名键，不是官方 NBA 稳定 ID。当前先保留其命名空间，取得官方球员 ID 后再明确关联。姓名依据独立于能力评分，不用能力值反推是谁。

### 2. 在轨迹里找到号码真正可读的时刻

按切镜、缺口、角色变化、外观／号码矛盾把 T 分成可信的连续片段。每段从原分辨率帧中选球衣正面或背面较清楚、遮挡少、尺寸足够的时刻，保存人物裁图与必要的全图上下文。清晰度高不代表号码可见，选帧还要判断朝向和号码区域。

先用现有 OCR 读取数字，再让多模态模型读取难例、背部姓名和球衣特征；输出看见的字符、候选和证据帧，允许无读数。可在小试中比较专用号码模型是否优于当前 OCR，暂不预设替换或训练。

号码保持字符串，`0` 和 `00` 独立；半个 `1` 不能自动补成名单中某人的 `11`。原图插值放大可方便查看，生成式超分补出的细节不能充当独立号码依据。

### 3. 跨帧汇总，再从名单查询名字

在已核对属于同一人的片段内，对可读号码做质量加权汇总：模糊／不可读帧不投票，近乎重复的相邻帧减少权重，不把几十张相同模糊图当作几十份支持。号码与球队、当场名单能唯一对应且没有反证时建立姓名关联；多个候选、名单缺失或证据冲突时继续补看或保留未知。

OCR 和大模型看同一张裁图的一致结果有帮助，但不是两份独立现场证据；大模型自报的 0.98 等置信度也不是实测正确率。姓名是否可靠与每帧是否仍跟对人、位置是否可靠分别记录。

### 4. 认出名字以后，继续核对是不是同一个人

维护“临时轨迹片段 → 稳定球员身份 → 名单姓名”的关联。一个球员可以对应多段 T；同一 T 串人时必须拆段，不能整条投票后覆盖另一人。连续画面主要依据运动连续性、局部外观及号码；遮挡前后比较球队、号码、护袖、鞋等细节和合理时间／位置关系。

相机运动会改变图像位置，续接应复用现有相机补偿；已有可靠球场坐标可以辅助，切镜后不沿用旧镜头像素距离。鞋、发型等外观只适合同一比赛内辅助续接，不能单独解出名字。

同一比赛时刻，独立的两个场上人不能占同一个身份；同队不同球员的号码／名单冲突应触发复核。检测重复框先去重，特写／回放先区分镜头类型和比赛时间，避免把回放与直播重复计为两人。画面可能没有十人全部可见；不为凑两队五人强分。换人后保留旧身份和入／离场区间，新上场者需要新关联，不能将十个 UI 槽位当作整场仅有十名真人。

离线视频可在稍后读清号码后，向前补充通过连续性或续接证据验证的同人片段；不能穿越尚未解决的交叉、长遮挡或切镜边界。已知“这个人是谁”不代表遮挡期间知道他在哪里，坐标允许为空。

### 5. 多模态模型按疑点主动补看

建议最小循环为：浏览候选片段 → 提出号码／球队／续接疑点 → 请求指定时刻原图和人物裁图或查询名单 → 更新身份候选。优先处理未知、冲突和新出现的人；已有稳定关联复用结果，不逐帧调用大模型。没有新增可用证据就保留未知，需要时让人确认一个清晰参考或修正一段，人工作为兜底。

第一版只需复用当前取帧、裁图、OCR、名单查询和区间绑定工具，增加选帧及身份结果组织。无需先做新的服务拆分、向量数据库或重训人脸识别。

## 各种证据的使用顺序

| 证据 | 主要用途 | 不能独立解决的部分 |
| --- | --- | --- |
| 可读球队文字／队标、号码、匹配比赛名单 | 确定真实姓名的主依据 | 名单日期错、号码未读清或历史同号会产生歧义 |
| 背部姓名／导播姓名字幕 | 核对候选 | 必须确认文字确实对应当前人物；字幕可能谈另一人 |
| 连续运动、可信跟踪与相机补偿 | 维持同人关联 | 跟踪器可能串人，需要号码／外观复核 |
| 鞋、护袖、局部外观／ReID | 遮挡后和跨片段续接 | 同队相似外观与低分辨率会混淆；不直接提供姓名 |
| 当场阵容、官方事件、解说音频 | 缩小候选、辅助检查 | 解说可能滞后、字幕／事件时间需对齐，不能凭动作习惯定人 |
| 人脸 | 有清晰特写时可额外核对 | 常规转播远景不作为主链路 |

上述组合为项目建议，尚未用本队视频比较准确率。

## 脚底绘制与开关

分析结果保存所有球员的身份、有限轨迹关联和逐帧图像位置；显示配置单独保存全局开关、选中球队／球员、是否显示号码和脚环。筛选只作用于渲染，关闭某人的名字仍参与后台关联与冲突检查，重新开启直接读取同一时间点已有结果。

标签可显示“姓名 · #号码”，文字保持屏幕方向，脚环锚在脚底。先复用当前框底中心和展示平滑，再对脚可见、遮挡或跳起的困难片段比较脚部／鞋部关键点；脚踝中点不是天然的地面接触点，跳起时要定义是跟随可见脚下还是显示估计地面投影。

身份明确但位置未知时，保留身份、暂停对应标签；低质量锚点可降级或隐藏，不沿用冻结坐标造成漂移。展示平滑不穿越切镜、串人边界和长缺口，原始观测保持。短时位置预测若后续需要引入，明确其估计状态和有限范围。姓名标签互相遮挡时可小范围错位配连线，减少文字占用。

只做脚下姓名跟随可以直接使用原视频图像坐标，不需要完整米制 2D 球场。若要求脚环严格贴合球场透视，再按需复用可靠标定；文字不必做透视变形。浏览器应按解码帧时间／原视频 PTS 同步，暂停、拖动和跳转结果一致。

网页里的开关通过独立叠加层实现。烧录进普通 MP4 的文字不能在同一文件播放时任意关闭；可交付“原视频＋身份位置数据＋可切换播放器”，需要固定成片时按选择重新渲染。两种输出复用同一身份结果和显示策略。

## 下一步建议与验证

1. 从官方 001／002及现有有名单的小样例中挑连续可读号码、同队交叉、长遮挡和切镜／回放四种情况，人工整理少量独立姓名与身份区间参考，不把模型结果当真值。先核实每段比赛和名单来源。
2. 比较“单帧 OCR＋名单”“清晰多帧 OCR／多模态＋名单”“再加疑点主动补看和续接”三种方法。号码专用模型只在现有路线短板明确后增加同片对照。
3. 评估已输出姓名的准确率及身份覆盖率、号码可读片段覆盖、串人次数与持续时间、未知区间、补看调用数和总耗时。分别核查姓名、续接、脚点和显示质量，不将有位置的帧数当姓名准确率。门槛根据实测讨论，不预设承诺。
4. 接全员／球队／单人显示开关，核对关闭和开启不改变身份数据，跳转／暂停对齐，导出选择生效；检查交叉、遮挡和跳起时名字是否指向正确球员。

本轮没有调用新识别模型、生成新成片或修改生产代码，以上是后续试验顺序。
