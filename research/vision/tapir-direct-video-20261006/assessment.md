# 这次小试对工作流方案的影响

2026-10-06，Asia/Shanghai。本机实验结果；尚未集成到工作台，未提交或推送。

**建议保留 TAPIR 作为自动跟踪的候选组件，让用户直接在视频上完成主要操作；2D 球场暂不作为必经编辑步骤，但后台地面映射能力仍需保留。** 这次验证的是一名球员的身体点，不能由此宣布十人身份连续、贴地箭头或完整 Agent 工作流已经可靠。

## 先看实际效果

[三栏半速对照视频](../../../artifacts/tapir-direct-video-20261006/comparison-threeway/comparison-half-speed.mp4)含同一个 5 秒片段的 150 个采样帧，输出为 10 秒、15 fps、1440×696，7,946,496 字节（约 7.95 MB）。数字 1–4 是同一目标身上的候选跟踪点，并非四名球员。

- A：现有 T2→T39 候选关联对应的检测框，在框内按相同比例放置四个参考点；缺失保持空白。
- B：首次 512×288 输入的原始 TAPIR 结果，保留实际失败输出。
- C：相同视频、相同原图种子的 256×256 输入控制，原样显示模型结果。

三栏完全共用源帧；不做插值、平滑或手工修点，TAPIR 仅显示可见分数大于 0.5 且在画面内的候选。上方保留全画面，下方同一区域放大。检测框内锚点和外观表面点的语义不同，本片用于检验可行性，不是严格同任务的模型排行榜。

## 已确认的发现

1. **跟踪运算本身并不慢。** 这次在 RTX 5060 Laptop 上，C 的 150 帧 / 四点推理约 0.900 秒；包括加载、解码和保存的脚本运行约 7.959 秒。B 分别约 2.190 秒和 10.461 秒。首次模型下载、实验代码准备、检查与对照渲染不计入这些数值。两轮都为离线处理、各运行一次，不是十人或在线全链耗时。
2. **接入方式会直接影响结果。** 首轮在查询帧本身就出现约 51–111 源像素的大偏移。源码及独立小网格诊断确认，这个固定官方版本的内部采样 helper 对横纵坐标都除以网格高度，非方形网格不适配。遵循官方默认方形输入后，查询帧误差约 1.8–3.3 源像素。没有改官方模型、强锁输出到种子或重新挑选点。控制同时改变缩放形状与细化层数，不能将所有画面差异只归到一个原因。
3. **适配后的 TAPIR 有补强价值。** 源帧 634、646 等原检测缺口内，C 的上身点仍在白衣 00 附近；800 的原关联缺口中仍显示该目标的身体候选，而 B 已偏到另一白衣球员附近。704、780 的候选也总体随目标。这里是关键画面的视觉判断，不是逐帧人工真值准确率。
4. **遮挡与接地问题仍在。** 源帧 660 的腰髋候选与前景裁判重叠，仍被判为可见；后段也会只剩一个可见候选。TAPIR 输出的高分数不能单独作为“跟对球员”或“真实脚底”的确认。模型判可见的帧数未被当作正确率。

这些判断由两位不同作者交叉复核：推理作者审查对照脚本与成片，比较作者复核原始数组、坐标变换和可见性计算。数值检查见 [root-numeric-review.json](../../../artifacts/tapir-direct-video-20261006/root-numeric-review.json)，三栏最终检查见 [review.json](../../../artifacts/tapir-direct-video-20261006/comparison-threeway/review.json)。技术检查通过不等同于篮球跟踪精度验收。

## 对下一版方案的建议

主流程仍由模型自动完成：检测与身份关联提供可靠起点，点跟踪负责短片内的连续位置，联合检查在遮挡 / 漂移 / 切镜处重新检测和续接，Agent 根据已观察到的动作调用现有标注与渲染操作。人工只在自动流程无法消除冲突时处理少量待确认项。

2D 作为可选视图和统一球场坐标保留。普通人物提示可以使用视频坐标；箭头需要固定在地板上、随镜头移动、或计算真实距离时，仍要地面映射。TAPIR 跟住球衣或鞋上的一点，并没有自动完成这一步。应减少用户必须手动经过的页面，不应据此删掉所需几何能力。

未来 Agent / 第三方 API 应接收带来源帧、固定身份候选、可见性与置信状态的结构化轨迹，并通过明确操作创建 / 更新标注、检查投影、预览和导出。该接口属于后续方案，本轮没有实现新 API，也没有修改当前战术标注布局、模块或用户草稿。

本轮可据此确定 TAPIR 值得继续接入评估；完整方案仍需用多人遮挡、切镜和真实地面标注验证自动纠错及映射效果。不要把单人四点推理耗时乘以十，代替真实十人测量。
