## 核查结论

多区间裁剪已经实现：[前端区间选择](../../../engineering/tools/player-review/footage-ui.mjs)把保留帧区间传给[裁切服务](../../../engineering/scripts/review_video_trim.py)，后者实际编码 MP4、同步候选、保留原帧 / 原时间，并在删除段两侧设置切镜。保留两段就能删除中间广告并拼接；可保留多个区间，最多 64 段。本轮没有改视频裁切算法。

原普通选人只保存人工位置锚点，轨迹计算同时查看前后两个带 ID 的锚点。因此未来新 ID 可能反过来参与过去帧的匹配，两 ID 同时存在时会导致过去帧冲突。它通常没有删除过去锚点，但重算结果可能改变过去的关联。

此外，原人工区间绑定在非锚点帧中总是优先，后面普通选人可能只改了这一帧，而其后的帧继续被旧区间压住。重复 ID 被多个 P 使用时，原实现把双方置为冲突；没有定向释放错段的规则。原行为见[先前分段纠正交接](../../../handoffs/Linzeyu912/2026-10-01-2137-track-id-correction.md)，本轮修正实现入口为[身份时间线](../../../engineering/tools/player-review/identity-timeline.mjs)与[轨迹计算](../../../engineering/tools/player-review/trajectory.mjs)。

## 本机修正后的规则

1. 身份和位置分别保存。`identityKeyframes` 是身份分界；`anchors` 是当帧人工位置。首次在某帧选人不会向此前回填，之后改脚点或框也不会建立新的身份分界。
2. P1 在第 1 秒确认 T10，第 6 秒确认 T60：1–6 秒之间用 T10，自第 6 秒用 T60，即使 T10 仍存在到片尾。第 10 秒再确认 T70，自第 10 秒使用 T70。错误从第 5 秒开始时，应定位到第 5 秒确认，或显式限定修正区间。
3. 以当前帧为起点，后续身份确认、后续人工区间规则起点或切镜作为边界。切镜后需要重新选人。新 ID 暂时没有框时留空，不回退使用旧 ID；启用短缺口估计时，也不跨身份分界插值。
4. 有限起止区间继续可用。身份分界和区间规则比较生效起点，较晚者优先；同一开始帧按人工操作序号决定。区间外恢复适用的原规则，区间内已有更晚确认保持。
5. 新人工确认独占相应 ID；重复占用时，较晚的生效分界优先，同帧以最新操作为准。旧身份仅在实际重复占用段变成 `missing`，记录 `identitySource=reassigned`、`previousTrackId`、`claimedBy`。不删除另一 P 的历史记录、不全局交换 P、不猜替代 ID。另一 P 后续正确确认继续生效；若仍是同一 ID，则反过来释放较早的旧占用。旧草稿没有新人工确认的重复关系继续报冲突。
6. 新身份生效后，原来绑在旧 ID 上的位置锚点保留原记录，但不再覆盖新身份。删除位置只删位置；删除身份分界或撤销会重算相应区间，撤销保存完整会话状态。

## 草稿与输出

旧草稿的原始 JSON 自动备份到浏览器原键的 `:before-forward-identity` 项，首次备份保持不变；实际用户草稿将在加载新版时迁移，本轮测试没有操作正式草稿。原锚点、有限区间和跟踪候选保持原值。

旧版没有独立身份字段，无法完全判断一次带 ID 的位置编辑是否也代表新的人工身份确认。迁移采用按时间排序、连续相同 ID 合并的推断方式，并标 `origin=legacy_anchor`；用户需复核迁移后的时间轴。之后的选人和位置编辑明确区分，包括重复确认同一个 ID 的新分界。

导出仍为内部 `schemaVersion=2`，新增 `settings.identityBindingMode=forward_only_v1`、实体 `identityKeyframes`，逐点保留身份起点、操作序号与释放依据。模型坐标、人工位置、缺口与估计仍分别记录，`allFramesManuallyVerified=false` 不变。服务新增该 JavaScript 模块的静态路由，前端 bundle 已重建。
