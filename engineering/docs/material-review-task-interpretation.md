## 对请求的理解

林泽羽希望何先对素材库进行分类、标注，再筛掉没有使用价值的低质量素材及难点覆盖重复的素材，尽量让每种难点都有代表片段。消息举出的维度包括清晰度、只有半场的画面、镜头推拉和中途特写。林泽羽预计随后上传正在查看的数据；目前无法从截图确认那些数据是否就是已经登记的上传批次。

这里优先做的是片段层面的素材盘点与难点标签。截图没有要求把所有素材逐帧标完十人身份、轨迹与球场，也没有明确要求开发新系统。已有战术动作标签可以沿用，补充画面难点和筛选意见即可。

“难点重复”结合“尽可能每种难点都有”理解为同类处理困难的样本过多，可以挑代表；这是推断，不能直接等同于同一球权重复。“只有半场”也可能指画面仅覆盖前场或人物出画，不自动等同于球权不完整或不合格。

## 建议的最小标注表

先用一个轻量表格，每段一行；多种难点允许同时出现，未看片的内容填待核实。

| 列 | 建议记录 |
|---|---|
| 片段 ID / 路径 | 使用固定全局 ID，避免不同批次的 003、005 混淆。 |
| 可见动作 | 挡拆、空切、传导、低位等；沿用已确认标签，草案仍保留待核实。 |
| 清晰度与可见性 | 球、球员、号码能否辨认；可用 / 勉强 / 不可用及具体原因。分辨率只是辅助。 |
| 画面范围与过程 | 前场半场 / 全场推进、关键人物是否出画；完整球权 / 局部配合另行记录。 |
| 镜头难点与时间段 | 平移、推近、拉远、特写切入、回放或遮挡；异常写视频秒数。 |
| 重复关系 | 同一内容的关联 ID，与不同内容但同类难点分开记录。 |
| 处理意见与理由 | 优先保留 / 难点代表 / 备用 / 待剔除，例如“画面模糊且与另一片段重复”。 |

上述分类是建议，不是已经写入所有标签的结果。

## 筛选顺序与完成产出

1. 先确认本次覆盖范围，尤其是截图所说的新数据是否已上传；从指定批次开始看片。
2. 先做少量片段统一口径，再按同一张表补分类和异常时间段。
3. 确认真正重复的球权 / 内容；同类难点则保留代表，兼顾不同动作和难点组合。
4. 汇总难点覆盖，列出代表片段、待剔除片段与原因，以及仍缺少的难点样本。

清晰度差但仍能支持某种困难场景研究的片段可以留作难点样本；关键动作无法辨认且没有独特用途的片段才建议剔除。中途特写不必淘汰整段，可先记录不可用区间。清晰的前场半场画面往往适合分析站位，不能因“半场”一项就删除。

“删掉”来自截图里的工作安排；本轮用户请求仅为同步和理解任务，因此本轮没有实际删除、裁剪或改标视频。后续可先给出待剔除清单，再在明确执行范围下处理。原始采集快照保留，复核结论写入整理层，遵循 [视频管理规范](../../docs/video-data-management.md)。

最终交付建议是：一份逐段分类表、一份难点代表清单和一份剔除理由清单。已有工作台可用于看连续画面、定位时间与筛直播区间；逐帧身份、轨迹和战术画布审核属于后续更细的工作。
