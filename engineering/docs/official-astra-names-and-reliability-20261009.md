## 为什么上一版没有姓名

上一轮最终交付的是 005 短样片。它没有执行姓名识别，传给解说和联合成片的输入也没有已采用姓名；因此只能产生匿名人物和无姓名的视频。这是试跑范围漏项，不能用“渲染器支持姓名”代替实际姓名成片验收。

本轮复用官方 001 的现有轨迹，重新调用 Astra 读取球衣号码和比较目标是否同人，再由已有同场名单查姓名。输入使用姓名识别前的 session，不复用前轮 Qwen 读数或已采用姓名。已有同源清晰帧索引仅作为取图提示，未给模型姓名、号码答案。模型仍必须提供实际图片证据；看不清、身份冲突或有效时间范围之外保持未知。

新增 `--player-name-provider openrouter`，读取服务端 `OPEN_ROUTER_KEY`（兼容 `OPENROUTER_API_KEY`），固定调用 `openai/gpt-6-astra`。使用原有姓名 job、采用和显示契约。Qwen 特有的 `enable_thinking` 不发送给 Astra。姓名、理解、润色、绘图、独立视觉检查全部使用 OpenRouter Astra；语音沿用现有 Seed TTS。

## 失败原因与处理

| 已观察的问题 | 为什么会升级为整个任务失败 | 本轮或前轮已落地的处理 |
| --- | --- | --- |
| 官方 001 多次在 480 / 600 秒内未保存完成方案 | 概览信息重复、未知姓名区间及全空能力记录占上下文；评分出处按字段和区间反复传递。部分任务到最后一轮才输出完整计划，来不及修正 | 模型只收具名有效区间；相同评分提取成共享 profile，保留每个实际引用及出处。去掉重复概览 / 资产文本。剩余 180 秒或剩余 4 轮时提示先保存，成功保存不再把完整宿主快照回灌模型 |
| 真实模型输出 `other + shotStatus=uncertain` / 空可选字段 | 生成端可选字段与保存端语义不完全一致，合法的非投篮意思被占位字段拦住 | 前轮已规范化无意义占位；真正冲突的 `other + confirmed` 仍报错。确认出手和证据要求不降低 |
| 本轮草稿给非投篮事件填写 `confirmed`，给普通节点填写无用反馈 | 工具 schema 的“可选”没有给模型明确可用的空值，模型倾向填满字段 | `shotStatus` 和 `shotFeedback` 明确允许 null，并说明非投篮使用 null；保留真实语义冲突检查 |
| cue 已引用正确人物，但遗漏姓名来源数组 | 旧错误把缺引用与真实时间越界都叫“姓名区间错误”，模型反复修错方向 | 宿主根据已经核对的 participantId 补齐来源；真实时间越界仍拒绝，错误给出 cue、人物和有效帧范围，不扩大姓名范围 |
| Astra 输出合法的单时刻暂停句，保存 / 润色却拒绝 | Agent 与渲染器允许开始、结束相等；job、润色和编辑层却要求严格大于。这是本轮复现的接口不一致 | 三个消费入口统一为暂停句允许相等、播放句必须有正时间窗；不改写模型选定的出手时刻 |
| 模型成功，宿主保存失败后只能重新请求整个模型 | 已成功的阶段没有作为可恢复输入消费 | 首份计划尚未保存时，复用同一视频 / 轨迹 / 姓名 / 模型配置的 completed worker 结果；先重新通过当前完整校验，再保存。拒绝候选和不兼容旧结果不复用，保留原 producer job 引用 |
| 图片传到绘图 Agent，但 `assetId` 和坐标变换只在宿主 details | 模型有图却无法合法绑定必需的资产字段 | 前轮已把实际资产 ID、尺寸和变换放入模型可见文本 |
| 单节点审核完成，最终原生合并才发现匿名 action 引用或人数超限 | 局部、视觉和原生转换校验不一致；反复重试不能改变确定性的合并错误 | 前轮修复匿名 subjectId / entityId 混用和背景观察重复合并。本轮继续提前检查图形唯一归属、主体重复、移动动作路线及坐标范围，错误在当前 Agent 的保存调用返回 |
| 本轮四节点审核通过，合并时仍因 screen 两个控制点失败 | 视觉审核确认了画面依据，但绘图工具未检查原生格式；screen 实际只允许一个锚点，方向 / 长度由 angle / size 表达 | 保存和原生采用共用控制点检查；保存时也检查锚帧属于图形时段。本轮只重新请求 n1 绘图与审核，保留其余三个已通过节点，未手改模型坐标 |
| 普通节点携带无意义的 shotFeedback，引出不存在的人物对应任务 | 旧模型填满可选字段，下游把不适用于当前节点的投手引用当成需要核验的主体 | 绘图输入只在 shot_release 保留 shotFeedback，原始保存计划不改动；配合生成 schema 的 null 选项 |
| OpenRouter 短暂 Connection error | 解说有续接，独立绘图原先直接退出；重新开始丢掉该节点对话和取证上下文 | 绘图沿用现有 transient 分类和同 Agent 续接，最多一次；鉴权、余额和非网络错误不按断线重试，模型不切换 |
| Windows 音频缓存临时路径过长 | 已生成音频仍因本地文件操作失败，后续整个成片停止 | 前轮已将临时文件改为短 UUID 名，保留缓存校验和原子替换 |
| 早期失败记录只有终态，缺少保存错误详情 | 难以判断应补证据、改接口还是继续网络请求，容易盲目重跑 | 理解已保存脱敏工具错误和拒绝候选。本轮为绘图补齐实时轮次、工具错误、连接续接和完整结果记录 |

这些错误不都来自模型内容能力：一部分是宿主接口和格式衔接，一部分是上下文与时间预算，一部分是网络。旧 001 日志没有保存每一次拒绝的详细原因，不能倒推它们全部由同一个字段引起。

对同一份旧 001 快照测量，修复前模型上下文文本约 280,480 字符，本轮为 29,277 字符，减少约 89.6%。仍保留 37 个可称名区间及 10 份共享评分 profile；完整姓名原始记录、未知区间、原始评分和图片资产仍由宿主保存、校验和恢复。这个数是 JSON 字符数，不是 API token 账单。

旧 001 日志中，模型响应报告的 `totalTokens` 曾从首轮约 2.1 万增到后续约 12–21 万，并记录过 Connection error 和最终预算中止。上下文精简与提早保存针对该现象；最终是否改善须以本轮真实结果判断，不能用静态测试代替。

本轮首次理解尝试 `3b8fe8fcf5d04e038f373417446b2af3` 在约 149 秒内经历三次 Connection error（包含两次同上下文续接），没有保存方案。独立诊断把同样 32 张图片、约 18.94 MB 请求发给 Astra，HTTP 200；因此没有证据认定为固定图片数或大小上限。新增 fetch 诊断只记状态、耗时、请求字节数及底层错误类型 / code，不记 URL、Header、正文或密钥。第一次失败缺少这层日志，不能声称已确定其底层网络原因。

第二次理解 `4e24355fcf314c49a2bc680a7f188761` 的 11 轮请求均返回正常，Agent 在约 451.9 秒完成；第 8 轮提前保存暴露了姓名引用和事件状态问题，第 10 轮又暴露评价证据超出前一秒窗口，模型在第 11 轮自行修正通过。随后宿主因单时刻暂停句拒绝保存。修复后通过上述复用逻辑保存成功，恢复未再请求模型，也没有人工重写文本、出手评价或证据。润色入口同样存在暂停句问题，第一次在 API 调用前拒绝，修复后继续成功。

这次再次说明：只测试单个 Agent 返回 JSON 不足以证明全流程成功。应优先检查真实模型输出能否被下一环节消费；不需要用更多整任务重试掩盖接口不一致。

## 本轮验收

姓名阶段 19 次真实 Astra 请求全部成功，没有请求重试；其中 9 次为进一步读取证据的 follow-up，不能误计成失败重试。总耗时约 440.5 秒，实际发送 115 张证据图，从 398 个来源帧评估清晰度。识别出两队十名球员：Amen Thompson、Jabari Smith Jr.、Tari Eason、Alperen Sengun、Kevin Durant、Max Christie、Daniel Gafford、Klay Thompson、Cooper Flagg、Naji Marshall。

应用后的 11,153 个球员位置记录中，8,797 个带姓名（约 78.9%，是位置覆盖率，不是姓名准确率）。其中 P2 的 1,126 个姓名位置仍为 needs_review：早段同一关联里读到 #10 与 #7 冲突，显示保留 `~`。没有使用人工槽位强制指定身份的实验方法，未知区间未强制扩名。帧 500 已检查十人姓名显示；出手锚帧 1005 的投手不在具名有效区间，解说保留匿名投手，不能声称投篮时刻已完整具名。

理解阶段发生一次真实网络失败后重跑；第二次 Agent 自行修正后完成，随后宿主暂停句错误以原 completed 结果恢复，没有第三次理解模型重跑。润色阶段在 API 前遇到相同时间校验错误，修复后一次真实请求完成。

绘图 job `531154c7-5544-4b34-9631-97ea65e9b8f4` 的四个节点都通过独立审核。首次原生合并因 n1 的 screen 控制点数量失败；修复共享检查后，只重跑 n1 的绘图与独立审核，n2 / n3 / n4 均复用。合并后四节点全部采用，八个图形，没有待审核图形或动作。任务保留 `partial` 内容质量状态：n4 对旧计划中无意义的匿名投手引用无法定位，未编造对应关系；不把这一局部缺口改标为全部质量通过。
