- 日期：2026-10-04，Asia/Shanghai。
- 状态：设计草案，待用户确认后形成实施计划。本文件中的新按钮、区间框修正和 Agent 任务尚未实现。
- 范围：本机工作台的素材入口、机器球员识别、区间人工纠正、战术 Agent、重点球员圈与图形归属。

## 1. 用户要完成的事

用户导入一个新比赛视频，机器先给出人物框和跟踪结果。发现某段认错人或框偏了，可以选择起止时间一次纠正。进入战术阶段，有明确的 Agent 生成入口，得到暂停讲解、平滑未来路线、挡拆标记和重点球员圈，再人工调整。

重点球员圈默认贴住所选球员的脚下并随人移动。路线和挡拆的球员归属与脚圈跟随分别表达。原视频展示不增加常驻球员姓名或编号标签。

当前素材列表精简到一个已制作示例，后续导入的视频自动加入当前列表。

## 3. 一个清晰的主流程

主导航改为面向制作过程的四步，保持原有处理数据和导出能力可进入：

```text
① 导入与识别  →  ② 球员与球场检查  →  ③ 战术制作  →  ④ 保存与导出
```

### ① 导入与识别

```text
我的视频                           [导入并识别球员]

[005 已完成示例] [新导入的视频……]

当前文件：xxx.mp4
机器状态：排队 / 读取视频 / 检测跟踪 / 整理结果 / 完成 / 失败
默认方案：篮球检测 + 外观续接        [高级模型设置 ▾]

[识别完成，检查球员]                失败时：[查看原因] [重试]
```

- 使用系统文件选择器，文件导入成功后立即调用现有识别队列；关闭选择器不产生任务。
- 导入、解码、识别有独立状态，上传成功不能标为球员识别完成。
- 默认使用已有篮球权重组合 `team-stable`。高级选项按所选权重的实际可用性启用。
- 任务完成自动打开这段视频的球员检查。重复点击不能重复提交同一个任务。
- 新视频即使人物结果为空，也能继续建立人工画布，明确显示检测缺口。
- 处理失败保留视频并给出错误摘要和重试；不把旧结果的「可打开」状态覆盖到新任务状态上。

### ② 球员与球场检查

```text
[原视频 + 人物框]                     当前选中：画面中的球员

修正范围： [起点 00:02.00] ━━━━━ [终点 00:03.50]
            [当前画面设为起点]    [当前画面设为终点]

要修正： [人物认错了] [框或脚点位置不对]
范围内预览： [起始画面] [中间画面] [结束画面]
影响：修改 30 帧 / 缺测跳过 5 帧 / 保留人工位置 3 帧

[应用这段修改] [撤销]
[自动标定球场] → 核对投影 → [进入战术制作]
```

- 时间输入与范围滑块同步，仍保留帧号帮助精确定位。默认纠正所选区间；单帧模式放到次要选项。
- 「人物认错了」：在代表帧点选正确人物，明确这段属于哪位球员，预览实际涉及的 T 轨迹和另一球员受影响的帧。
- 应用区间身份修正时拆分旧区间边界，完整修改所选段中的目标对应，保留区间外的记录。不能沿用当前「更晚人工边界优先」而悄悄少改一半。
- 「框或脚点位置不对」：在代表帧拖框或脚点，批量传播修正量；可以增加第二个关键帧表达偏差随时间的变化。
- 位置传播在各帧原始位置上应用相对修正，不把同一个绝对框复制到整段。关键帧之间插值的是修正量，球员原有运动与尺寸变化继续保留。
- 已有独立人工位置默认保留，结果预览明确计数；需要替换时用可见的选项操作。T 缺测、身份冲突、出画和切镜处跳过或分段，不创造不存在的人物框。
- 一次应用作为一个可撤销操作；结果保留来源，批量估计不自动变成逐帧人工审核。
- 球场检查接入远端已经完成的「自动标定 → 核对画面 → 进入 2D」流程，并保留人工兜底。

### ③ 战术制作

```text
战术制作                         [Agent 生成战术方案]
分析范围：当前回合 / 当前阶段

Agent 状态：准备画面 → 分析跑位 → 整理图形 → 候选完成
[候选阶段 1] [候选阶段 2]          [采用方案] [重新生成]

[选择 / 修改] [画路线] [挡拆标记] [重点球员圈]
[暂停讲解画面 + 平滑未来箭头 + 脚底圈]

选中路线：路线属于谁（可选）        [修改转弯点] [删除]
选中脚圈：脚圈跟随谁                [贴到脚底] [微调偏移]

[预览播放] [暂停] [重播本段]       [保存]
```

- Agent 主按钮始终可发现；不可运行时在按钮旁显示实际缺失原因，并保留人工工具。
- 首次空草稿生成回合阶段、暂停位置、少量重点路线、相关挡拆和圈；已有人工内容时默认补充当前阶段，保留已有图形和阶段设置。
- 输出先作为候选预览，采用后进入同一人工编辑画布，允许拖点、旋转、删除、撤销和保存。
- 每个对象标明是 Agent 建议或人工修改，审核仍由用户操作。
- Agent 提炼起点、主要转向和终点，控制点 2–6 个，禁止将逐帧检测噪声直接画成路线。
- 路线表达未来运动，关键时刻暂停后展示，再继续；播放时保留未走完部分。保留当前裁短方式并允许人工调整显示时间。
- 缺少有效球场映射时，候选仅用于暂停画面，界面明确提示并可一键回球场检查。身份或位置不足时缩小建议范围，不以 005 示例或固定模板冒充新视频的分析。

### ④ 保存与导出

- 保存覆盖当前草稿时检查版本号；浏览器临时记录与本机已保存状态分别显示。
- 保留完整 JSON 导出，新流程使用「保存草稿」等准确名称。
- MP4 烧录导出仍是独立能力；本轮不将保存或旧冻结报告宣称为成片视频导出。

## 6. 区间纠正的数据契约

新增结构化操作由前后端共同验证：

- `replaceIdentityRange`：视频/模型、球员槽位、目标轨迹、首尾帧、预览版本及影响对象；首尾帧均包含，内部一律使用零基索引。
- `correctImageRange`：球员、首尾帧、修正关键帧、模式（框/脚点）、已有人工位置策略；相对框修正保留原 `detectorBox`，脚点修正保留原始来源。

处理函数只修改同一视频和选中区间。已有 review-edit 校验和 sessionRevision 保护继续复用。应用与预览使用同一纯函数，UI 数量必须与实际结果一致。

区间结束后在下一帧恢复原有效身份；被挤占的另一位球员只释放实际重叠区间。拆分绑定不能改变区间外的位置、身份和审核状态。当前身份审核签名包含边界和顺序，因此不能简单插一个恢复边界后任由外部审核失效：保存旧关联来源，只有同帧有效身份、位置和原始观测完全一致时才能迁移原审核引用，保留审核人及时间；不得把原未审核记录变成已审核。

批量位置修正使用独立来源 `manual_range`，附加原始观测来源、修正方法、支持关键帧、操作 ID 和逐帧审核状态。用户实际拖动的关键帧与区间内传播帧分别记录，不能全部导出成普通 `manual`。

同帧有合法原始观测、对应未冲突的区间修正点可用于脚圈和展示，同时保留「区间修正、待核对」状态；缺测补出的点仍不得作为合法观察点。轨迹导出、脚点读取、地面投影、质量提示、审核及 Agent 输入必须共同识别这一来源，避免修完之后圈被隐藏，或将传播点误当逐帧人工真值。

更正只改变对应或显示几何，不自动确认人名、球衣号、地面真值或整个区间的人工审核。

## 7. 脚底圈和球员归属

- 「重点球员圈」工具优先通过画面中人物框命中，选择被点击的人；框重叠时给出人物候选，避免随机选择。
- 圆心默认直接使用当前合法球员脚点：已有人工脚点或已采用脚部候选优先，否则使用框底部中心 `((x1+x2)/2, y2)`。
- 默认偏移为零，有效球场映射只影响圈的地面透视形状，不成为画面脚圈跟随的前置条件。
- 选中时显著显示「脚圈跟随谁」；更换人时自动贴到新人的脚底。另设「微调偏移」「贴到脚底」及一次撤销。
- 老圈保留旧偏移，提供显式吸附动作，避免自动改变已有制作结果。数据增加明确的锚定模式，保存与校验同步兼容旧记录。
- 路线和挡拆属性使用「路线属于谁」「掩护由谁执行」等文案；归属用于解释与筛选，不会自动改变用户画出的路线。只跟随的圈直接读取人物位置。
- 缺测、身份冲突和切镜时隐藏对应圈，不能借用另一个人的位置。
- 同一视频、模型与帧映射下，进入战术页时同步最新人物结果，并补入新参与者；保留人工图形，受来源变化影响的路线显式提示重新核对。不同来源仍建立独立草稿。
- 建立人工画布的真实快照入口允许零参与者；正式轨迹导出仍保留其原有要求。

当前更新 reviewDigest 会使所有图形失效，刷新还会拒绝移除旧参与者。同步需要明确处理三类对象：同源且仍存在实体的新「脚点锚定圈」重绑最新来源并重新取得合法脚点；旧偏移圈与地面图形保留几何并标为待核对；关联球员被移除的对象进入可恢复的待重新关联列表，保存其原对象和旧参与者资料，不阻断其他对象同步。无效对象不强塞到当前有效参与者中，保存契约需支持这份归档记录。

## 8. 真实 Agent 的接入方案

### 可选方案与当前推荐

| 方案 | 适用情况 | 取舍 |
| --- | --- | --- |
| A：本机 GPU + 已登录 Codex CLI 作为语义 Agent（推荐） | 当前桌面工作台 | 利用已安装环境和登录状态；CLI 路径、额度、视觉输出需实际烟测 |
| B：本机 GPU + 直接多模态 API | 后续独立部署或服务化 | 更适合稳定服务接口；需要配置 provider、凭据和可用模型，本轮不推测现有账号配置 |

本机已核验 `codex-cli 0.160.0`，`codex login status` 为 ChatGPT 已登录；CLI 帮助支持图像输入、结构化输出 schema、JSON 事件和最后结果文件。**这只证明接口与登录状态存在，尚未证明篮球视觉任务成功。**

依据 OpenAI Docs 的[非交互运行文档](https://learn.chatgpt.com/docs/non-interactive-mode)和[命令参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)，A 方案采用固定参数的非交互任务，附带采样图像，要求输出符合 JSON Schema。沿用本机默认模型，不从文档名称猜测当前账号可用模型。

### 输入与输出

输入包绑定视频字节哈希、模型、原始帧映射、当前人物修正、球场映射与草稿版本，包含：

- 分析区间的时序画面与时间索引；长片按选择区间分批，不把首尾两张图当完整视频。
- 对应球员的框、合法脚点、身份建议/确认状态、主要运动采样及位置缺口。
- 已有阶段、图形和用户讲解目标。

输出为候选方案：阶段、暂停位置、参与者、动作依据、2–6 个控制点的未来路线、挡拆位置/角度、重点球员圈和需要人工核对的问题。必须使用输入中的实体和帧范围；对象可回看其依据画面。

输出 schema 统一使用本视频零基 `startFrame`、`freezeFrame`、`endFrameExclusive`；包含尾帧的身份区间只在边界转换。每个图形明确 `space`（video 原图像素 / court 米）、参考帧和控制点。脚圈优先返回 entityId 和脚点锚定模式。服务端生成对象 ID、阶段 ID 及来源绑定，模型不得提交或修改 review、人工审核、保存版本和来源哈希。

### 运行与采用

新增任务适配器，负责固定参数调用、超时、取消、日志、结果读取和严格校验；模型输出仅作为数据，不执行模型生成的命令。媒体画面和资料中的文字不作为执行指令。

CLI 自身也有工具执行能力，不能只约束最终 JSON。任务使用专用输入目录和受限工具/插件配置，至少以只读沙箱运行，不继承危险权限；使用 ephemeral 会话。采用环境现有登录，不把凭据写进任务包。实际烟测需同时确认视觉输出和用户数据、仓库无副作用。若本机运行无法满足这些约束，显示执行器不可用并转向配置 API 方案，不放宽权限来绕过。

新增接口：

- `GET /api/tactics-agent/status`：执行器可用性及明确原因。
- `POST /api/tactics-agent/jobs`：验证当前 session、来源、草稿版本与分析区间，建立任务。
- `GET /api/tactics-agent/jobs/<id>`：queued / preparing / analyzing / validating / ready / failed / cancelled。
- `POST /api/tactics-agent/jobs/<id>/cancel`：取消该任务。
- `POST /api/tactics-agent/jobs/<id>/adopt`：验证当前来源和版本后采用候选。

候选与人工草稿分别保存。请求期间用户修改图形、换视频或更新模型，迟到结果可以保留为旧候选，但不得覆盖当前草稿。采用已有人工内容上的补充时只追加本次生成对象，一次撤销恢复。

任务记录服务器已保存 version，以及请求时浏览器尚未保存草稿的 revision 和内容 digest。采用时服务端核对保存版本、来源和当前提交的草稿内容，前端在返回时再核对当前 revision/digest，任何变化都拒绝覆盖。采用事务以 jobId 为幂等键，重复点击/重试不能重复追加阶段或图形。

任务失败明确显示原因，不返回预制示例作为成功结果。Agent 不自动批准身份、位置或战术审核。

## 10. 验收必须看到的结果

1. 当前工作台素材选择和视频库只剩保留的 005；新导入一个文件后自动出现第二项，其他工作台素材和旧草稿可恢复。
2. 使用一个新文件从导入真正走到机器处理完成，打开实际人物框；缺少权重、处理失败和重试均有明确反馈。
3. 选择例如 2.00–3.50 秒纠正身份，区间前后数据不变，区间内既有边界处理与预览一致；缺测和切镜不伪造观测。
4. 一个区间的框/脚点可批量修正，保留运动，支持第二个修正关键帧；跳过、保留和修改数量准确，一次撤销恢复整段。
5. 点击人物放圈，圆心贴合法脚点，播放后继续跟随同一个人；换人后重贴，老圈的显式吸附可撤销。
6. 在处理页纠正位置后进入战术页，圈采用新位置，新参与者可选；空检测也可以建立真实人工画布。
7. 在新视频上点击 Agent 按钮，实际调用已配置执行器，输出与视频对应的候选，采用后可改路线、旋转挡拆、删除和保存恢复。
8. Agent 请求期间手工修改或切视频，迟到结果不覆盖；无执行器、无额度、超时或无有效分析结果不伪报成功。
9. 真实浏览器走通一次完整流程，并由独立复核者检查；程序测试通过与球员身份/战术判断准确性分别报告。
