## 目标与范围

用户希望现有前端更简洁、优美，具有苹果界面与 AirDrop 式的通透感、连贯反馈和流畅交互。建议以现有制作工作台为范围，先设计「战术制作」关键页，再推广到球员标定、可选球场映射和成片页。评委观看入口属于另一项页面设计，不在本轮扩展。

推荐方向是银白背景、深色视频舞台、少量蓝色强调、局部半透明玻璃控件。浅色是讨论起点；已询问用户对浅色、深色或跟随系统的偏好，写稿时尚未收到选择。以下数值均为拟议设计起点，不是 Apple 规范或已验证指标。

## 页面构想

建议关键页包含五个稳定区域：

1. 顶栏：素材名称 / 切换、保存状态、撤销、当前主操作；模型配置收进设置。
2. 左侧导航：球员、映射（可选）、战术、成片，使用统一线性图标和短标签。
3. 中央舞台：视频占据主要面积；绘制工具集中在画面外侧边缘的轻玻璃工具条，避免遮住球员、比分或关键落点。
4. 右侧面板：「助手」处理生成与候选，「属性」处理所选对象；切换保留各自内容。选择图形时展示对应属性，同时保持运行任务可见、可返回。
5. 底部时间区：播放、时间轴、标注区间与暂停点按层级集中；原片时间与成片时间保持明确区分。

普通浏览时只显示当前所需内容；模型来源、坐标、调试细节和备份按需展开。人工兜底入口仍可找到，机器候选、人工确认、失败与待处理状态在相关操作处清楚呈现。

## 视觉规则

| 项目 | 拟议规则 |
| --- | --- |
| 色彩 | 银白 / 中性浅灰为底，深灰正文；单一蓝色用于主要操作；球队色及审核状态色保留原有含义 |
| 玻璃层 | 用于导航、浮动工具条、菜单与弹层；浅色半透明底、适量背景模糊、细高光边和柔和阴影；避免多层玻璃嵌套 |
| 内容层 | 视频、时间轴、表单和长文字保持稳定、清晰的底色；视频本体不做模糊或折射处理 |
| 排版 | 正文以 14–15px 起步，辅助文字 12–13px，标题 18–22px；字体使用跨平台系统字体栈 |
| 间距与形状 | 以 4 / 8 / 12 / 16 / 24px 组织间距；输入与按钮约 10–12px 圆角，主要面板约 16–20px |
| 操作层级 | 每个任务区域突出一个主动作；其余使用次级按钮或文本操作；常用图标有标签或可访问名称 |

Apple 的公开设计说明将 Liquid Glass 主要放在浮于内容之上的控制与导航层，并强调层级、可读性及减少透明度 / 动态效果的支持。本计划借用这些原则设计网页；原生材质的完整光学效果不作为本次交付承诺。[Apple 官方说明](https://developer.apple.com/videos/play/wwdc2025/219/)

## 交互与动效

| 场景 | 目标体验 | 拟议实现边界 |
| --- | --- | --- |
| 按钮悬停 / 按下 | 立即响应，轻微压感，松开恢复 | 约 100–160ms；不延迟业务动作 |
| 面板与菜单 | 从触发位置自然展开，关闭回到原处 | 约 180–240ms 的透明度与小幅位移；正确恢复键盘焦点 |
| 工作区切换 | 当前状态清楚，视频与所选对象保持上下文 | 轻量过渡；不让画布参与缩放弹跳 |
| 视频导入 | 拖入时边框轻亮，导入后过渡到素材卡片和处理状态 | 可借鉴 AirDrop 的明确接收反馈；仅显示真实已知进度 |
| Agent / 导出 | 就绪、排队、处理中、完成、失败有一致呈现 | 耗时未确定时显示阶段与已用时间，不伪造百分比；已有结果和重试入口可见 |
| 时间轴拖动 / 图形编辑 | 指针、落点和画面同步 | 直接跟手，不添加缓动或吸附；播放不受装饰动画阻塞 |
| 保存 / 撤销 | 状态在固定位置更新，简短提示操作结果 | 提示少打断操作；浏览器草稿与服务端保存状态准确区分 |

避免全局 `transition: all`。大面积动态模糊和持续光效需要实机性能评估；浏览器不支持玻璃效果时使用实色回退。保留并验证 `prefers-reduced-motion`；计划提供降低透明度的可用方案。

## 后续实施顺序

本轮完成到计划与交流为止。用户决定继续后，按以下阶段推进，每阶段结果可以单独评审：

1. **设计样稿**：以战术制作页做布局和视觉稿，包含普通编辑、助手生成、选中对象三个状态。先确定层级、玻璃强度与浅深色方向。
2. **统一视觉基础**：梳理现有样式覆盖，建立颜色、字号、间距、圆角、阴影和动效变量；完成按钮、标签、表单、菜单、提示与面板的统一规则。
3. **调整关键页布局**：精简顶部、整理右侧助手 / 属性、汇集播放与时间区；检查低频功能仍有清晰入口。导入入口合并单独确认默认方式，不顺带改变模型调用策略。
4. **完善动效和其他工作区**：在关键页验证后推广到人物、映射、成片和视频库；统一空态、加载、失败、重试、保存、渲染反馈。
5. **隔离环境验收**：以真实视频和测试草稿验收布局及交互，再比较改版前后。发现问题先修复，不以静态截图代替操作验收。

不需要迁移整站框架。现有原生 HTML / ES modules 与局部 React 能承载本次设计。

## 工程影响与验收

- 样式主要涉及 [style.css](../../tools/player-review/style.css)、[pipeline.css](../../tools/player-review/pipeline.css)、[tactics.css](../../tools/player-review/tactics.css)。应整理现有覆盖关系，避免继续叠加末尾补丁。
- 结构主要涉及 [index.html](../../tools/player-review/index.html)、[workbench-shell.mjs](../../tools/player-review/workbench-shell.mjs)、[tactics-ui.mjs](../../tools/player-review/tactics-ui.mjs)，人物与映射按需调整各自 UI 模块。保留事件绑定、选择状态、草稿键和数据契约；相关 JSX / 打包入口变更后重建 bundle。
- 画布尺寸、视频矩形与指针坐标关联；布局和动画改变后，必须检查选人、圈选、画线、拖动、缩放及时间轴定位是否准确。
- 重点窗口：1440×900、1280×720、900px 宽；补查窄屏和浏览器放大。目标是常用操作易找到，主操作不被裁切，面板展开后视频仍可用。
- 功能回归：打开 / 切换视频、四个工作区、选中对象、绘制 / 拖动、撤销、保存、刷新恢复、候选展示 / 采用、失败重试、成片预览 / 导出。UI 验收不替代模型质量验收。
- 无障碍与性能：键盘可达、焦点可见、提示不只依靠颜色、减少动态效果生效；实测播放叠加面板开关的流畅性，模糊影响播放时降级材质。
- 当前页面初始化会保存草稿并自动发起身份初检。未来实屏验证应采用隔离端口、状态目录和测试数据，并禁用实际模型 provider 或使用确定性替身；`?qa=1` 本身不等于只读。
