# 未来路线展示与人工修正实施计划

Goal: 在已有战术工作台实现贴地未来路线、人工修正与阶段暂停播放。

Architecture: 纯函数 presentation 模块缓存合法球场路线；tactics document 承载独立展示修正；现有 UI / IndexedDB / CAS 保存；现有 video-display 解码帧驱动剩余路线。

Tech Stack: 原生 JavaScript ESM、SVG/Canvas、Node test、Python 本地服务。

Spec: `../specs/2026-10-03-future-route-editor.md`

## Global Constraints

- 当前 main 已同步到 4c6b9d8；不新建分支或 worktree，不推送。仅选择性提交本任务文件，保留所有原有未跟踪文件。
- 不修改原始视频、review 观测、身份/动作审核来实现展示修正。展示修正持久化为独立字段，旧文档兼容。
- 缺测、串人、切镜、异常跳跃及标定断点不可跨接；无当前帧标定不可复用旧投影。
- 播放只显示未走完路线；完成部分和终点圈消失。曲线预先平滑，播放只裁剪。
- 保持现有草稿排队写入、撤销、版本检查、QA/正式和候选/工作区隔离。
- 测试先验证关键行为失败再实现；不为低风险样式或文档编写镜像测试。不得派生代理。

## Review Focus

优先审核来源隔离、时间裁剪、投影坐标、拖拽及异步竞态、阶段跳帧暂停、导出范围。实现者报告测试证据，独立评审不重复执行相同测试；必要时针对具体疑点做小型复现。

## Task 3: 阶段暂停播放、浏览器验收与文档

- [ ] 扩展 `app.mjs` 到 `tactics-ui.mjs` 的播放器桥接，复用 video-display 的已呈现帧回调及现有 frameAtMediaTime / frameSeekTime。使用一个战术主画布，播放期间本地已解码帧为背景，不逐帧请求 JPEG。
