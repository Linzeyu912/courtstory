# 篮球专用检测与固定十人工作台实施计划

依据：用户 2026-10-02 明确同意上一轮诊断和修复路线；继续现有工作台，固定球员 1–10，并实测遮挡 / 断轨改进。此计划是已批准方向的执行拆分，不增加云部署、OCR、2K 或战术生成范围。

## 设计与约束

- 在现有 main 工作区实现，保留所有已有修改与草稿；不创建分支、PR、云资源，不自动提交 / 推送。
- 保留 P1–P10 的存储身份和向后生效的人工关联语义，显示固定球员 1–10。内部 T 轨迹可超过十个，不能把编号限制当作识别正确。
- 原工作台样例 005 是 SAS–MIA；新增 LAL–MIN 使用独立 sample ID `nba-lal-min-005`。同一原视频的模型版本共用原音轨、真实 PTS，草稿按版本指纹隔离。
- 引入可配置篮球检测入口，通过 model.names 找 player 类；低置信检测允许续接已有轨迹，不直接生成已确认球员。GPU 实测记录模型 / 权重 SHA、参数和设备。
- 优先现有 BoT-SORT 的外观特征和相机补偿，再以可靠球衣颜色限制明显跨队续接，低质量 / 遮挡外观不更新模板。去重保留真正相邻球员。
- 遮挡时保留身份，位置不强行补满；短缺口估计必须标明来源，长缺口和出画留空。模型建议不自动冒充人工确认。
- 继续候选记录数组：frame/time/tracks(7 列)/pending_detections(6 列)/candidate_count；允许附加 track_evidence。meta 必须匹配源视频 SHA 和帧数。
- 服务增加通用 trackingVariants 列表并保留 original / legacy alternativeTracks 行为。每个版本返回 trackingMetadata，供界面展示来源。可选 identitySuggestions 按 P1–P10 提供建议及分段绑定，只在用户主动采用时写独立 modelBindings，保留撤销和待复核状态，不计作人工确认。
- 本机已有 004–006 也用最终篮球配置生成新版本；原候选 / 原草稿保留。optional 跟踪版本未生成时仍能载入原样例。defaultVariant 仅选择实际可用版本，显式 URL 可查看旧版本。

## 任务与验收

1. [x] 检测 / 跟踪执行器：添加可复现篮球专用推理、低分续接、可选 ReID、可靠队色与重复框处理；同片段独立变量对照，生成完整逐帧候选、模型元数据及建议。先写有价值的回归用例，再实现；运行真实 GPU 片段。

4. [x] 整体验收：JS / Python 回归、真实服务与浏览器 QA 草稿、实际画面抽查跨队串号 / 重复 / 缺失、完整视频 / 音轨 / PTS 验证；独立代码和结果复核。
