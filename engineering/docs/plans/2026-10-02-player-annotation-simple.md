# 球员标注简化：2026-10-02

用户本轮要求：先看单人标注和固定 ID，暂停轨迹优化；界面简单，自动完成编号和分队，不要求理解或逐个配置“五人槽位”。

## 已确认的问题

- NBA 专用检测权重未换。004 的 optimized 与 team-stable 原始观测字节相同。
- team-stable 把身份分配与队色门槛耦合：004 的十个身份建议只留下五个，少显示 288 条本来可见的球员观测。
- 旧界面需要手动载入建议；没有固定身份关联的真实检测默认不画框。断轨后的新临时编号因此也消失。
- 004 第 178 帧只有三个已关联固定 ID，但另有三个可见球员框。恢复被队色删除的初始身份不能自动解决所有断轨关联。

## 本轮实现

默认入口为球员标注，保留原来的高级工作台。

```text
球员标注                    撤销   高级工具
视频选择
┌─────────────────────────────────────┐
│ 原视频：球员框、队色、脚下固定 ID     │
└─────────────────────────────────────┘
上一帧  播放  下一帧       时间 / 帧数
────────── 视频进度 ──────────
ID 1  ID 2  …  ID 10
选中的球员 / 纠正编号 / 更换队色
```

- 加载草稿后自动补充模型编号；原有编号和人工修改优先。无需用户先建立十个空位。
- 先分配身份，再附加队色。队色不确定仍保留身份和灰色框。
- team-stable 从原始观测 SHA 完全相同的 optimized 建议补回身份，不读取其他版本草稿，也不改变原始检测数据、元数据或草稿命名空间。
- 有明确 player 角色但尚未匹配身份的检测显示灰框。用户通过明确的纠正操作把它接到现有 ID；不强行占用别人的 ID。
- 普通点击已编号框只选择该球员，不确认或抢占身份；关联修改可撤销。
- 初始关闭轨迹尾迹和篮球 / 篮筐叠加。流程图、参数、球场标定、2D、轨迹修复和导出进入高级工具。

## 数据边界

- 十个固定 ID 不等于每帧十人都在画面中。检测缺失、遮挡、出画处不造框、不填隐蔽坐标。
- 自动编号与队色仍是模型结果，不冒充人工确认；未知碎片不声称已经认出同一个人。
- 不替换权重，不重新跑检测，不加入本轮轨迹插值或跟踪算法优化。
- 保留草稿、人工姓名、球队、身份关键帧、脚点、原片 PTS / 音轨、场景对象、脚候选和球场候选的原始约束。
- 补充建议必须与当前原始观测和视频匹配；剪辑后的建议不能引用父片帧号或父片 SHA。

## 验收

1. 默认首屏以视频标注为主，十个 ID 可选，用户不再看到槽位配置或五步流水线。
2. 004 自动恢复十个编号，并量化恢复前后的实际可见框数；断轨未知框仍可见、可纠正。
3. 队色未知不会抹去身份；ID 不随颜色变化或逐帧左右位置重排。
4. 普通点选不写入人工确认；明确纠错、撤销、保存和刷新有效。
5. 高级模式与默认模式来回切换不损失已有草稿。
6. 独立复核回归测试、实际浏览器画面、原数据 SHA 和候选缓存兼容性。

本设计根据用户已明确的范围直接执行；不扩展到战术路线或部署模型。
