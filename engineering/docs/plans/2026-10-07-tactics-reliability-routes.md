# 战术生成与人工补漏调整

日期：2026-10-07（Asia/Shanghai）。依据：用户对官方训练 002 连续两轮生成失败、路线不足、重点圈过多，以及逐帧补漏操作的反馈。状态：本轮代码与人工兜底验证完成，完整模型生成可靠性仍未通过；结果见[验证报告](../tactics-adjustment-20261007.md)。

## 使用规则

- 原视频分段抽帧分析，界面区分请求启动、等待模型、收到输出、校验和完成。
- 300 秒是整轮预算，初次调用留出自动修复时间；没有实质输出时提前结束等待并记录证据。模型错误不能统一解释成网络或额度问题。
- 移动者优先使用真实路线；按阶段覆盖持球、切入、顺下、外弹、接应和相关防守移动。静止参与者使用小位置标记，掩护使用掩护符号，重点圈仅给当前持球人。
- 实线表示当前动作，虚线表示后续已观察移动，不表示预测。证据不足保留人工事项，不以虚构路线达到数量目标。
- 漏人修正可在起点和终点各点一次，通过有界区间生成可预览、一次应用和撤销的估计位置。人工插值不称为模型检出，不制造检测框；切镜、遮挡或身份冲突必须中断。
- 不修改原片、其他任务数据或已有人工草稿；实际模型验证使用隔离工作台。

## 实施分工

1. 运行适配器：事件诊断、每次调用状态、无输出终止、保留重试预算与精简图像修复。
2. 标注合同与渲染：增加位置标记，限制 Agent 重点圈角色，检查真实移动与路线的对应。
3. 人工修正：复用区间估计，增加起终点流程、预览、应用和撤销。
4. 集成：状态文案、回归检查、真实 002 生成、浏览器操作和文件保护检查。

## 验证标准

- 模拟无响应、网络错误、终态模型错误和成功输出，核对失败分类、重试次数与预算。
- 已启动请求不能被显示为已收到模型输出；每段等待时间可见。
- 新候选中非持球人的旧重点圈转换成位置标记，人工圈保持；移动动作无路线时进入修复。
- 位置标记能在预览和正式渲染显示；旧文档继续读取。
- 手工补漏能预览整段、一次应用和撤销，不能跨切镜或覆盖冲突身份。
- 真实模型结果单独报告；自动测试通过不等于模型视觉质量或整个旧 runner 验收通过。
