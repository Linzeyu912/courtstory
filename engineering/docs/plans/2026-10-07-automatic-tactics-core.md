# 自动战术生成核心修复

日期：2026-10-07（Asia/Shanghai）。依据：用户要求自动完成主要战术标注，人工只负责核对与有限纠错。此前“人工兜底可用”不满足这个要求。本计划正在实施，不能作为已通过验收的证明。

技术：现有 Python 服务、Codex 非交互视觉调用、Node 原生战术校验与渲染。沿用仓库 `engineering/docs/plans` 的计划位置；不另建分支，不自动提交其他任务数据。

## 已证实的问题

1. 官方 002 的第四次第二阶段调用不是模型主动失败：每秒保存进度时，`state.json` 原子替换触发 Windows 文件占用错误，异常导致程序主动终止健康子进程。隔离复现确认该链路。
2. 第一阶段生成预览后，进度文件约 20.6 MB；每秒重写完整预览内容，扩大文件冲突和存储开销。
3. 前三次第二阶段无响应尚未根因定位。相同联系表的小型视觉任务两次均成功，只证明通道和图像能够工作。
4. 当前要求视觉模型同时完成真实动作判断、坐标、全量 V4 字段、样式、身份占位和账本。大部分格式字段可以由程序确定，不应占用视觉判断任务。
5. 独立输入 001 的第二阶段已在 89.761 秒返回完整 `agent_message` 和 `turn.completed`，但 CLI 的结果文件尚未完成落盘，90 秒边界仍被终止并重复推理。这是结果收尾竞态，不能归为模型没有生成。
6. 002 全片虽然在 238.781 秒经结构校验生成 7 条路线，独立视觉复核仍发现一条把传球前后不同白衣球员串成同一人。因此结构校验、生成完成和视觉正确必须分别报告，不能仅按路线数验收。

## 实施设计

- 保留当前可信 Codex 登录与来源校验，不依赖尚未配置的外部密钥。
- 模型输出紧凑视觉事实：局部人物、角色、真实动作、参考帧和观察帧、原图坐标、可见与不确定事项。模型仍须判断动作和有证据的路线。
- 程序确定性生成完整 V4 候选、字段、样式、阶段范围及已有球员义务；保留原参与者覆盖、参考帧、来源摘要和原生文档校验。
- 局部人物不能冒充已确认 P 身份；不可见、遮挡和镜头变化明确记录。不同画面的像素位移不能机械连成路线；路线坐标必须表达在指定参考帧中，并有实际动作依据。
- 重点圈仅给该参考帧当前持球人。其他移动者画有依据的路线，静止参与者画位置标记，掩护者画掩护符号。不得把所有人标成不确定或静止来获得成功。
- 失败只修复对应阶段，已成功阶段保留。修复仍计入整体墙钟和调用次数上限，不无限循环，不静默缩小分析范围。
- 将大型预览拆为带摘要的独立缓存文件，轻量状态只保存引用和进度。读取兼容旧状态；缓存损坏明确报错，不混入其他来源。
- 临时 Windows 文件占用有限重试；进度写失败不终止健康推理。必要保存失败单独报告，保留已产生结果和诊断，不误报模型失败。
- 明确完成事件后的完整 JSON 结果保留与收尾处理；只能使用通过事件类型、工具禁用及完整 JSON 校验的最终消息，禁止拼接部分消息冒充结果。
- 路线发布前进行独立原图视觉核验，逐条检查同人连续性、同时可见的不同队友、球权转移、原图参考系及持球证据。前次模型的 `observed` 声明不作为核验依据；无法确认的路线与错误圈不进入已通过候选。
- 自动核验和定点修复计入整体预算与调用上限；优先复用已解码的同源原图。未完成核验不得标作完整成功，已有效的路线不得被修复悄悄改成静止。

## 验收与交付

1. 先复现保存锁冲突和模型无响应，再增加对应回归检查；文件仍保持原子替换、正常取消和超时。
2. 相同官方 002 第二阶段真实调用需产生多人的有效标注和至少两名不同移动者的证据路线，再经完整 V4 校验。
3. 隔离工作台一次提交官方 002 全段，至少连续两轮完成全部阶段；记录首内容时间、各阶段耗时、重试、有效路线人物数、覆盖和不确定项。小 JSON 成功不算全段验收。
4. 另一已登记视频作为独立输入复核；真实视觉质量与自动测试分别报告。
5. 浏览器检查完整预览、持球圈、路线、逐项异常及人工采用行为。用户不需要逐个填写帧号或自行启动每个子阶段。
6. 不修改原视频、用户人工草稿或其他任务数据；核对保护摘要。代码回归、实际模型结果与产品可用状态分别记录，未通过项明确保留。

实现后更新工作流、状态和交接记录。当前任务不包含新增付费云资源、提取登录令牌作为 API 密钥或自动提交其他任务数据。
