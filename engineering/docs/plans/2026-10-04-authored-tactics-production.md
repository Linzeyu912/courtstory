# 将已认可的战术成片流程接入工作台

日期：2026-10-04，Asia/Shanghai。用户已明确要求把旧成片流程交给工作台 Agent，并保留人工修正。沿用 main 工作流；本计划按当前授权执行，不另建独立演示应用。

## 目标与验收

正式工作台完成：导入 → Agent 查看前后动作并编排 → 查看准确帧建议 → 采用到同一草稿 → 人工调整 → 成片预览 → 下载 MP4。旧 005 V2 的大箭头、四点曲线、近似地面镜头跟随、冻结逐步绘制、只留剩余路线和到达淡出作为渲染验收标准。视觉可展示与战术、身份准确性分开。

参考来源：本机 `outputs/future-route-video-20261003-v2/` 中的 authored_routes.json、render_authored_video.py 与已核对哈希的 MP4。参考视频只提供表现形式，不能成为新比赛的人物、动作或坐标证据。

## 数据与职责

- `annotations.items` 仍是唯一图形列表。路线可选 `authoredPath` 承载四点 cubic_bezier、完成进度、示意相机引用与 ribbon 外观；现有 points 为参考帧的四个像素控制点。
- 可选 `document.production` 存示意相机关键帧、来源/阶段绑定及冻结动画时长；不复制 routes，不修改 review.court、人物身份或审核证据。相机明确 approximate，需人工可调整。
- 普通 video 图形仍只在参考帧显示。只有显式编排、相机支撑和绑定合法的路线才能按新的连续示意投影显示；切镜和支撑范围外不得外推。
- 新 Agent 输出严格 V2，旧 V1 精确兼容。采用只增加当前任务内容，保留人工图形和既有编排。每个新增对象仍通过实际可展示检查。
- 共享 JS 几何与时间编译器生成每个输出帧的 sourceFrame、phaseId、展开率和 SVG。Python 只处理解码、像素合成、编码与产物验证，不重写曲线数学。
- 输出时间与原片时间分离：冻结时原片时间固定，展开动画继续；恢复后消耗剩余路线。默认静音，和旧片一致。

## 界面

第三步保持一个 Agent 入口和一个图形列表。四点路线可以拖端点/手柄；增加易读的路线完成进度、冻结时长与示意镜头角点调整。删除、撤销、保存与旧草稿兼容。

第三步增加“成片预览”，第四步提供“导出成片 MP4”。二者调用同一个渲染任务、播放和下载同一个已验证产物。任务显示进度与取消；草稿有修改则明确旧成片不是当前版本。原素材下载与 JSON/审核报告仍可用，但不可混称成片。

## 执行顺序与分工

1. 核心：扩展严格数据校验、Bezier/ribbon/示意相机、共享时间编译、Agent V1/V2采用以及原005配置转换。先用单元测试锁定旧曲线和386帧时间线。
2. 界面：接入同一文档编辑、编排调整、成片任务按钮和播放器，保存版本隔离、撤销与旧草稿往返测试。
3. 服务：Agent提示及可信风格参考帧；持久化不可变渲染快照、Node/Sharp常驻光栅化、PyAV顺序解码、FFmpeg编码；真实进度、取消、Range下载。
4. 验证：原005配置通过正式API转换、编辑和导出，与旧片抽帧比对；再用当前新片真实调用Agent验证生成而不是只回放固定配置。
5. 独立复核、操作指南、交接、选择性提交与远端SHA核对。浏览器当前草稿先保存备份；不覆写已采用内容。

## 必须覆盖的边界

- 旧文档/旧候选兼容，追加不覆盖人工路线、相机或暂停编排。
- 退化Bezier、进度倒退、相机退化/反转、支撑缺失、切镜、来源变化和画外几何明确拒绝或失效。
- 冻结前后准确帧一致，展开/收缩分别依赖输出/来源时钟；30fps输出不可直接当输入帧率。
- 所有原图形（路线/虚线/圆点/挡拆/脚圈）共享SVG输出；编辑手柄与人物定位框不进入成片。
- 任务绑定文档digest、源视频哈希、版本与渲染器版本。失败、取消不发布未验证MP4，不覆盖源素材或用户草稿。
- 不逐帧启动进程、不全量保存位图；输出帧数/时长限制与完整解码验证。
- 多机依赖从配置/已安装模块发现；本机Bundled Sharp仅作为当前可用运行时，不写成所有机器保证。
- 成片视觉验收与真实Agent质量分别记录；没有真实生成成功不宣称自动工作流已验收。
