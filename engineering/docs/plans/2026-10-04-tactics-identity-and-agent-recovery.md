# 战术制作：看清球员与生成初稿

用户反馈：图形操作只有 P1 等编号，无法判断画面中的人物；整段视频生成战术建议失败。目标是在现有工作台内修复两处，保留手工编辑和既有草稿。

## 已核实的原因

- 图形选项仅显示 participants 的 id/name；review.entities 内的身份参考、人物框未用于展示。P 编号是固定槽位，不是球衣号码，也不能证明整个轨迹一直属于同一个人。
- 2026-10-04 的作业 8b055f48-5733-4c07-b866-2dc64f629027 在模型返回前达到 300 秒超时。输入 JSON 234,809 字符，人物轨迹占 94.6%；1,060 条点中 697 条缺测。输入膨胀是待验证因素，不能在真实复跑前断言是唯一原因。

## 操作设计

图形操作 → 选择球员 → 显示队服和号码（有有效人工参考时）或“身份待确认” → 查看对应人物裁切图和当前帧核对状态 → “在画面中查看”临时突出这个人。当前不可见时明确说明，并可定位到有效参考或观测帧。定位只用于编辑，不创建图形，不改变绑定，不进入成片。

“生成战术初稿”读取视频和已有位置，为当前视频建立阶段、暂停点、未来路线与标记。结果先预览，采用后继续手工调整。缺少可靠身份时保持不确定，不把 P 编号当成识别结果。失败显示原因，手工操作仍可用。

## 实施与验收

1. 前端：统一球员文案、人物预览、定位；覆盖新建、已有图形、人物重叠候选与动作角色。新建路线默认不关联。
2. 后端：压缩轨迹输入，保留缺测和身份风险含义；不放宽输出或采用校验。保持模型、超时和图片不变，用同一视频复跑，比较输入大小与实际结果。
3. 保护：解码未完成不显示旧人物裁切；无效参考不推断号码；脚圈绑定/偏移不受查看操作影响；不覆盖用户草稿。
4. 验证：相关 Node/Python 回归，隔离目录真实 Agent → 初稿校验 → 浏览器预览，独立复核后更新本机服务与说明。

不增加新的模型供应商、永久球员标签或导出视频功能。
