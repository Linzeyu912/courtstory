# 最终执行计划：Agent 战术工作流、封装工具与多球员标注

日期：2026-10-06（Asia/Shanghai）。版本：Final v1。状态：**实施依据已整理；本轮只交付规划，以下新增 runner、tool、API 尚未实现。**

本稿合并聊天决定、现有代码审计和本机实测，替代此前的实施顺序。原稿保存在[模型主导旧稿](archive/2026-10-06-workbench-v2-model-first-before-final.md)，更早的手绘主线也保留在归档中。执行时同时使用[Agent 工作流程](../agent-tactics-workflow.md)与[工具合同](../specs/agent-tactics-tools-v1.md)：本文件管理目标、任务、依赖和验收；工作流程管理操作顺序与默认策略；工具合同管理输入输出和错误。

## 1. 最终决定

最终交付是**可由 Agent 一次提交、自动运行、检查、修正并导出成片的工作流程，以及支撑它的工具包**。现有工作台是查看、编辑和异常兜底入口，不要求用户反复操作三个页面。

| 事项 | 决定 |
| --- | --- |
| 用户主流程 | 输入原视频、区间和制作目标 → Agent 自动处理 → 返回成片、可编辑文档和证据。 |
| 自动化主体 | 检测／跟踪模型给位置候选，视觉模型解释身份与配合，确定性工具负责坐标、图形、版本、校验和编码。人工只处理无法自动解决的区间。 |
| 2D 球场 | 保留现有能力，按需作为后台几何数据层；不再要求每次先打开 2D 编辑器。视频局部暂停标注可以不经过球场映射。 |
| 2D → 实拍视频 | 贴地、相机运动中的地面图形和跨时间空间关系必须走明确的投影工具；人物身体点跟踪不能替代地面映射。这里的“3D 视频”指当前实拍视频，不承诺重建三维场景。 |
| TAPIR | 用于短段点轨迹候选、检测缺口诊断和重连证据；不负责姓名、球衣号码、球队、脚掌落地或战术理解。 |
| 球员标注 | 从“少数路线”升级为“逐阶段盘点全部实际参与者，再生成可读的多人标注”，包括相关无球人和防守人。 |
| 身份不完整 | 允许稳定匿名 ID；姓名／号码未知不阻塞有证据的标注。遮挡位置未知必须保留未知，不能补成已观察事实。 |
| 界面保护 | 不修改当前战术标注布局、工具和模块组成，以及撤销、保存、预览、导出行为。优先新增外部 adapter、runner 和文档。 |
| 成片风格 | 延续用户认可的暂停讲解、平滑大箭头、播放时只显示尚未完成的路线、稳定终点和接近完成时淡出。坐标从本次视频证据重新生成。 |
| 外部复现 | 本地 Agent、未来 HTTP API 和可选 MCP adapter 调用同一 runner，不分别实现三套业务逻辑。 |

不把“所有十人全程绝对正确”“球衣号码全部识别”“重建完整 3D 球场”作为第一版产出的先决条件。需要这些能力的具体图形独立接受质量检查。

## 2. 现有证据与能力边界

以下是已完成实验，不是本计划新增功能已经上线。

| 证据 | 实际结果 | 对实施的约束 |
| --- | --- | --- |
| [身份延续实验](../../../research/vision/player-identity-continuation-20261006/README.md) | 白衣 00 的 T2 → T39 局部连接增加 104 个位置；仍有 25 行缺失。 | 可以做局部重连；未证明十人身份或脚点全部正确。 |
| [直接视频／球场路径对照](../../../research/vision/direct-video-vs-court-20261006/README.md) | 同一 3 秒样本共用一次视觉模型调用 86.80 秒；直接视频阶段 12.58 秒，球场阶段 13.39 秒，后者另需约 25.08 秒标定与传播。 | 直接标注可减少几何步骤；它是固定图像坐标对照，不能当作运动相机下贴地精度证明，也不是完整新导入耗时。 |
| [TAPIR 实测](../../../research/vision/tapir-direct-video-20261006/README.md) | 同一 5 秒、4 个种子、150 帧实验，256×256 输入单次 GPU 推理 0.900 秒；源码／权重已缓存的脚本总运行 7.959 秒，不含下载和安装；部分检测缺口中保留了身体点。 | 仅是单次本机离线测量，不代表十人全流程性能、跟踪精度或第三方 API 速度。 |
| TAPIR 适配失败对照 | 512×288 输入在查询帧即出现严重偏差；方形输入的查询帧误差降到约 1.84–3.26 个源图像素。 | 首版固定已验证版本与方形输入，保存双轴变换，查询帧自洽检查失败就拒绝结果；不能拿高置信分数直接通过。 |

当前原生图形只有 route、screen、spotlight。可据此增加真实跑位、掩护和多球员聚焦圈。球员姓名／角色目前是编辑元数据或结构化说明，**不会直接烧进视频**；第一版不为此改造当前渲染模块。一般防守关系放在外层结构结果中，不能假装原生已支持新的防守图形类型。

当前 player_foot 跟随要求已声明球员和合法的原有轨迹；任意 TAPIR query 不能直接交给现有跟随器。court_player_foot 还需要外层检查位置来源，不能因为坐标有限就把 estimated 当成真实观测。现有本地接口不是已部署的第三方 API。

## 3. 给 Agent 的默认完整流程

~~~mermaid
flowchart TD
    A[提交视频、区间和目标] --> B[固定来源与版本，读取能力]
    B --> C[检测、身份与位置证据]
    C --> D[分析阶段、参与者和真实动作]
    D --> E{是否需要贴地或球场空间关系}
    E -->|是| F[准备与检查球场映射]
    E -->|否| G[生成多人标注候选]
    F --> G
    G --> H[逐人覆盖检查与逐帧投影检查]
    H --> I[原视频合成预览与独立复核]
    I -->|通过| J[保存新的派生文档]
    I -->|可修复，预算允许| K[仅修正失败区间，最多一次]
    K --> H
    I -->|仍不通过| L[返回部分可用结果和具体异常包]
    J --> M[正式渲染、完整解码、结果清单]
~~~

正常成功路径只需一次 submit；Agent 不需要模拟点击界面，也不要求人工逐步“采用”。自动通过策略后，runner 在独立结果仓库采用并保存新文档；不得覆写用户原草稿。

### 工具包

下表名称是**计划新增的统一工具合同**，不是已经存在的命令。

| 工具 | 责任与主要输出 |
| --- | --- |
| inspect_clip | 固定视频、准确帧／PTS、轨迹与文档版本；返回能力清单、来源快照和证据帧引用。 |
| prepare_players | 编排现有检测、身份和有界的局部修复，输出逐人证据、身份置信与可见性；TAPIR 适配加入后在这里调用。 |
| prepare_geometry | 按需生成并验证 H(t)、模板与投影可用区间；明确坐标单位和未知区间。 |
| analyze_play | 输出阶段、实际参与者、角色、动作、相关防守关系、依据帧和显示意图。 |
| build_player_annotations | 将已接受的动作和参与者编译为当前引擎可编辑的图形，输出新候选和逐人图形映射。 |
| check_participant_coverage | 对照独立的阶段参与者清单，检查每位相关球员是否真的有可见标注，以及缺失原因。 |
| check_projection | 检查来源、绑定、逐帧可见性、坐标、标定、跳点与裁切；不能只检查“编码成功”。 |
| preview_projection | 使用准确原视频帧和正式图形生成合成预览，供独立视觉复核，不写用户草稿。 |
| commit_candidate | 检查版本、人工锁和机器验收结果，采用并保存到该 run 的独立结果仓库。 |
| render_projected_video | 对已保存的准确版本渲染，完整解码验证 MP4，返回清单、耗时与结果引用。 |

运行控制统一为 submit_workflow、get_run、resume_run、cancel_run。模型可以分步调用工具，也可以只调用 submit_workflow/get_run；两种方式使用相同的状态和检查。

## 4. 多球员标注的明确规则

策略名称 richer_players_v1。目标是**参与者完整、画面可读**，不是给十个人同时堆满箭头。

1. **先盘点，再画。** 每个阶段分别记录画面中的球员与实际参与战术的人。角色可以是持球人、掩护人、顺下／外弹者、切入者、接应者、空间拉开者、主防者、协防者或未知。未知姓名保留匿名 ID。
2. **每个实际参与者都有交代。** 在其可见、可定位的时段，至少显示一种适合的路线、掩护符号或聚焦圈。静止参与者用位置圈；相关防守人也纳入，不能只标进攻持球人。
3. **不造动作。** 只有真实观测支持的移动才能画路线。被遮挡、出画或位置无法确认时，报告 unavailable 与依据；不能借平滑生成一段“看起来合理”的跑位。
4. **线型有固定含义。** 实线表示当前完整动作，虚线只表示后来真实发生、已由后续视频确认的动作。置信低、估计、预测不能用虚线包装。
5. **控制同屏密度。** 初始每个提示时段最多 3 条主要路线，聚焦圈软上限 6 个。超出时优先沿真实动作边界分阶段或使用已有合法关键帧，不删参与者来通过检查。不承诺当前引擎尚未支持的“同一冻结源帧任意轮播分组”。
6. **角色信息可读、可追溯。** 视频使用现有圈／路线／掩护；角色、匿名 ID、姓名证据和防守关系写入配套说明与可编辑结果。若以后要求视频文字层，单列适配落点及核心影响，不混入首版。
7. **覆盖度必须查实际渲染。** document.participants 有十人不等于标了十人；逐阶段逐人关联 annotationIds、证据帧、实际可见帧、隐藏原因。全程隐藏、画错人或无依据的标注都不能算 covered。

例如某次挡拆中，持球人有实际运球路线，掩护人有 screen 和位置提示，顺下人有真实顺下路线，弱侧接应人有静态圈，直接参与防守的两人有各自位置提示。动作先后复杂时分段呈现；这只是图形分配范例，具体人和路线必须来自该视频。

独立复核在生成图形前保留一份参与者清单，生成器不得通过删减它来提高覆盖率。无法确定参与者归属的帧返回异常证据；不能用泛化的“低置信”理由豁免所有漏标。

## 5. 坐标、TAPIR 和质量失败的处理

外层 sourceSpace 只有 image_pixels / court_meters；displayIntent 为 reference_frame / fixed_interval / declared_player_follow / court_projection。这些是工具语义，不是给原生 schema 添加新枚举。

| 制作要求 | 必要证据与策略 |
| --- | --- |
| 在暂停帧讲解多人站位／动作 | 当前帧可靠坐标，或有可靠映射支持的跨时间位置；不自动要求完整 2D 轨迹。跨帧路线归到同一冻结画面时，须校正相机运动或证明误差在门限内。 |
| 随人物移动的提示圈 | 已声明球员、正确身份和当前引擎可消费的合法逐帧位置；不能把身体点伪装成脚点。 |
| 区间固定图像图形 | 明确是固定像素图形；相机移动时不能把它声称为贴地。 |
| 贴地路线、球场位置和实际空间关系 | 合法接地点、逐帧映射、正确球场模板及独立回投检查。 |
| TAPIR 补点 | 保存 pointTrackRef、种子、预处理变换、遮挡与不确定度、anchorSemantics；默认只是候选证据。 |

TAPIR 首版使用已经测试的官方代码和权重版本，方形 256×256 输入，保存两个轴各自的缩放。查询帧自洽是必要适配检查，不能替代身份和轨迹质量检查；细节及初始门限写在工作流程。存在新身体点跟随格式需求时，先返回 capability_unavailable，并记录具体差异；仍可交付其他合法的暂停标注或原有轨迹跟随。

自动修复只覆盖失败区间；默认最多一轮。缺少几何时，可在允许部分结果的任务中返回明确的暂停讲解版本，并标记未完成的贴地需求；用户明确要求贴地的任务不能静默降级。完全无法形成有证据的标注时返回 needs_attention，无效视频不算成功。

阶段出口：

- **M0（T00–T03）：工具骨架能实际运行并安全保存、导出。**
- **M1（T04–T05）：Agent 能一次调用生成比当前更丰富的多人战术标注。** 这是优先验收的可见成果，不等待 TAPIR、十人全程或 2D 分支完成。
- **M2（T06–T07）：改善连续性并扩展多人覆盖。** 不将局部点补齐冒充全局身份问题解决。
- **M3（T08–T09）：贴地与异常恢复可靠。** 基础预览／硬检查已经包含在 M1，不延后到这里才验证。
- **M4（T10–T11）：第三方可调用、可恢复、可复验。**

## 7. 验收设计与出门条件

### 样本与对照

使用 6 段 3–8 秒视频：当前 Pacers 白衣 00 样本、已认可的 005 战术样本、库内 001／002 真实映射确认后的片段，以及覆盖严重遮挡／交叉、十人画面／出画或切镜的补充片段。T00 核对准确文件名、SHA 和源帧区间；不得只凭编号挑文件。可以从同一视频选择不同片段，但须披露样本局限。

同片比较原方案与 richer_players_v1，输入、基础检测、硬件和是否复用缓存一致。分别做 1 人、3 人、最多 10 人负载检查。人工仅为离线验收标注参与者及关键帧，不成为运行中的坐标输入前提；完全不可见的位置不编造真值。

### 必须通过

- 一次输入即可自动得到 MP4、可编辑文档、coverage、质量报告和 manifest；运行时无需打开 2D 页面。
- 在有 ≥3 名实际参与者的样本中，除持球人外覆盖有证据的无球配合者；相关防守者不能因生成器忽略而漏掉。
- 逐阶段，每位已确认的可见且可定位参与者至少有一次正确可见图形；不能整片只亮一次就通过其余阶段。未知或无法显示者有具体来源和区间，不与 covered 混算。
- 验收集内自动接受的结果不得含已确认的错绑人物或无依据路线；这是有限样本出门条件，不是现实世界零错误保证。
- 原生 schema、来源、版本、逐帧投影和最终 MP4 完整解码均通过；实际看片检查遮挡、跳动、错位和画面拥挤。
- 地面分支使用未参与拟合的场线／参考点检查。初始工程目标为源图 720p 等效中位误差 ≤6 px、P95 ≤12 px；由 T00 确认真值可测性与适用样本，调整必须版本化且不得将调低门限冒充性能提升。
- 原布局、工具、撤销／保存／预览／导出回归通过；新 adapter 关闭即可回到原流程，不删除现有资产或草稿。
- 重复提交、失败恢复、服务重启、版本冲突、人工锁、预算耗尽及取消后的迟到输出都有可验证结果。

### 记录但不能偷换概念的指标

参与者覆盖率、身份错绑数、缺失区间、轨迹跳点与位置误差分别报告。平滑程度不能替代正确性；插值不能算观测覆盖；TAPIR 可见分数不能算跟踪准确率。

耗时报告模型准备、检测、跟踪、身份、战术分析、几何、预览／修复、编码、排队及端到端时间，分冷启动／复用缓存，重复次数随报告披露。样本不足不编造 P95。费用不可测时为 null，不能写 0 元；不根据 0.900 秒推理外推十人端到端时长。API 并行必须实测 1/2/3，并保留串行身份合并与版本提交。

## 8. 第一个执行批次

执行 Agent 从 T00–T03 开始：读取这三份合同 → 核对当前仓库与未提交改动 → 记录保护清单 → 固定测试样本 → 建立 schema 和持久 runner → 通过现有图形／保存／渲染工具跑出一个独立成片 → 交独立 verifier 检查。随后直接推进 T04–T05，展示更丰富的多人标注。

不要先重写工作台、训练新模型或新增 2D 页面。遇到来源不匹配、版本冲突、未知原生能力、预算不足或要求必须贴地但无可靠标定，按工具错误返回具体异常；禁止绕过校验器、修改历史跟踪来源或覆写人工锁来完成任务。

## 9. 最终交付包

每次 run 至少包含 manifest.json、run.json、play-analysis.json、player-evidence.json、annotation-map.json、coverage.json、quality-report.json、最终可编辑 document.json、预览、result.mp4，以及必要的模型／标定引用。未完成任务也交付状态与可复查的异常包；不把半成品标成 succeeded。

代码交付包括同一份工作流程定义、工具 schema、runner、薄 adapters、CLI、API 使用示例、固定样本测试与回滚说明。Agent 操作顺序及默认预算以[工作流程](../agent-tactics-workflow.md)为准；接口、状态和错误以[工具合同](../specs/agent-tactics-tools-v1.md)为准。
