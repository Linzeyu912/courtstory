# 第一部分：视频身份初稿

第一部分球员标定复用第三部分的视频阅读工具，生成可人工审核的 P 身份、有限 T 关联区间与有名单依据的姓名候选。机器结果仍需审核；匿名、未知和部分结果都允许保留。

## 使用

1. 从视频库打开素材，进入球员标定；页面自动启动一次身份初检。没有检测框时先调用现有检测流程，缺少权重或观察时显示实际原因。
2. 在姓名表单选择已知赛季、两组实际球队及 NBA 比赛编号。已保存的上下文优先，包括主动清空；未知素材不会把占位文字当作比赛事实。
3. 查看问题并定位画面，按需要修改人物关联区间、排除非球员、补点和确认姓名。机器初稿不覆盖人工修改或自动升级为人工确认。
4. 初检的身份与姓名作为一次草稿更新保存，可以一起撤销。保存稿重载后，姓名面板直接显示有效区间内的候选；“高级：单独补查姓名”仍可使用。
5. 第三部分从当前保存稿读取身份和姓名快照。部分结果可先使用，其他区间可人工补充或显式继续检查。

## 实现与保护

- [identity_video.py](../scripts/identity_video.py) 复用视频解码、总览、源帧窗口、区域图片和 provider；[identity-worker.mjs](../tools/player-review/agents/identity-worker.mjs) 使用独立身份提示与保存工具。
- 宿主核对视频来源、实际读图、时间基准、区间端点、缺测、切镜和关联冲突；机器关联仅作用于真实存在的有限观察区间。
- [比赛名单](../../data/player-rosters/README.md) 按明确上下文和号码产生唯一姓名候选。无可靠证据时保持未知；没有使用人脸识别。
- 人工姓名、人工区间、位置、排除和审核记录优先。过期来源、换素材、迟到结果及不匹配草稿不得覆盖新稿。
- `ready` 只表示已有可读候选；完整程度另看 `candidate.completionStatus`。`partial` 不是全片识别通过，显式续接最多两轮。

## 配置与接口

身份、姓名、解说和 Polly 共用服务端明确指定的 `--env-file`，支持 UTF-8 和带 BOM 的 UTF-16；同名进程环境变量优先。独立绘图继承 Node 代理配置。安装需同时执行工作台与 `agents/` 的 npm 依赖安装，见[本地启动](local-setup.md)。

`GET /api/identity-agent/status` 的 `initialReview` 返回配置状态；`POST /api/identity-agent/jobs` 的 `purpose: initial_review` 使用 `video-identity-review-v2`。available 只代表配置检查通过，不代表模型真实请求或识别质量已验收。
