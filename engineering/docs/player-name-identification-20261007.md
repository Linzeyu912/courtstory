日期：2026-10-07 12:30，America/New_York（UTC-04:00）。状态：本机 main 已实现并完成定向测试与真实模型／短片试验；未提交、未推送，十人全片姓名准确率仍未验收。

本文保留首版及 v3 的历史验证口径。用户要求减少未知并修复串人后的最新实现、真实模型复测和全片结果见 [v4 优化记录](player-name-optimization-20261007.md)；后续消费层按有限重叠处理冲突，不再采用本文早期的整 P 姓名拒绝规则。

## 操作与数据

在球员标定页的“全员姓名识别”填写赛季、红组 A／蓝组 B 的实际球队缩写；可选填已经收录的 NBA 比赛编号。点击“识别姓名”会对全部已关联球员选取真实人物框证据，不需要逐人先手填号码。模型只读球队文字与球衣号码，姓名来自所选比赛或赛季名单。没有有效绑定、不可读号码、名单不匹配和角色／身份冲突保持未知。

首轮每人最多八张图，针对未读、单读或矛盾再补看最多四张未使用的源帧，每人至多两次请求、总图不超过十二张。请求失败保留已有结果，不无限重试；读取时保持 `0`／`00` 区别。不同有限片段分别投票，清晰片段不被另一段的单张离群读数整体否决。两份不同源帧支持并不代表独立人类真值，机器结果始终标记待核对。

选择“加入候选结果”只写 `entity.machineNameIdentities`，保留视频／跟踪来源、有限起止帧、T、证据及姓名候选，不改原始框、脚点、轨迹或 `playerProfile`。已有人工姓名和来源匹配的 confirmed profile 优先；“白1号”等工作标签不会被当作已确认真人姓名。同一 P 出现互不相同的可靠号码时列出 `identity_conflict`，该 P 的机器姓名先不采用；其他独立 P 的候选不受影响。

“显示姓名标签”可全部关闭，按红／蓝组或单个球员选择；姓名、号码、脚环也可分别切换。配置独立保存在浏览器展示存储中，关闭显示仍保留全部分析、身份和位置结果。暂停寻帧、载入或失败时清空并隐藏姓名层，仅当目标解码帧已发布才绘制，避免把新帧的名字画在旧画面上。

姓名锚点复用当前展示位置与平滑，缺少位置时不画、不冻结旧坐标。当前仍主要为检测框底中心，未证明为真实脚部接地点。轨迹备份导出包含全员逐帧姓名／位置与显示配置，正式战术 MP4 在创建任务时接收同一快照，并按原视频源帧号绘制。网页可随时开关，普通 MP4 为固定烙字，需要按新的显示选择重新渲染。

## 本机运行与接口

默认姓名视觉 provider 延用现有配置。本轮按用户要求用显式的交互测试入口优先调用 Qwen Token Plan：

```powershell
python engineering/scripts/serve_player_review.py --library data/videos/tactics/acceptance/review-library.json --port 8892 --player-name-provider qwen-token-plan-interactive
```

本机根 `.env` 读取 `QWEN_TOKEN_PLAN_KEY`，默认 `qwen3.8-max`、北京 Token Plan 端点，无按量 Key 自动回退；号码读取显式关闭思考模式。本轮按人在 Codex 中发起并检查的交互测试使用，不将套餐默认作为常驻生产后端。配置项与实际模型能力边界另见 [Token Plan 已有试验](../../research/agents/qwen-parallel-20261007/README.md)。代码、日志及本轮文档不保存密钥。更新代码或名单后请重启工作台，以重新载入模块和名单缓存。

| HTTP 接口 | 用途 |
| --- | --- |
| `GET /api/player-name-identity/status` | provider 配置状态；不读取账单余额 |
| `POST /api/player-name-identity/jobs` | 传 sample、variant、qa、session、clientRevision、season、teamMap，可选 gameId |
| `GET /api/player-name-identity/jobs/<id>` | 按相同 sample／variant／qa 读状态和候选 |
| `POST /api/player-name-identity/jobs/<id>/cancel` | 取消，迟到结果不采用，原草稿保留 |

相同快照复用正在运行或完成的任务。失败可显式重试；模型运行期间草稿、视频、跟踪版本或识别上下文变化时旧结果不能应用。服务重启可读取已完成任务，未完成任务明确标为失败，不悄悄续跑模型。

新 [按比赛名单](../../data/player-rosters/README.md) 独立于 2K 能力表，当前收录 `0022500701` 的官方实际出场球员。名单保留来源／日期；姓名键为 normalized_name_key，不冒充官方 NBA 稳定 ID。本任务未改原视频标签、2K 数据包或原始快照。任务初期旧版 2K 包 DAL `32`／`31` 查无记录；收尾由另一会话同步了覆盖范围更大的数据包，该历史缺口不能推广为最新版缺口。按比赛名单仍用于明确比赛当天的出场上下文。

## 实际验证

### 真实 Qwen

输入是已有十人身份区间的官方 001 独立 QA 副本，原视频与正式草稿保持。按画面 DAL／HOU、比分／节次和月日交叉核对，显式选择 2025-26、A=HOU、B=DAL、比赛 `0022500701`。

- 首次思考模式开启、每人十二图试验出现超时，保留调用记录，没有将失败改写为成功。阿里云官方 [视觉参数说明](https://help.aliyun.com/en/model-studio/vision) 与 [思考模式说明](https://help.aliyun.com/zh/model-studio/deep-thinking) 支持显式关闭思考模式，本轮采集日期 2026-10-07。
- v2：十次请求均成功，93.766 秒，原严格聚合得到两段 Cooper Flagg 候选。
- v3：分段票与定向补看后，二十次请求均成功，314.750 秒；六十四段中十段 candidate、五十四段 unknown。这是调用和覆盖记录，不是识别准确率，也不是同条件速度比较。
- 当前消费层按 P2、P10 的身份冲突拒绝四条机器姓名，采用六条有限区间，显示五名候选：Kevin Durant、Max Christie、Daniel Gafford、Klay Thompson、Cooper Flagg。姓名带候选标记，不把两种姓名互换视为修好了人物身份。
- 输入副本／原资料保持；没有形成逐帧人类真值，不声称十名球员都准确识别。既有 P→T 关联质量和可读号码仍是主要限制。

复跑脚本与采集结果约定见 [研究／渲染 QA](../../research/vision/player-name-identity-20261007/README.md)。真实模型 JSON、裁图、应用副本和日志位于忽略的本机 `artifacts/player-name-identity-20261007/`。
