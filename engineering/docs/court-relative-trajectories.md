# 人物轨迹以球场为参照

2026-10-04，Asia/Shanghai。人物检测器、跟踪器、原始框和人工标注保持原样；修改的是派生位置与尾迹呈现。

## 坐标关系

定义 `H_t` 为第 t 帧图像到固定 2D 球场的单应矩阵，`p_t` 为该帧脚下点：

```text
采集：p_t → q_t = H_t(p_t)              （2D 球场坐标，单位米）
当前画面展示历史：q_t → H_current^-1(q_t)（统一投回当前镜头）
```

历史帧不能共用当前 `H_current` 来计算球场位置，也不能直接连接历史像素 `p_t`。这两种方法都会残留镜头运动。`court-trails.mjs` 供工作台 P 球员尾迹与 T 临时编号尾迹调用；P 的尾迹直接使用 `buildCourtTrajectories` 生成的未平滑球场点，2D 展示和导出也复用相同的脚下点选择函数。

## 脚下点优先级与依据

1. 现有人工图像位置 / 区间位置修正优先，人工 2D 锚点仍由 2D 层优先采用。
2. 用户明确选择的独立姿态对比模型照旧生效；其视频和跟踪版本必须匹配，缺失时保留原位置并标记 `groundCandidateMissing`。
3. 默认来源可读取当前 clip 的脚部候选：只有左右 **ankle** 语义都明确、各置信度至少 0.5、时间匹配（3 毫秒内）、视频 / 跟踪指纹匹配、画面和人物框下半部位置合理，才取双踝中点。记录来源、方法与分数，不宣称接地已确认。
4. 没有可靠双踝时沿用检测框底边中点。不会把脚趾 / 脚跟候选改名为脚踝，不会跨帧补出未检测的脚踝。

当前导入视频没有自动运行姿态模型；既有 RTMPose 脚部文件通常是脚趾 / 脚跟候选。因此新增优先规则不代表所有视频现在都有双踝输出，也不代表本轮已改善姿态模型本身。接入新姿态输出应遵守现有来源指纹和时间对齐协议。

## 中断与原始数据

- 最近 1.2 秒内逐帧取样；无当前标定则尾迹为空，页面明确提示，人物框继续显示。历史帧缺标定、缺位置、身份区间断点、切镜、估计位置处断开。
- 相邻观测间隔超过 0.15 秒或球场速度超过 16 米/秒时断开显示；这是异常连线门槛，不是速度测量结果或精度保证。原始观察和导出的未平滑坐标不因此改写。
- 采用 / 修改标定或脚部来源后，工作台刷新统一重建逐帧矩阵缓存与球场点，播放时复用；不把上一次相机矩阵冻结到无标定帧。
- 篮球的图像尾迹保持独立，空中球不按人物地面点强制投影。
- 页面已有的显示平滑仍只作用于呈现；本轮没有对原始轨迹做平滑或补帧。
