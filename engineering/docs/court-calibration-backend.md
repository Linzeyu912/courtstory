# 篮筐方向约束的球场标定后端

更新：2026-10-04，Asia/Shanghai。依据用户要求实现“找篮筐 → 判断方向 → 约束场地点与场地线 → 跟随旋转镜头 → 用地面交点计算位置”。这是本机工程功能；全部输出仍需复核，米制精度尚未验收。

## 处理流程

### 当前采用方案与操作流程（2026-10-04 确认）

用户明确采用当前多帧点线联合方式，并要求保留人工选点兜底。以下是当前工作台的实际操作，不依赖聊天模型为视频提供点位。

| 阶段 | 用户操作与系统处理 | 结果 / 分支 |
|---|---|---|
| 1. 准备镜头 | 保留普通比赛画面，登记切镜边界；到球场标定页选一帧线条较清楚的画面作为参考。 | 每个连续镜头分别标定；不要求看到中场或所有场地端点。当前不是自动切镜分类。 |
| 2. 自动初始化 | 点击“自动标定本镜头”。本地 YOLO 48 点模型估计具名场地点，既有篮筐检测辅助判断篮侧；用地面点建立初始投影。 | 模型缺失、方向不确定或点布局不足时可直接人工选点，也可换清楚的帧重试。篮筐本身不作为地面点。 |
| 3. 跟随相机 | SIFT 地面特征匹配估计各帧透视变化，必要时短程 LK 回退；自动参照可尝试同侧模型重估。 | 适应同镜头旋转、推拉；匹配失败留空，切镜停止。 |
| 4. 多帧联合校正 | 从可靠对齐帧最多取 11 帧，融合被人员框与底部屏蔽后仍可见的线段；联合 AB/CD、BC、DA、远边线及初始点位拟合。 | 支持充分才调整整块球场投影，三分线随模板共同更新；近侧不可见线只推算。几何 / 线支持检查失败保留原候选。 |
| 5. 原图核对 | 新候选随当前帧预览，检查叠在原视频上的禁区、罚球线、边线与三分线，并查看推拉前后和遮挡恢复处。 | 黄色虚线 / 空心点表示推算。实线有线支持，仍需核对；候选预览不会直接采用整段。 |
| 6. 人工修正 | 展开“不准确？人工选点修正”，点击 A–J 中相应点名后，在原视频重选同一地面交点。核对后点击“确认修正并跟随镜头”。 | 当前帧至少 4 个有效且布局不退化的地面控制点才可拟合；可以用其他清楚的具名点代替遮挡点。此按钮只确认当前参考帧，重新跟随后仍需检查候选。“其他选点方式”中也可只确认当前帧并打开 2D。 |
| 7. 采用与 2D | 检查后点击“采用结果并进入 2D”，自动进入“04 2D 轨迹核对”。已有保存结果且未预览新候选时，按钮为“查看已保存的 2D”，直接使用草稿。 | 保留人工帧、缺失帧、来源和待核对状态。采用整段不是整段人工确认；球员脚点是否正确 / 接地需另核对。 |

人工兜底为长期保留的并行入口，自动模型失败之前也能主动使用：

- **局部改点**：只替换选中的具名点，其他点保留；支持删除错误参照点和继续核对。
- **完整人工标定**：选择篮侧后，手动点选至少 4 个布局分散、不退化的地面交点。A/B/C/D 清楚时可使用四角向导；缺少这些点时选其他已有具名交点，无需标全 A–J。
- **遮挡 / 画外**：优先换参考帧或使用可见点。允许在画外区域点选，但保存为估计参照；近侧 G/H 的自动推算展示不会自动成为控制点。当前人工入口是选点，尚无人工描整条线并直接求解的入口。
- **保护人工结果**：自动响应、载入候选和批量采用保留人工参照；人工参照的镜头传播跳过模型重估和多帧几何校正，仅传播已核对的几何。修改或删除参考点后，依赖旧参考的映射需要重新生成或核对。
- **模型不可用时**：人工选点、当前帧拟合和 SIFT / LK 镜头跟随仍可使用本机几何 / 视频依赖，不要求场地点 YOLO 或多模态服务成功。

### 后端步骤与边界

1. 读取与当前视频、帧和时间对应的 E-BARD 篮筐检测。当前复用已有检测结果，不重新运行人物检测或更改 ByteTrack。浏览器选择通用检测版本时，后端可以读取同一视频已登记的 E-BARD 对象，分别记录两个检测版本的指纹。
2. 运行本机 YOLO11n 48 点模型，分别检查两组已有语义定义的场地点。根据禁区底线到罚球线的方向、远近边关系及篮筐与推算篮下地面位置的一致性，判断当前视图的左右朝向。没有采用“篮筐横坐标小于画面一半就是左半场”的规则，也不再仅以两组点的置信度总和选边。
3. 如果地面结构与篮筐一致，但模型将其放入另一侧槽位，可以重新解释左右语义。保留原始像素坐标、`modelSlot`、`slotSide` 和重解释依据。预测出虚假的镜像球场、地面点不足或多组几何冲突时返回失败原因。
4. 只用具名地面点拟合球场到画面的 `courtToImage`，并提供反向矩阵 `imageToCourt`。篮圈有高度，绝不作为地面拟合点。球员脚点仍须单独确认是否接地。
5. 自动参照请求镜头传播时，按约 1 秒间隔再次运行同一 48 点模型，结合已登记篮筐检查同侧几何。新模型候选未得到局部标线修正支持时，优先保留有效 SIFT 镜头估计；只有运动匹配失败才用该模型候选恢复。人工点选或已人工核对的参照仅按 SIFT / LK 跟随，不被模型重估替换。整段在来源剪辑边界及传入切镜边界处停止，失效帧保留空白。
6. 对每帧回投影 NBA 边线、禁区、三分线和中线，并计算投影采样点到 Canny 边缘的中位距离、3 像素内支持率及可见 / 支持线组。工作台候选状态展示线组与边缘距离，方便先看视频叠线再决定是否采用。

这里的 Canny 线缘用于邻近度诊断和回退保护，不代表标定准确率。局部修正另用具名场地线附近的亮度剖面，区分细白线和油漆区色块边界，再联合原始控制点拟合；具体见下节。球员、广告、木地板纹理仍可能产生干扰。球场完整中线不是必要条件，仍需要方向不同且分布足够的地面证据。镜头内旋转、变焦与平移通过稀疏模型检查和局部运动匹配更新矩阵；镜头畸变、滚动快门、场地非平面和超出支持视角仍需重新人工标定。

## 本地自动出点与人工兜底（2026-10-03 追加）

工作台“球场标定”页新增“自动识别场地并跟随镜头”，调用现有 `/api/court-calibrate`，从当前帧自动初始化并生成当前镜头的候选。当前帧点位自动载入供检查，整段采用仍沿用待核对流程。识别失败提示换清楚的帧或人工补点；模型缺失保留后端错误。请求期间新增的人工点、已有人工核对和草稿保留；处理期间切镜改变则拒绝旧响应。

运行链路为本机 YOLO11n 48 点模型、既有 E-BARD 篮筐证据、OpenCV 标线拟合与 SIFT / LK。**运行时不调用 OpenAI / Codex 多模态服务，也没有使用聊天模型目测坐标作为初始化或训练标签。** 本轮看图只用于开发排查；所有输出坐标由上述代码从视频计算。多模态辅助尚未接入，不是比赛时的必要依赖。

局部标线修正位于 [court_line_refinement.py](../scripts/court_line_refinement.py)：

- A–D 仍指 NBA 16 英尺三秒区外沿。12 英尺内侧线使用独立模板，只能辅助拟合，不能把最近白线直接当作 A–D。尺寸依据为 [NBA 官方场地图](https://cms.nba.com/official/wp-content/uploads/sites/4/2018/01/2017-18-Officials-Guide-Updated-January.pdf)，2026-10-03 复核；该体育规则来源不属于 BroadcastCode 赛事要求。
- 在初始投影附近沿标线法向采样：白线要求两侧更暗；色块边界要求跨较宽区域保持亮度变化。结合人员框屏蔽、沿线覆盖与强度门槛拟合直线，避免逐点吸附到任意最近边缘。
- 至少需要底线和两条禁区长边的图像支持；罚球线不可辨时明确保留模型先验。四线交点先用于几何检查，再联合原有控制点做加权拟合，减少对远侧边线的牵动。控制点移动过大或其他球场线缘指标明显变差时保留原解。
- `quality.courtLineFit` 记录 `laneWidthFeet`、`laneEvidence`、各线覆盖 / 支持样本、是否保留罚球线先验、具名点调整量。各线内部残差与法向偏移以宽度最多 960 的处理图像像素计，具名点调整量已还原到原视频像素。原始模型点继续保留在 `modelImage`。这些是拟合证据，不能用“调整了多少像素”表示真实误差下降。
- 校正场地几何时保留原始自动参照的 SIFT 特征支持区域，避免微小点位变化改变整段镜头跟随。`court48RefreshFrames` 计数实际采用的模型重估；证据不足而保留相机估计的帧记录 `retained_camera`。

本机样例 005 的本轮结果：143 帧中 139 帧有映射，失效帧仍是从零计数的 108–111；用时约 23.47 秒。初始线修正 1 次；帧 31 的模型重估未获得足够标线支持，保留相机估计。A 点相对旧输出的位移中位数约 6.01 像素、最大约 10.02 像素；**未建立真实标注集，因此不能据此宣称定位误差降低了相同比例。** 完整同帧放大对照视频为本机忽略目录 `artifacts/court-a-refinement/005-a-before-after.mp4`，半速仅用于观察，不改变候选时间戳。

本轮 40 项 Python 场地检查、314 项工作台前端检查通过。合成图检查内外线区分、已知偏移的改善、遮挡回退及人工参照保护；DOM 交互检查自动请求、待核对状态、请求期间人工点保留和切镜变化丢弃旧结果。实际浏览器操作尚未完成；此前本机预览端口无法从内置浏览器访问，使用导出视频展示。

当前方向按同侧主转播视图解释。反向机位、镜像、篮下视角及跨机位物理球篮身份仍需人工核对；后端没有自动辨认球队进攻端。多筐、不可见篮筐、退化点布局、异常透视等情况会返回不确定，不能当作全自动通用标定。

## 多帧点线联合标定与遮挡端点（2026-10-04 追加）

用户反馈 B/C、两侧边线有偏差，且观众经常挡住近侧边线及端点。新增 [court_temporal_refinement.py](../scripts/court_temporal_refinement.py)，接入自动初始化后的镜头传播末尾：

1. 从当前镜头最多取 11 帧通过参考帧 SIFT 匹配的图像，按已有平面变换对齐。人员框和底部 25% 被排除，每个融合像素至少需要 3 帧有效观测；用中位图提取持续的标线。切镜边界继续由原传播入口限定。LK 回退帧和模型独立重置的帧不作为融合证据。
2. 同时拟合禁区两条长边 AB/CD、罚球线 BC、底线 DA 和远侧边线，再与原模型控制点做软约束联合拟合。长线先截取画面内的可见部分，不要求线段端点或中线露出。BC 缺少线段支持时本阶段保留旧解，不把模型原位当成新增观测。近侧边线有可靠线段时也参与；看不见时不参与拟合。
3. 检查禁区面积 / 内外线语义、交点稳定性、透视分母、控制点和推算端点位移，以及联合直线残差。通过后，用同一个地面校正变换更新依赖该参考的各帧，保留已有相机运动及失效缺口；模型独立重置产生的几何不套用这次校正。人工点选或人工确认参照跳过自动联合校正。
4. `quality.temporalLineFit` / `summary.temporalLineFit` 记录是否采用、源视频帧号、支持线和拟合距离；`sourceFrames` 为原视频坐标，`frameCoordinates: source_video`。直线内部采样残差仍是最多 960 宽的工作图像像素，`meanLineDistance*Pixels` 和 `cornerAdjustmentPixels` 是原视频像素。保留 `beforeTemporalImage`，不覆盖原始 `modelImage`。
5. `quality.lineVisibility` / `pointVisibility` 区分 `supported_projection` 与 `inferred`；画外、人员框 / 底部屏蔽区域、缺少对应标线分别记录原因。这里的可见性是启发式，尚未实现观众语义分割。另一帧的线支持不会让当前被挡住的点变成观测点。

工作台用黄色虚线 / 空心点表示推算，近侧 G/H 只作为展示端点，不加入 `points` 控制列表，不要求用户在看不见的地方补点。实线标为“线支持投影”，仍需核对；人工修改后的几何不继续显示旧自动拟合的证据。旧候选没有新证据时，也不会被显示为机器已识别的实线。

005 本机重新运行：139/143 帧有映射，失效帧仍是 108–111（从零计数）。11 帧提供 AB、BC、CD、DA 和远侧边线支持；139 帧的近侧边线均标为推算。本次原视频尺度的平均拟合线距离由 4.844 px 变为 1.292 px，这是**对本次提取标线的拟合残差，不是独立定位误差**。尚无人工真值集，其他地板样式 / 机位和真实精度待验收。本轮没有新增或重跑测试套件；实际完成 005 全片流水线、输出模式校验、语法检查及导出画面检查。

对照视频在本机忽略目录 `artifacts/court-occlusion-20261004/005-bc-sidelines-before-after.mp4`：上方整场新投影，下方 B/C 同帧放大对照，半速播放。`run_005.py`、`render_comparison.py` 和 `comparison-summary.json` 同目录留存。正式候选文件及用户草稿未替换，工作台重新点击自动识别后使用新逻辑；本轮仅本地修改。

## 本机模型

```text
68e5faf5fb5388cf83477238abe22e9824a69fb33a4cf34f79ab61858f410064
```

服务只在首次自动标定或镜头重估请求时加载模型。可用 `--court-model` 指定这份权重的其他本地路径，用 `--court-imgsz 640` 或 `960` 选择输入尺寸，默认 640。自动初始化缺少权重、哈希不符或推理依赖不可用时返回明确错误，不自动下载或安装。手工传播在本机模型不可用时保留旧的 SIFT / LK 路径和线缘诊断；如果传播中模型不可用，会记录原因，不中断这次传播。

依赖使用已有视觉环境，见[运行环境记录](../research/vision-local-aws-deployment.md)。共享仓库不包含模型权重。

## HTTP 接口

启动服务的原命令保持可用：

```powershell
& tmp/vision-deploy-bench-venv/Scripts/python.exe engineering/scripts/serve_player_review.py --library data/videos/tactics/acceptance/review-library.json --port 8876
```

新增 `POST /api/court-calibrate`，请求类型为 `application/json`，只服务本机登记的视频：

```json
{
  "sample": "005",
  "variant": "ebard",
  "frame": 0,
  "cuts": [],
  "propagate": false
}
```

- `frame` 为从零开始的帧号；`variant` 省略时取该样例默认版本。
- `cuts` 为额外切镜边界；真实来源剪辑边界始终保留。
- `propagate: false` 只返回初始参照，设为 `true` 则继续生成同镜头逐帧候选。
- 返回既有 `courtCandidates` 格式：`schemaVersion: 1`、`template: "NBA"`、`videoHash`、`keyframes`、`invalidFrames` 等。新增 `initialization` 记录方向依据、原始来源帧 / 时间和模型版本。
- 每帧 `quality.projectedLines` 包含 `medianResidualPixels`、`supportWithin3Pixels`、`visibleFamilies`、`supportedFamilies`、`visibleCourtBoundsMeters`、`visibleImageBoundsPixels` 与 `uncertaintyHint`；重估帧另有 `quality.courtLineFit.refinementApplied` 与修正依据。UI 展示模板可见范围、可见 / 支持线组及线缘距离，不会将这些数值标为准确率。`not_quantified_from_edges` 明确表示没有据边缘距离推算定位误差。
- 初始化不确定时返回 HTTP 200，`initialization.status: "invalid"`、`keyframes: []`、`unresolvedFrames: [frame]`，保留机器可读的原因；不会伪造左右侧来填满候选。非法请求返回 400，缺少可用本地模型返回 503。
- 有效候选保留 `needs_review`、`reviewRequired: true`、`metricAccuracyValidated: false`。

该接口与原 `/api/court-propagate` 一样只返回提议，不直接修改服务器候选文件。工作台按钮接收后载入当前帧待核对点位，并保留已有人工参照；整段采用继续走已有流程。返回值未经保存并重新登记前，不会自动随另一次剪辑进入缓存。

## 命令行生成文件

省略 `--seed` 时自动根据篮筐与场地点初始化；必须指定新输出路径，已有文件会被拒绝覆盖：

```powershell
# 只看初始场地候选
& tmp/vision-deploy-bench-venv/Scripts/python.exe engineering/scripts/build_court_review_candidates.py --sample 005 --frame 0 --initial-only --output artifacts/court-auto-005-initial.json

# 初始化后跟随同一镜头
& tmp/vision-deploy-bench-venv/Scripts/python.exe engineering/scripts/build_court_review_candidates.py --sample 005 --frame 0 --output artifacts/court-auto-005-motion.json
```

原来的 `--seed <JSON路径>` 入口继续使用指定的地面参照。自动初始化失败时仍写出含原因的诊断 JSON，调用方需要检查 `initialization.status` 和 `summary.validFrames`，不能仅凭命令退出成功判断已获得标定。

生成文件可经复核后在视频库显式登记为 `courtCandidates`。旧研究、种子和共享候选不会自动替换。已登记的候选经过裁切时，初始化的本地帧号和待处理帧会同步映射；参考帧被删掉则标 `source_removed`，保留原始来源帧和时间，不在二次裁切时恢复为有效初始化。模型输入的旧检测指纹用于追溯原始证据，不代表重新推理过裁切视频。
