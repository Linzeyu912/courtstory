# 球员标定与战术制作：单屏工作台

日期：2026-10-09，America/New_York。来源为本聊天用户审核的两组布局图及后续姓名显示要求。

## 范围与分支

用户先要求渲染审核图，再明确安排多个子 agent 实施并推送；随后要求直接在 main 开发，不开分支。此次指令覆盖历史 UI 分支约定。实现与设计资料已复制到主工作目录，旧 UI worktree 保留恢复副本，不继续开发。基线为 main `902aeaf`，保留最近的左侧画面说明优化和 Astra 全员姓名识别接线。

## 页面行为

- 球员标定：十个槽位与显示控制放到左侧；视频、逐帧播放、当前帧与原审核时间轴在中间保持可见；右侧关联、同人续接、姓名识别、更多工具原位切换，初检入口独立。保持已有人工绑定、姓名候选有限区间与显式加入流程。
- 战术制作：工具栏、画布、播放与真实时间轴共用视口剩余高度；右侧标注属性、标注列表与更多设置切换。长列表分页，低频设置通过浮层打开，已有数据和事件绑定保留。
- 解说：逐句编辑分页，视频与逐帧定位条保留，原片和已有成片切换显示。
- 小尺寸采用原有纵向阅读方式；不把桌面密集布局硬塞进手机。

## 姓名显示规则

用户新增要求：球员姓名出现在战术画布，提供显示／隐藏开关；重点球员圈关联的人必须展示姓名。

- 普通姓名遵循姓名显示开关及球员／球队筛选。
- 当前时间有效且可见的重点圈，强制显示关联球员的姓名信息；不依赖鼠标是否选中该图形。
- 姓名仍必须匹配视频／跟踪来源、当前帧、T 编号及有效区间。没有可靠姓名时回退球员编号／未知提示，不因圈选生成姓名，也不将未关联的人工圈猜为某个人。
- 重点圈离开有效区间后恢复普通显示规则。候选姓名沿用既有标记，不当作人工确认。
- 画布和成片使用共享标签规则，避免前端预览与导出重复叠加或互相矛盾。

## 实际验证

- 重建正式 `ui.bundle.mjs`；784 项前端测试通过，92 项 HTTP 服务、姓名接口和战术渲染测试通过。修复了旧 `identity-simple` 测试在新 Node 提供全局 sessionStorage 时跨夹具共享存储的问题，仅调整测试隔离。
- 独立服务使用临时素材登记、剪辑和草稿目录，未读取用户正在编辑的草稿；不改 8892 服务。浏览器拦截模型任务 POST，本轮未调用收费模型。
- 1440×900、1366×768 的球员视频、播放、帧数、时间轴、Agent 同屏；战术画布高度分别为 463px、331px，1366 下视频约 580×326。解说视频高度分别为 518px、386px，播放条和 Agent 同屏。390 宽手机没有横向溢出。
- 真实操作检查：两点跑位绘制、切解说再返回、切换视口尺寸、拖动控制点、保存隔离草稿均成功，无页面 JS 异常。
- 关闭姓名开关后，真实画布中有效重点圈仍显示 `P1 · pending`；浏览器内独立姓名夹具验证全开显示两人、关闭后仅重点圈保留有效姓名、过期退编号、候选带问号。夹具名字不是模型识别结论。
