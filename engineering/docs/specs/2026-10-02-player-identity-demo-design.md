# 首轮球员身份 demo：本机部署与人工确认

- 日期：2026-10-02，Asia/Shanghai。
- 状态：规格草案，待用户审阅；未实现界面、未安装模型依赖、未运行推理。
- 已确认的用户需求：输入 NBA 转播的一段进攻回合，识别场上球员，关联球队、球衣号码、姓名和 2K 能力；第一轮允许人工确认。
- 本稿中的模型、界面和验收方式是本次建议，不代表团队已经采用的技术方案。

## 1. 第一轮的目标

跑通“自动检测和跟踪 → 人工确认身份 → 本地 2K 查询 → 标注视频和能力卡片”。先检查可见球员是否找全、是否混入观众或裁判、是否在交叉和遮挡后跟错人。

分析整段短片后，人工可以选择号码较清楚的时刻确认身份。只有同一轨迹片段的身份一致且人工确认了有效时间范围，才能把姓名显示到该范围内的前后帧。

人工确认结果与自动检测、跟踪结果分别记录。不将人工纠正后的姓名正确率称为全自动身份识别准确率。画面外、完全遮挡和未确认身份的球员分别保留“暂不可见”“遮挡”“身份未知”；不强凑每帧十个框。

“暂不可见”和“遮挡”由参考标注或人工复核确认；仅凭轨迹消失不能断言是哪一种情况，未复核时记录为跟踪缺口。

首轮不接自动战术判断、持球人判断、轮廓高亮、慢放编排和路线箭头。球衣号码 OCR、比分框 OCR 与号码大模型属于后续自动化对照；本轮比赛信息由素材标签预填并人工确认，自行上传的视频由用户补充日期、赛季和对阵。这一操作不算比分框自动识别。

## 2. 部署位置和运行组件

部署在当前电脑，以本地浏览器界面操作，视频和 2K 数据在本机处理。网页监听本地地址；首轮不创建云服务器，也不建立公开分享地址。

| 组件 | 首轮用途 | 当前状态 |
|---|---|---|
| 独立 Python 环境、GPU 版 PyTorch、Ultralytics | 加载模型并在显卡上推理 | 当前检查的 Python 环境缺少 torch 和 ultralytics；版本组合与实际兼容性需验证 |
| E-BARD 篮球微调 YOLOv8n | 检测球员、裁判、球、篮筐；首轮使用球员结果 | 作者公开了权重；尚未下载、加载或实测 |
| BoT-SORT | 连续帧轨迹；明确指定该跟踪器 | 临时 track_id 不是球员姓名；实际串人和丢轨情况需评价 |
| 本地网页（建议 Gradio） | 选片、查看关键帧、人工修正、预览与导出 | 当前 Python 环境已有 Gradio；demo 界面尚未创建 |
| 本地 2K 数据读取器 | 按确认后的 player_id、season 查记录与出处 | 已有数据包和索引；集成尚未实现 |
| 视频解码、标注、编码 | 生成与原片时间对应的标注视频 | 当前已有 OpenCV 和 FFmpeg；首轮输出仍需端到端验证 |

2026-10-02 本机只读检查：RTX 5060 Laptop GPU，8151 MiB 显存，驱动 592.27；Python 3.13.11。此信息只证明设备与当前环境存在，不证明模型能运行，也不预先承诺速度或峰值显存。实现时使用独立环境，选择官方支持该显卡和 Python 的 GPU 包，不改动现有全局包。安装成功后必须执行显卡运算与模型推理检查；CPU 排错不替代 GPU 部署验收。

## 3. 首轮样片与运行顺序

主样片为 [005：LAL–MIN](../../../data/videos/nba/2024-25/labels/005.json)，标签记录 2025-04-27、第二节、10.68 秒、720p、25 fps、完整球权；视频位于 `data/videos/nba/2024-25/clips/005_LAL-MIN_Q2_catch-shoot_10.8s_720p.mp4`。

对照为 [001：IND–OKC](../../../data/videos/nba/2024-25/labels/001.json)，8.108 秒、1080p、前场配合局部片段，不称为完整进攻回合；视频位于 `data/videos/nba/2024-25/clips/IND-OKC_Q4_pick-pop_8.1s_1080p.mp4`。

1. 在独立环境中加载权重，验证 GPU 单帧推理，记录实际依赖版本、权重哈希、加载结果与显存。
2. 确认主样片可解码，按连续镜头分析整段，缓存检测框、轨迹与关键帧。保留原片时序；发生切镜头时分段，不直接沿用同名 track_id。
3. 网页显示轨迹候选和清晰帧。用户确认是否为场上球员，并指定球队、字符串号码、姓名及有效时间范围。误检、漏检与无法确认的区间保持明确标记。
4. 身份确认后查询 2K 记录，生成视频姓名标签、球员能力卡片和可重新加载的身份 JSON。
5. 完整播放结果并复核交叉、遮挡和重新入镜区间；有串人时修正相应时间范围，再导出。随后在 001 上运行同一流程，记录表现差异。

首轮采用单任务离线处理；耗时与显存由实际运行测量。不将整段视频交给大模型逐帧猜姓名。

## 4. 人工确认界面与纠正规则

```text
[选择 005 / 001 / 本地视频]  [日期、赛季、对阵：确认]  [分析片段]
┌ 视频：候选框、临时编号、已确认姓名 ┐ ┌ 当前轨迹证据帧 ┐
│ 时间滑块 / 前后逐帧               │ │ 开始、中段、结束 │
└──────────────────────────────────┘ └────────────────┘
轨迹 T08  有效范围 [开始时间 — 结束时间]
[场上球员 / 误检 / 身份未知]  球队 [选择]
号码 [文本输入]  姓名 [候选名单搜索]
[确认此区间] [拆分区间] [关联已确认球员] [标记漏检]
[查看能力与来源] [保存确认结果] [导出视频和 JSON]
```

- 身份绑定到“镜头内的轨迹片段与有效时间范围”。一个人物可关联多个不连续 track；一个发生换人的 track 必须拆分范围，不给整个 track 永久锁死姓名。
- 删除误检也限定时间范围。两个空间不同、同帧存在的轨迹不能同时静默绑定同一人物；界面提示冲突并要求修正。
- 人工确认不要求第一帧十人全部可见。球员后来进入镜头时使用新候选，身份不确定时等待用户确认。
- 最小首轮提供漏检区间标记，缺口在视频中保持未标注。单帧补框不等于已生成连续轨迹；从人工框重新跟踪或手工轨迹编辑需另行定义和验证，本稿不承诺该功能。
- 保存确认结果后可关闭、重新载入，恢复所有身份、时间范围、误检排除和断轨关联。原始自动轨迹保留，人工修改不覆盖它。

## 5. 2K 联接与输出约定

按 [2K 读取指南](../../../2K%20Player%20Data/AGENTS.md) 使用索引。赛季、球队和号码只产生候选，不以该查询代替身份确认；整季名单不是当天的场上五人。号码保持文本，`0` 与 `00` 不合并；同号码多候选时让用户选取，无法确认则保持未知。

身份确认后按 `player_id + season` 查能力。能力为空时显示未知，保留游戏版本、record_id、字段来源和日期口径；不跨季填值，也不用 2K 能力反向认人。数据中的 player_id 是上游规范化姓名键，不宣称 NBA 官方编号。

身份记录至少保存：素材编号及视频哈希、比赛日期与赛季、镜头编号、原 track_id、起止帧及时间、球队、原始号码文本、候选 player_id、确认 player_id、确认方式 `human_confirmed`、证据帧、误检排除、漏检区间、2K record_id 与来源引用。算法参数和运行组件版本随本次结果保存。

帧编号从 0 开始，身份有效区间使用 `[start_frame, end_frame)`，包含起始帧、不包含结束帧。时间对应原片的帧时间戳；实现与验收同时检查相邻区间交界处，防止多标或少标一帧。

导出包括标注视频、身份 JSON、能力卡片数据和运行报告。临时视频、模型缓存及推理输出放入被忽略的本地目录；不改写来源成片与原始标签。此部署不代表正式赛事 AWS 部署或作品提交。

## 6. 验收标准

- GPU 运算、单帧检测和连续短片跟踪实际通过；报告实际显存、耗时和版本，出现失败时记录原始问题。
- 005 与 001 均能完成分析、人工确认、预览、导出和重新载入；视频时间与原片一致，叠加位置随对应帧更新。
- 测试一次“同 ID 分段改人”和一次“同人关联多个 track”，保存与导出后的有效时间范围正确；冲突关联被提示。
- 对人工确认区间逐帧复核，不出现未处理的错名；区间外保持未知，漏检和误检区间保留。
- 分别报告自动可见球员漏检、观众或裁判混入、跟踪换人、未确认区间和人工修正次数。不用人工完成结果掩盖自动失败，也不承诺每帧十人齐全。
- 以人工标注的可见球员为评价参考；漏检和多检按帧内目标计数，串人按身份切换事件计数，修正按保存的编辑动作计数，并分别报告样本量。
- 2K 卡片从正确赛季记录读取，号码、能力空值、版本和来源口径完整保留。

## 7. 来源与尚未验证的部分

来源核验日期：2026-10-02。

- [E-BARD 作者检测模型卡](https://huggingface.co/GabrieleGiudici/E-BARD-detection-models)与[权重文件](https://huggingface.co/GabrieleGiudici/E-BARD-detection-models/tree/main)：公开篮球专项 YOLOv8n 和 RF-DETR Nano。首轮建议 YOLOv8n；作者测试集表现不外推为本项目准确率。
- [Ultralytics 跟踪文档](https://docs.ultralytics.com/modes/track/)：支持显式配置 BoT-SORT。跟踪编号不等于姓名，具体默认值和安装版本在实现时固定。
- [PyTorch 安装入口](https://pytorch.org/get-started/locally/)与[官方 GPU 包索引](https://download.pytorch.org/whl/cu130/torch/)：实现时核对 Windows、Python 和显卡支持，随后实测，不把文档可选组合称为本机推理通过。
- [Gradio 本地界面文档](https://www.gradio.app/docs/gradio/interface)：建议本地网页作为操作台，不开启公开分享。
- 本仓库素材标签与 2K 数据约定是数据联接依据；用户本轮明确允许人工确认。

当前没有模型推理、网页运行或结果视频证据。规格审阅后再写实施计划；安装环境、下载权重、实现界面和跑样片属于后续实施步骤。
