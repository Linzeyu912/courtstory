## 单次正常执行

在“战术制作”选择“整段原视频，分阶段分析”，填写目的后点击一次“生成战术初稿”。适合目前24秒以内原片；无需先人工做2D、确认全部P身份或给每个人填坐标。

建议制作目标：

> 覆盖持球、切入、掩护后跑位、接应及相关防守移动；多画有实际动作依据的路线，静止参与者用位置标记；重点圈只给该参考帧持球人。

程序顺序如下，用户无需逐段启动模型：

1. **同源原图观察。** 解码所选原片，按阶段输入高清原帧；模型输出局部人物、动作、参考帧脚点、真实观察路线、球权和不确定项。
2. **来源与合同校验。** 先核对媒体、尺寸、完整PTS、范围、切镜、观察引用与图像摘要。初次动作/连续性声明不等同于已确认；可恢复的三类语义缺项进入无可采用输出的待审核状态。
3. **独立原图审核。** 核对同人、同时可见的不同人、实际球权、路线方向、地板参考与大致终区。只给具体通过路线的对应观察授权，不升级整个人的未知身份。缺脚、裁切、无参照等明确保留。
4. **保守几何反证。** 本地Court48与独立地板线只拒绝明显终点矛盾，不授权精确坐标。旧反证绑定具体几何和来源；只改说明或检查暂不可用不能清掉反证。
5. **受控局部修正。** 冻结通过图形/观察，让模型只修指定事实；禁止删路线、改成静止、缩短范围或编造遮挡脚点来冒充修复。实际改变后再审核、编译和原生校验；空patch仅记录未解决项，不虚报修复。
6. **合并预览。** 保留可展示图形及具体例外。全部阶段处理完且有局部例外是`manual_review`；某段失败为`generation_partial`；审核没有完成为`audit_pending`，不能采用未审图形。不把1/2写成整段完成。
7. **采用、保存、成片。** 采用候选后再保存；采用不等于保存。确认服务端版本/摘要，导出同一草稿的正式MP4，检查渲染成功和可播放。当前成片是静音，不改变原素材音轨。

实线表示当前实际动作，虚线表示随后确实观察到的移动，不是预测。重点圈只给对应帧实际持球者。位置标记不能拿来冒充漏掉的真实运动。路线是参考画面中的观察示意，不能称逐帧测量或米制轨迹。

## 固定参数与停止条件

| 项目 | 本轮已验证的实际配置 |
|---|---|
| 战术模型 | `gpt-6.1-sol`，`low`；只对战术调用显式覆盖 |
| 原视频总预算 | 每轮960秒、最多6次真实模型调用，共用实际墙钟 |
| 首次生成/结构重试 | 最多180秒；无内容上限180秒 |
| 原图审核/复审 | 每次最多210秒 |
| 审核后的局部patch | 最多90秒；只有剩余至少285秒才启动，保留225秒复审/收尾 |
| 审核传输错误 | 同一审核最多自动再试一次；原图/事实/prompt/schema复用，仍计入本轮上限 |
| 默认连接 | `auto`、原有OpenAI认证；HTTP/SSE仅可选对照，尚未验证稳定，不能升为默认 |
| 实际配置记录 | 每call的`runtime.json`，状态中的调用数、失败码、`transportMode`、`providerAlias` |

超时上限是防止无限等待，不是速度保证。取消、额度/认证错误、原图改变、剩余预算不足或调用数耗尽必须停止。网络连接中断和无内容超时分开记录；没有协议证据时不宣称服务卡死。

普通“仅重试失败段”会开启**新一轮**960秒/6次预算，复用已完成事实；务必分别记录每轮和累计耗时/调用数。不能把多轮恢复说成首轮一次提交成功。已完成阶段保留，没有完成审核的图形不发布。

## 节省时间的规则

- 优先检查、恢复已有任务；高清原图、已生成观察、合法审核和已保存图形都按来源复用，不重新解码/重新识别健康阶段。
- 不为同一个连接错误连续做整片重跑。先读本轮具体失败码及日志，达到单轮重试上限后停；只有修正了可验证原因、连接方式或输入问题，才再做有明确目的的对照。
- 修复某个程序问题先跑受影响回归；不要没有新变化就反复跑全部套件，也不要用大量纯JSON小试验替代一次真实原图核对。
- 原图复核分别检查人物、球权、路线方向/终区和相机反证；计数区分路线条数、不同球员人数、近零噪声及真实移动。
- 有必要验证重复稳定性时，明确试验次数、代码快照、预算和通过条件；失败不会自动变为增加无限次数的实验。
- 每次结束保存短交接：已完成步骤、剩余问题、jobId、版本/摘要、真实耗时/调用数、可查看输出、当前运行服务。下次从这里继续。
