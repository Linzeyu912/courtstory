# 战术编排与 MP4 成片操作说明

用户认可的 005 V2 视觉基准、原制作配置/脚本、暂停与剩余路线参数及 Agent 复用指令已保存为[005 V2 制作流程](005-authored-v2-workflow.md)。

适用：当前工作台的「战术制作」与「保存与导出」。成片为**静音、30 fps**；预览与下载使用同一份编码 MP4。冻结讲解会增加成片时长。

验证边界（2026-10-04）：已在新视频实际调用 Agent，生成并采用三阶段、两条编排曲线及近似相机。模型建议仍需人工核对人物、方向与时机；这次样例通过不代表任意素材都能自动达到相同质量。模型初稿若未通过结构校验，会自动修正一次；仍不合格则保留原草稿并显示失败原因。

## 1. 生成初稿并采用

1. 导入视频并完成识别，检查需要使用的球员与位置，再进入第 3 步「战术制作」。人物身份尚未核实时，不要把 P 编号当作球衣号码。
2. 展开「Agent 战术初稿」，选择分析范围，填写「希望讲清楚什么」，例如“持球掩护后切入与弱侧跑位”，点击「生成战术初稿」。空白草稿可分析整段；已有内容时使用「当前阶段，追加初稿」。
3. 查看阶段说明和每个参考画面的标记，核对人物、方向、起止时机与可见数量。缺少预览图或标记不可见时，先处理提示，不把该项当作已经核对。
4. 满意后点「采用到草稿，继续编辑」。建议进入原有「本阶段图形」列表；没有第二套图形列表。

生成失败或点「取消生成」不会清空人工草稿。可以重试，也可继续用画路线、虚线箭头、传球路线、挡拆标记和重点球员圈手工编辑。若没有编排曲线或示意相机，相应的专用控件不会出现可编辑内容。

## 2. 在原画布调整效果

先在「本阶段图形」中选中对象。修改后可用画布顶部「撤销」，确认后点「保存」，看到本机版本提示再离开。

| 想调整什么 | 操作 |
| --- | --- |
| 四点大曲线 | 选中「编排曲线」，点「回参考帧调曲线」。准确画面加载后，拖起点、出发手柄、到达手柄或终点；拖线条可整体移动。四点固定，不能加删转弯点。 |
| 跑动节奏 | 展开「路线完成进度」，选关键点，调整「原视频帧」与「完成百分比」，点「应用进度」。百分比表示此时已走完的路线，成片显示剩余部分；可增加或删除中间关键点，进度不能倒退。 |
| 显示区间 | 在「显示时间」修改起止帧，点「应用显示时间」。编排路线的进度首尾会同步调整；缩短区间会移除区间外的中间进度点。 |
| 冻结动画时长 | 展开「冻结动画与示意相机」，选「冻结讲解点」，分别设置绘制前、绘制中、绘制后的秒数，点「应用冻结时长」。这是成片停留时长，不是原视频帧号。 |
| 近似镜头投影 | 在同一区域选「示意相机」和「相机参考帧」，点「定位并调整四角」。等待准确画面加载，拖动 1–4 号角点，完成后点「结束角点调整」。会影响使用这台示意相机的路线，可撤销。 |

示意相机是用于讲解的近似地面投影，不等于人工核对过的球场标定，也不会修改人物轨迹或审核结果。镜头切换、支撑范围不足或来源变化时，按提示处理；普通参考帧图形不会仅因延长显示时间而自动变成连续跟随路线。

## 3. 检查画面与成片预览

- **「逐点检查」**：在原视频上到讲解点自动暂停，点击「继续播放」逐点核对；适合定位和修改。
- **「成片预览」→「生成成片预览」**：生成含路线、标记和冻结动画的 MP4。完成后用播放器连续查看实际成片，尤其检查曲线方向、绘制节奏、剩余路线和相机跟随。

生成过程中显示进度，可点「取消生成」。取消或失败保留草稿；失败信息处理后可重新生成。渲染使用点击按钮时的草稿快照，无需先保存，但仍建议保存重要修改。

生成后再改草稿，界面会提示成片来自旧快照。点「重新生成当前草稿」后再交付；「下载旧快照 MP4」不包含后续修改。

## 4. 下载成片

进入第 4 步「保存与导出」。已生成的当前快照会复用同一份成片；未生成时点「生成成片 MP4」，完成后点「下载成片 MP4」。这里的播放器与第 3 步成片预览使用相同产物，当前没有配音、字幕合成或原声轨道。

「原素材与数据备份（可选）」中的「下载原素材视频」不含战术叠加；如素材经过裁切，下载的是当前裁切副本。完整战术 JSON 与审核 HTML 在战术画布的「来源、草稿与导出」中获取，审核 HTML 不能替代 MP4 成片。

## 5. 调整阶段，或恢复失效编排

若只是工作台更新了审核数据字段，视频与编排画面未变：先核对参考画面和相机四角，再在「冻结动画与示意相机」点击「重新绑定此视频编排」。它会核验原来源凭据，以及视频、尺寸、完整帧映射、阶段和切镜是否一致；通过后仅恢复独立曲线与示意相机，可撤销。随后保存并重新生成成片。它不会确认球员或球场轨迹，其他失效图形仍须分别核对。

缺少原来源凭据，或上述内容已改变时，恢复会被拒绝。保留原稿，使用下方移除编排流程重新制作，不要靠反复保存绕过提示。

有成片编排时，分段、合并和改变阶段暂停帧会被拦截；阶段名称仍可修改。

1. 先保存需要保留的版本。
2. 打开「冻结动画与示意相机」，点「移除成片编排」。它会保留图形、控制点和样式，移除镜头跟随、路线进度与冻结动画；编排路线退回参考帧静态图形。**可用「撤销」恢复。**
3. 再调整阶段，按需要重新生成初稿或手工编辑。已有图形仍保留，因此生成范围仍遵循当前阶段追加规则。
4. 若旧草稿已提示图形因阶段或来源变化而失效，移除编排不会替你确认新位置。定位到正确参考画面，选中图形，点「在本帧重新定位」，检查后保存并重新生成成片。

提示“服务器已有新版本”时，先用「导出完整数据 JSON」保留本地修改，再核对本机保存版本；不要连续重试渲染或直接覆盖想保留的草稿。

## 服务维护：渲染依赖

以下配置由启动本地服务的人处理，普通编辑不需要填写路径。

| 依赖 | 当前查找方式 |
| --- | --- |
| Node.js | 服务使用 PATH 中的 `node`；使用 Node.js 22 或更新版本。 |
| Sharp | 先读取 `TACTICS_SHARP_MODULE` 指向的已安装模块，再尝试正常解析 `sharp`。代码还尝试当前用户的 Codex 捆绑运行时，但不保证其他机器存在该回退目录。 |
| FFmpeg | 按 `--tactics-ffmpeg` 服务参数、`TACTICS_FFMPEG` 环境变量、PATH 中的 `ffmpeg` 的顺序查找。指定值应是本机真实可执行文件。 |
| Python | 启动服务的 Python 环境需要可导入 `av`（PyAV）和 `numpy`。 |

环境变量应在启动服务前设置，并由服务进程继承；换机器需重新检查实际安装位置，不复制他人的绝对目录。保持原来的素材库等启动参数，只按需要补充 FFmpeg 参数或环境变量。

任务保存在 `--tactics-folder` 下的 `render-jobs`，默认根目录为仓库内 `data/local-workbench/tactics`。失败信息可结合对应任务目录的 `svg-error.txt`、`encode-error.txt` 排查。服务只发布完成验证的成片；失败或取消的中间视频不是交付文件。

配置依据：[服务入口](../scripts/serve_player_review.py)、[渲染任务与编码](../scripts/tactics_render.py)、[Sharp 渲染进程](../tools/tactical-overlay/production-worker.mjs)、[Node 调用](../scripts/tactical_workbench.py)。
