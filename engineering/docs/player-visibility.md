# 球员画面状态与镜头外空位置

日期：2026-10-04，Asia/Shanghai。依据为本聊天用户确认的三种情况；这是本机工作台的产品约定，不是赛事官方要求。仓库来源：[BroadcastCode Team Hub](https://github.com/Linzeyu912/courtstory)。开始时远端 Issues 列表为空，未新建或分配任务。

## 操作

在「02 球员标定」选择球员，在右侧「球员画面状态」填写起止帧，然后选择：

| 状态 | 行为 |
|---|---|
| 正常记录 | 使用原有检测 / 跟踪或人工位置；没有观测时继续留空，不凭空恢复坐标。 |
| 遮挡 / 漏识别 | 保留身份，暂不使用该区间机器位置，列入待恢复缺口；已有人工位置仍作为修复依据保留。 |
| 镜头外 | 保留球员记录，原图及 2D 坐标为空；不计入待补点缺口，不插值，不强制人工补位置。 |

默认只改当前帧；可以填写一段范围，或使用「选取当前整段缺口 / 状态」。界面帧号从 1 开始，起止帧均包含在内。重新入画时，对对应区间选择「正常记录」，并核对或重新关联 T 编号。正常记录不会把旧的身份取消记录重新关联回来，也不等于人工确认人物。

「前后帧短缺口补点」提供关闭、0.2、0.5、1 秒，沿用原有全草稿设置，默认关闭。开启后，有前后位置、身份连续且不跨切镜的短缺口才允许估计；最长间隔计算两端观测的时间差，估计仍需人工核对。镜头外区间不受该开关影响，始终留空。

同一面板也在「04 2D 轨迹核对」可用。操作可撤销、保存草稿、刷新恢复；移除某条画面状态后恢复底层记录。交换球员时状态随人移动，清空球员时状态一并清除。

## 数据与边界

- `entity.visibilityRanges` 保存互不重叠、按帧排序的 `{start,end,state,origin}`，内部帧号从 0 开始。`state` 为 `visible`、`occluded`、`out_of_view`，`origin` 为 `human_visibility_review`。局部修改仅拆分重叠区间，保留两侧记录。
- 画面状态独立于 P / T 关联与原始检测。镜头外状态覆盖旧图像点、球场点的显示，但不删除它们；恢复或撤销可找回原记录。未曾出现的球员槽位也能先标镜头外，不制造身份确认。
- 图像与球场导出保留 `observationState`、`positionRequired` 及人工范围来源。镜头外使用既有 `source: out_of_view`、`x/y: null`、`positionRequired: false`，从 `unresolved` / `courtUnresolved` 排除，轨迹线断开。没有充分观测、也没有人工判断的帧仍为 `unknown`。
- 兼容旧草稿 `bindings` / `identityKeyframes` 中的 `out_of_view`。新「正常记录」或「遮挡 / 漏识别」范围可以覆盖旧出画状态，原身份解析与逐帧确认使用同一规则。
- 「遮挡 / 漏识别」是人工判断；无观测不会自动证明遮挡或镜头外。没有实现根据镜头范围自动分类，也没有采用未来帧把镜头外球员默认放到底线。
- 沿用既有线性原图插值及位移限制，不声称新增了视觉重识别或独立位置精度验证。
