## 2. 必须保留的视觉规则

1. 用少量连续、平滑的大箭头解释动作。每条一个箭头头部，不沿检测点画密集碎线。
2. 每条路线只用四个三次 Bezier 控制点：起点、出发手柄、到达手柄、终点。路线可概括，但起终区域、方向、先后和转弯应符合原视频。
3. 关键时刻先暂停，让画面停稳，再逐步画出未来动作的完整路线，留出观看时间。
4. 恢复播放后，从路线尾部去掉已经完成的部分，保留未走完部分；完整显示后的目的地与箭头方向保持稳定。
5. 剩余路线过短时整体淡出，避免缩成小钩、小三角或孤立小箭头。
6. 本版成片不显示球员标签、检测框、密集小箭头或终点小圆圈。人工编辑手柄不进成片。

这版只示范跑位宽箭头，未包含所有战术工具。传球黄圆点、虚线箭头、挡拆符号、重点脚圈继续按用户需求保留；不得把本片的“去掉小标记”解释为删除那些独立工具。参考图：[完整宽曲线](../tools/tactical-overlay/style-references/wide-curves.jpg)、[播放中的剩余路线](../tools/tactical-overlay/style-references/remaining-route.jpg)。

## 3. Agent 编排步骤

### A. 先看动作，再画路线

查看一段完整回合和起点、中间转弯、终点、阶段切换画面。必要时多取帧，辨认参与者，不凭一个静态画面猜完整跑位。先写阶段说明与动作顺序，再决定每阶段展示哪些路线。

本版的历史配置如下，帧号为原片零基帧号：

| 阶段 | 暂停源帧 | 路线与动作概括 | 动作进度范围 |
| --- | --- | --- | --- |
| 1 | 15 | 右侧球员上提至掩护位置；持球人浅弧接近掩护 | 两条均为 15–40 |
| 2 | 40 | 持球人绕掩护向左；掩护人向右内线顺下 | 绕出 40–78；顺下 40–90 |
| 3 | 90 | 弱侧切入篮下，以一条主路线表达 | 90–132 |

人物与方向来自当时独立视觉核对，不是该配置对任意新视频的通用角色绑定。静止参与者不要凭空添加跑位路线；复杂动作拆阶段，避免上一阶段路线叠到下一阶段。

### B. 概括曲线，而非复制逐帧抖动

Agent 为每个动作设定起终位置及两个弯曲手柄。中间控制点用于表达一次主要弧度，不追求每个检测点都穿过。查看起点、转弯和结束画面，必要时改控制点，再检查大箭头的方向和遮挡。

原配置的四点是参考冻结帧中的 1920×1080 图像坐标。渲染器用该帧的逆地面映射先转换到示意平面，形成连续宽箭头，再通过当前帧映射贴回视频。因此它能跟随镜头，而不是把参考帧的像素箭头固定在屏幕上。

原片使用视觉编排的禁区四角和 8 个镜头关键帧线性插值，属于近似讲解投影，不是精度已验收的球场标定。新工作流应在采用的标准 2D 球场坐标上编排，再用每帧球场映射投回视频；不要把本片的像素控制点或示意相机直接套到新素材。

### C. 单独编排路线完成进度

`progressFrames` 保存“在某个源帧已经走完多少路线”，不是再存一条检测轨迹。Agent 查看中间画面，给少量单调进度点，人工可以修改节奏。例如第一条路线为 `15:0 → 25:0.36 → 33:0.72 → 40:1`。

冻结时源帧不前进，路线完成进度也不前进；绘制动画使用输出时钟。恢复后，用当前源时间推进完成比例，只显示后面的剩余段。

旧脚本按帧号插值，适用于这个固定 30 fps 的样例。新工作台 V2 使用源 PTS 插值；变帧率视频不能照搬 `秒 × 30` 或旧帧号差规则。来源与时间契约按[2D 计划](plans/2026-10-05-2d-first-tactics-workbench-plan.md)执行。

### D. 样式与暂停节奏

| 参数 | 本片值 | 用途 |
| --- | --- | --- |
| 主色 / 描边 | RGB `(25,193,235)` / `(9,52,68)` | 浅色地板和深色禁区都清楚 |
| 线身宽 / 箭头长 / 箭头宽 | `0.20 / 0.67 / 0.70` | 在该近似地面平面形成宽箭头，非测量真值 |
| 透明度 / 描边 | `0.94 / 2.1 px` | 清晰且保留背景 |
| 抗锯齿 | 3 倍绘制再缩小 | 降低曲线边缘锯齿 |
| 提前淡出距离 | `0.55` | 尾部缩到头部前整体退场 |
| 暂停源帧 | `15 / 40 / 90` | 三阶段讲解点 |
| 每次额外停留 | `75` 输出帧，即 `2.5 秒` | 源帧本身另占 1 帧 |
| 停稳 / 绘制 | `5 / 21` 输出帧 | 绘制展开率使用 smoothstep |
| 片尾额外停留 | `18` 输出帧，即 `0.6 秒` | 收尾观看时间 |

帧数核对：`143 + 3×75 + 18 = 386`，输出时长 `386/30 = 12.866667 秒`。旧脚本 `holdIndex < 26` 使用停稳/绘制分支，之后完整展示；完整路线显示后的剩余裁短和固定终点逻辑与展开动画分开。

参数是这版视觉基准，其他分辨率、球场映射与动作速度需要调整，不将它们写成所有素材的默认准确值。

## 4. 复现本片与迁移到工作台

### 旧片复现

1. 从归档复制 `render_authored_video.py` 和 `authored_routes.json` 到**新的本机临时制作目录**，先保留原快照和已认可成片。
2. 确认原片 SHA-256 与上表一致。只在工作副本中调整 JSON 的 `sourceVideo`；确认脚本的 FFmpeg / ffprobe 路径和 Python 依赖 `av、cv2、numpy` 可用。
3. 运行 `python render_authored_video.py` 生成检查图，核对三阶段完整路线、阶段切换和剩余段。
4. 运行 `python render_authored_video.py --encode`。本片默认 NVENC；编码管线失败时脚本可重试 libx264。输出写在该工作副本所在目录。
5. 使用 ffprobe 检查 1080p、30 fps、386 帧和时间；完整解码成片；从编码后的 MP4 抽帧检查，而不只看制作预览。
6. 画面可复现不等于不同 FFmpeg/GPU 版本编码后字节相同。记录新产物的摘要，不要求重编码 MP4 与历史哈希相同。

原始命令和硬编码路径仅用于追溯。不要直接在归档目录或原输出目录执行 `--encode`；该旧脚本会写固定文件名，FFmpeg 的 `-y` 会覆盖已有输出。`finalize_metadata.py` 是原路径绑定的收尾脚本，复现时也只在工作副本中检查和适配。

### 工作台复用

Agent 输入：当前视频证据、所选时间段、稳定球员身份、采用的 2D 轨迹与映射、断点/缺口，加上本版风格参考。输出：阶段、讲解关键帧、少量曲线控制点、单调动作进度、来源与待核对项。

初稿采用到同一个战术文档，人工在 2D 主画布调整控制点、区间和讲解点，再走正式预览/成片 API。保存原始轨迹和人工内容；不能为得到平滑效果回写真实位置，或用独立脚本绕过工作台验收。

参考样片只提供表现形式。新视频每次重新确定角色、坐标、方向和时机；不复制这五条路线当作新比赛证据。
