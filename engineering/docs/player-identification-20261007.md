# 球员标定：自动初检与人工修正

日期：2026-10-07（Asia/Shanghai）。本机实现联调中，真实运行与最终验证结果待下节补齐；未提交或推送。

## 现在的操作顺序

1. 打开已有球员检测结果的视频。Agent 自动对整段抽样初检，无须先选择某个球员、填写号码或保存参考。
2. 查看“Agent 自动初检”的进度、结果和待处理问题。点击问题会定位到相应画面。抽样以整段首尾和切镜为边界，最多八帧；未抽到或证据不足的观察会保留未知，不代表逐帧审核完成。
3. 看见错误时点画面中的人。点击只选中，不会立即把整条跟踪轨迹归给某个球员。
4. 选择“改成谁”“不是球员”“补漏人”或“认回同一个人”。前两项和续认默认作用于明确显示的当前连续片段，点击“应用到这段”一次完成；需要时可以调整起止时间。缺帧、切镜、身份歧义、突然跳变和已有人工边界会截断默认范围。
5. “补漏人”先选球员编号，再点画面中的脚下，只补当前帧，不猜测其他帧。每次操作都能撤销。无需逐个确认十名球员才能继续球场映射或战术制作。

“模型找到的人”就是当前画面的检测框；跟踪号 T 只是跨帧关联线索，不保证一直是同一人。球员 1–10 是固定工作编号，机器建议仍为待核对。号码、球队和真实姓名可以之后在高级工具补充；单人清晰参考续认仍保留。

## Agent 做什么，失败后怎么办

YOLO 提供人物检测，跟踪器连接跨帧观察。新的身份 Agent 在这些观察与原视频抽样图上判断人物角色、提出有证据的身份关联，并列出错人、漏人、身份不确定或未覆盖片段。自动采用只补机器建议，不把它写成人工确认。

同一来源与算法版本复用进行中任务或已完成结果。刷新不应另起一轮模型推理；模型返回期间发生人工改动时，旧结果先保留供核对。使用已有初检更新草稿也要重新检查球员槽位与人工记录，不能将缓存身份套到另一套编号上。

初检错误会显示原因，可显式重试或直接人工修改。不会在失败后无限自动重试。单次运行有总时间预算，结构错误最多在预算内修复一次；服务、传输失败不会无限重发。取消与浏览器卸载分开处理，关闭或刷新页面只卸载当前轮询。

## 裁判误标的具体原因与修复

当前官方训练 001 的篮球专用 YOLO 权重和主要参数与仓库旧 005 的记录一致：conf 0.1、IoU 0.5、输入 704。本机权重与配置摘要也一致；这不证明不同视频、运行环境或用户过去所选变体的全部条件相同。

默认跟踪只提供 player 类，工作台曾只合入同源参考结果的球和篮筐，遗漏裁判角色。001 第 109 帧（约 1.818 秒）主轨 T13/P4 的框与参照裁判框重叠 IoU 0.9824，原片也能确认它是裁判。提高检测阈值不能充分解决，因为这条错误轨迹还曾有较高检测分数。

修复从同源、同帧的框重叠提取角色风险，不用参照结果的 T 号替换主轨编号。单帧证据仅作用于当帧；连续多帧证据只在有观察的有限片段内生效。原始检测、已有绑定及人工确认记录保留，派生轨迹与后续映射、战术输入共用风险校验；相关旧映射需要重新核对。

本机诊断数据和截图放在忽略目录 `artifacts/identity-usability-20261007/`，不随仓库自动共享。核心实证：原有 T13/P4 的 152 个错误自动显示在角色守卫后为零，不能据此宣称全片所有人物的真实身份都已验证。
