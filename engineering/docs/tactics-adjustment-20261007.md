## 人工补漏

选目标球员 → 进入“补漏人” → 在起点点击脚部 → 跳到建议终点并再次点击同一人的脚部 → 预览整段 → 应用。需要时可在中间补关键点；一次撤销还原整段。

默认建议约两秒，并在已知切镜、身份分界、明确遮挡／离场、冲突或已有位置处停止。未标记的遮挡仍需要人工观察并分段，不能称为自动识别全部遮挡。中间位置是按真实时间插值的人工估计，无检测框、无新 T 编号，不确认身份，不冒充模型检出或自动追踪。孤立单帧缺口保留仅补当前帧的兜底。

隔离界面实测：官方 002 起点约 19.05 秒，终点约 21.04 秒；两个端点形成 120 帧预览，其中 118 帧为估计。一次应用后状态正确，一次撤销恢复原缺口。没有采用或保存到生产视频。截图与日志在本机 `artifacts/tactics-adjustment-20261007/`。

## 路线与重点圈

- 每阶段分别覆盖有证据的持球突破、无球切入、顺下、外弹、接应及相关防守移动；路线至少有两个不同观察帧支持。
- Agent 重点圈仅允许对应暂停画面的持球人，同一暂停帧最多一个；球权转移允许后续暂停圈到新持球人。旧 Agent 非持球圈转换成小位置标记，已有人工圈保留。
- 静止参与者使用小位置标记，掩护使用掩护符号。证据不足列人工事项，不虚构路线凑数量。
- 实线表示当前实际动作，虚线表示后续已观察移动；虚线跑位仍能弯曲，不被误当成直线传球。
- 本轮图形以暂停帧解释为主，不承诺重点圈连续跟随球员。位置标记已经接入画布、选中、编辑及渲染链路。

## 生成等待与失败处理

整轮预算仍为 300 秒，首次分析使用最多 80%，预留 20% 给一次自动修复。逐段显示是否真正收到模型内容、等待时长及重试状态。启动 CLI 或创建会话不等于模型已经在分析。

无实质输出时按本次等待期限记录 `no_response`；已有内容但未完成记录 `timeout`。终态模型错误、连接错误和配置错误分别记录。Code Mode 初始化警告不单独判失败；工具调用仍禁止，事件解析不会因为一条错误记录漏检后续事件。

仅战术调用支持显式主模型及备用模型，原球队／号码识别调用继续使用原配置。共享执行器已补兼容检查，避免战术专属字段导致球队识别崩溃。当前本机战术主模型为 `gpt-6.1-sol`；备用同名时明确显示为同模型重试。

发送给模型的 JPEG 附件目标为 1.5 MiB：V4 拼图缩放、压缩模型副本，完整保存原尺寸源帧及逐图坐标变换。它是有损编码，不声称像素完全相同；原视频与工作台预览不缩放或压缩。超过界限明确报错，不悄悄删除参与者证据；V3 单独图片仍按原预算检查。提示词副本只缩短文字和小数显示，所有参与者、观察帧及确认状态保留，原始输入不修改。

## 实际模型结果与限制

历史失败记录 `091bc239-2276-4221-a349-7cec1c2b7c24` 两轮均只有会话与开始事件，没有战术分析内容。历史成功调用也有同一 Code Mode 警告，不能把该警告认定为失败根因。

本轮隔离真实整段测试包括原模型、备用模型、压缩图片以及紧凑提示输入，均未在预算内返回战术内容。小型通道测试能返回文字、真实单图说明及 V4 JSON；真实单图描述约 17 秒返回白红／黑蓝球衣和可读 30 号。

随后控制实验保持第一阶段完整 V4 schema、输入、所有参与者义务及五个观察帧，将它们拼成一张明确标注帧号与坐标变换的图片。一次调用约 84.251 秒返回，按相同来源与覆盖合同校验通过：21 个参与者记录，12 个图形（4 路线、6 位置标记、2 持球圈）。两圈分别属于第 0 与 513 帧，四条虚线路线有第 513 与 684 帧支持。未确认的旧 P 槽位保留待核对，可见人物用局部编号与 null 身份，不伪造绑定。

V4 已默认使用单张拼图附件，每幅原 JPEG、原尺寸编码副本及对应帧、rect／scale／摘要全部存档，输出依然为原视频像素。界面显示实际观察帧数，不把一张附件说成只有一帧证据。V4 内部副本不再误受传输总量限制；真正拼图附件仍严格限制 1.5 MiB。V3 和球队／号码识别不使用这项适配。
