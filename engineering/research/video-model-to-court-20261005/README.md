# 视频模型到篮球 2D 轨迹：研究入口

后续用户明确纠正研究方向：使用现有 Qwen3.8-Max API，以 Agent 反复读图和修正篮球地面轨迹。当前主线见[讨论稿](../qwen-video-trajectory-agent-20261005.md)；本包保留为此前视频模型背景研究，不代表当前建议另选 / 训练模型。

采集日期：2026-10-05，America/New_York。按用户澄清，核心问题是让模型直接读取比赛视频，得到球员连续位置并映射到 2D 球场；不存在的 Agent 视频模块不继续硬拆。

- [研究报告](REPORT.md)：模型如何编码视频、20 个项目比较、源码中实际的抽帧 / 掩码路径、现有工具的接入点和下一轮对照实验。
- [来源清单](sources.json)：20 个主仓库的固定提交、README 地址和正文 SHA-256；其中 7 个已另行克隆并阅读源码。许可证字段仅是 GitHub 元数据提示。
- [Qwen API 验证准备](QWEN_API_NOTES.md)：沿用用户约定的 `QWEN_KEY`，核实视频接口与采样参数；当前未做鉴权调用或模型实测。
- [上一轮 OpenCode / Codex 研究](../agent-video-understanding-20261005/README.md)：已按用户要求提交并推送，功能提交 `5725940`。该报告主要解决 Agent 输入协议问题。

最贴近新目标的研究候选是 Sa2VA、UFVideo 和 SAM3；Qwen3-VL 适合测试直接视频定位及身份 / 动作判断；SoccerNet Game State Reconstruction 给出了从视频到身份与 2D 小地图的完整工程参照。足球权重和场地模板不能直接作为篮球模型。

本轮完成资料与源码研究，没有下载大模型权重或执行 GPU 推理，没有新增模型精度、速度或十人身份稳定性的实测结论，也没有修改工作台功能。新研究包当前留在本地；此前 `5725940` 的推送状态与本包区分记录。
