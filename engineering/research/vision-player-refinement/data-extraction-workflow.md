# 直播画面筛选、身份标定与轨迹提取

更新：2026-10-02，Asia/Shanghai。依据本轮用户明确提出的三步流程及“先把数据提取做好”的优先级；不是已确认的球队战术或团队技术选型共识。

## 当前工作顺序

1. **直播画面筛选**：先保留能看清整体站位的普通转播区间。特写、采访、回放、停帧和慢放不进入数据提取区间。当前由操作人员逐帧选起止，尚无自动画面类型识别器。
2. **球员标定**：把场上十名球员对应到 P1–P10，填写球队、号码或姓名。P 是人工身份槽位，模型候选不保证只有十人，也可能包含观众和裁判；裁判 R1–R3 可选。当前不自动读取球衣号码或真实姓名。
3. **轨迹补全**：把同一人的多个临时 T 编号按正确帧区间归到同一个 P。例如 T1 和 T22 分别出现在前后段，人工确认后都属于 P1。串号要缩小关联区间；切镜不自动接续。

位置、身份和轨迹完成后，才分析某一时刻的防守、进攻站位、球员关系及战术意图，再考虑讲解。当前界面使用对阵 / 节次命名素材；采集动作标签仅供来源参考，不作为识别结果或必须接受的战术结论。球场米制映射是可选后续处理，不阻碍先提取原图像素轨迹。

## 已实现的本机行为

- 第一页选择多个保留区间，应用后生成实际 MP4 和对应逐帧候选；保留整段时直接使用原文件。删掉的区间不进入输出，保留区间之间自动设置切镜边界。原视频和原草稿保留。
- 裁切记录保留来源视频哈希、原帧号和原时间。嵌套裁切仍追溯到最初导入的工作台视频；帧间原始时间差保留，避免改变可变帧率片段的运动速度。
- 第二页用 React 管理 P 身份、人物候选预览、明确关联及坐标编辑。十名球员的完整选择可以人工确认；调试单人的轨迹可先进入第三页。未确认十人不会伪造完成记录。
- 身份确认按时间向后生效：确认帧之前保留原 ID，之后用新 ID，直到下一次身份分界 / 后续区间起点 / 切镜。位置编辑不建立分界；同一 ID 的重复占用只在受影响段释放旧身份，后续正确确认保留。旧草稿加载前原样备份，原锚点和区间不删除。详细核查、迁移歧义与操作例子见[身份绑定记录](identity-binding-review.md)。
- 第三页按区间关联多个 T，补原图脚点、拖动脚点或人物框、调整框大小、撤销和保留出画状态。新草稿默认关闭自动插值，旧草稿保留原设置。
- 第三页的原视频下方直接显示同步 2D 球场，保留滑动半场 / 全场、平移、跟随球员、点击轨迹定位及当前帧人工球场补点。校准入口仍独立，完成后可返回；无标定时显示待标定，不伪造映射坐标。切换页签移动同一个画布，草稿和操作记录保留。
- 可在原图手绘路径，只拟补选中区间的缺失帧，保留已知位置、冲突和出画状态。路径按真实视频时间沿绘制路线均匀分配，保存为 `manual_path` / `uniform_time_along_drawn_path`，需要逐帧核对；不能跨切镜。确认某一帧只把这一帧改成人工位置，其余拟补点仍待核对。
- 导出保留直播筛选、十人选择确认、来源帧映射、分段 T 关联、模型 / 人工 / 估计来源、手绘待核对帧和未解决缺口。始终保留 `allFramesManuallyVerified=false`；球场米制精度仍未验证。

实现入口：[工作台](../../tools/player-review/README.md)、[裁切服务](../../scripts/review_video_trim.py)、[样例与来源](../../../data/videos/tactics/acceptance/README.md)。实际剪辑缓存保存在被忽略的 `artifacts/player-review-clips/`，重启可恢复；草稿仍在对应浏览器的站点存储中。本机 HTTP 服务不上传数据。
