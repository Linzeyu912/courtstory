# 场地识别、移动镜头与球场映射

采集与实测：2026-10-01，Asia/Shanghai。范围：本地 001 NBA 片段与操作工作台。以下选型是建议，不是团队共识或赛事要求。

## 结论

建议分成三个环节：**识别场地结构并人工确认 → 随镜头更新透视映射 → 用场地线检查误差并允许重校**。球员检测与场地标定可以使用不同方法。

现有代码的 ABCD 是禁区四角，尺寸为 5.7912 × 4.8768 米，未把禁区设为整场。问题是旧界面没有清楚标明范围，且只用局部四角向远处推算，容易放大点选误差。旧首帧映射把“中线 × 远侧边线”投到约 (1668,517)，目视参考约 (1754,507)，相差约 86 像素。这个粗查支持重做标定，但不是独立测量真值。

NBA 模板为 28.6512 × 15.24 米；本次三分线采用篮圈中心半径 7.239 米、底角直线距边线 0.9144 米。依据 [NBA 规则第一条](https://official.nba.com/rule-no-1-court-dimensions-equipment/)及[官方 2025–26 规则球场图](https://cdn.nba.com/manage/2026/01/Official-2025-26-NBA-Playing-Rules.pdf)。NBA 与其他赛事的场地尺寸不能混用。

## 已实现

- 球场配色改为浅枫木色地板、灰蓝禁区和深色线条，保留半场滑动与全场视图。
- 默认进入“球场标定”。明确区分禁区、半场和全场尺寸。
- A–D 为禁区四角；E–H 为底线 / 中线与两条边线的交点；I–J 为底线与三分直线的交点。可以单点新增、重选、停用、删除、撤销，也可重做整组四角。
- 多点拟合球场到原图的单应矩阵，求逆得到原图到球场映射。用于拟合的点显示像素残差；残差不是独立准确率。点不足或布局退化时停止映射。
- 将禁区、三分线、边线、底线与中线投回原视频，供操作者核对。三分弧目前用于核对，没有作为自动识别出的语义线输入求解。
- [扩展参考](clip001-court-expanded.json)增加远侧底线交点，并在首帧增加中线交点；旧[四角快照](clip001-court-reference.json)保留原值。扩展参考仍来自目视读取，全部待复核。
- 已有草稿可点击“载入扩展参照点（保留人工帧）”；手工改过的整帧保留。新参考只在没有旧标定时默认载入。原图球员锚点、身份关联与球场校准分别保存。

前端仍使用相邻标定关键帧间的四个规范点插值，未把下面的光流实验接进正式映射。超过 1.2 秒、切镜、缺少两端或球篮方向不同的区间不生成映射。所有球场坐标继续标记待复核，不输出跑动距离或速度。

## 相机角度和坐标怎么转换

定义 `H_t` 为当前帧的“球场地面 → 图像”映射：

```
图像齐次坐标 ∝ H_t × [球场 X, 球场 Y, 1]
球场齐次坐标 ∝ inverse(H_t) × [脚点 u, 脚点 v, 1]
```

转换后需除以齐次坐标的第三项。地面是同一平面时，单应矩阵可表达透视变化；同一镜头摇动、俯仰或变焦后，需更新 `H_t`。不能把一张矩阵用于整个移动镜头，也不能只用一个“左右角度”描述所有变化。

二维位置整理和地面箭头叠加可以先用 `H_t`，不必先获得唯一的物理角度。若要输出可信的相机方位角、俯仰角和焦距，需要内参或额外约束，并处理姿态分解的多解问题。不能从四个目视点直接宣称已经测出真实夹角。依据：[OpenCV 单应与相机姿态教程](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)。

只把地面接触点用作球员位置。框底部中心只是代理；起跳、遮挡、脚踝不清楚时仍会有误差。篮筐 / 篮板有高度，不能当作地面交点混进同一平面拟合。三分弧在图像上的“最突出点”也不一定对应球场弧顶，不可随意配成已知点。

## 非 YOLO 方案

| 方法 | 能做什么 | 当前判断 |

## 本机实验：快，但纯传播会漂移

脚本：[analyze_court_geometry.py](../../scripts/analyze_court_geometry.py)。结果摘要：[court-geometry-audit.json](court-geometry-audit.json)。

- 输入：001 片段，1920 × 1080，243 帧，约 8.1 秒。
- OpenCV 5.0.0，CPU 4 线程，处理尺寸 960 × 540；没有 GPU 推理。用首帧扩展参考初始化球场区域，利用已有检测框屏蔽人物；没有重新运行 YOLO。因此不是无先验的自动场地识别。
- 首帧 LSD 及筛选约 **0.047 秒**，保留 **40 条无语义直线候选**。候选中仍有木纹、标志及不完整线段。
- 解码、线候选、逐帧光流、矩阵估计及预览写盘共 **2.49 秒**，单次测量。全部 242 次相邻帧估计通过实验门槛。
- 在 8 个后续参考帧，与目视点的中位差约为 **6.0、16.5、15.4、24.9、24.5、19.6、19.3、39.9 像素**（按原始分辨率）。预览末帧可见投影线漂移。参考点并非测量真值；这是差异诊断，不是准确率。
- 说明：光流内点比例、局部残差与覆盖范围合格，也可能积累整体误差。不能把“242 帧通过”解释成“242 帧位置正确”。质量门槛尚未在切镜或其他视频上验收。

输出图像及逐帧矩阵保存在被忽略的 `artifacts/court-calibration-audit/`；原素材不复制到研究目录。复现：


本测量不含模型冷启动、首次人物检测、自动语义识别、人工校准和完整成片生成，不能换算成完整视频的十分钟承诺，也不构成 AWS 资源实测。

## 建议下一步讨论

1. 初始画面输出带名称的线 / 点候选，操作者确认球篮方向、模板及几个分散交点。看不到的点留空。
2. 先对比 KaliCalib 与传统几何候选，使用同一批清晰、摇镜、变焦、遮挡和切镜片段。独立标注的核验点不能同时用于拟合。
3. 镜头内用光流更新；定期重新匹配实际场地线，联合点线误差重校。切镜另起标定，失效区间明确留空。
4. 人工点权重、误差报警阈值和重校间隔需由多片段实验决定。验收包含场地线贴合、独立球场位置误差、人工耗时与整段处理时间。

首轮已把人工入口、几何计算、可视化与诊断做实；自动语义模型和光流尚未接入工作台，物理相机参数估计尚未实现。后续离线模型试跑见下节。

## 脚点与场地网络补充实测（2026-10-01）

本节对应用户进一步明确的目标：先可靠提取每名球员在真实球场上的运动轨迹，再分析战术并向原画面叠加内容。以下均为本机单片段实验和实施建议，未通过独立精度验收。

### 位置到底如何还原

1. 确认使用 NBA 尺寸，并把画面中可见的场地交点与模板上的具名位置配对。四点应构成有效二维布局，不能集中在一条线上；无需恰好使用整个球场的四个角。
2. 解球场地面到图像的单应矩阵 `H_t`。例如 ABCD 是禁区四角，必须对应禁区的真实米制坐标，不能把它们对应为整场四角。画面中呈现梯形或其他四边形，不影响此方法；关键是对应点的身份正确。
3. 对原图地面点 `(u,v)` 计算 `[a,b,c] = inverse(H_t) × [u,v,1]`，输出 `(X,Y)=(a/c,b/c)`。这是透视变换，不是按矩形宽高做比例缩放。参见前述 OpenCV 教程。
4. 镜头移动后更新 `H_t`，再处理该帧脚点。切镜重新初始化。前端当前只有关键帧插值近似；尚未实现连续自动重校，也不能因此宣称真实轨迹已经恢复准确。

相机角度可作为后续诊断或三维渲染参数。就地面轨迹和地面贴图而言，直接使用单应矩阵即可；由四点唯一求出真实相机方位、俯仰和焦距仍缺少内参或额外约束。

### 脚点来源是独立的一层

旧界面的 `manual` 同时涵盖“人工点中检测框”和“人工补位置”。前者坐标仍来自框底边中心。本轮新增 `footMethod` 并修正文案，避免把人工选人解释为人工测量脚点。

建议后续约定球员位置为地面上的代表点，并保持全片定义一致：两脚均着地且可见时，可分别投影鞋底接地点，再在球场坐标中求中点；单脚支撑时记录支撑状态。起跳、遮挡、接触状态不确定时，保留未知或使用有来源的时序估计，不把悬空脚踝硬投影成地面真值。站立脚切换也会引起代表点抖动，需要在物理坐标中审慎平滑。

当前短缺口仍在原图中线性插值，再投影；这会混入镜头运动。下一阶段应在两端都有可靠标定和身份时，优先比较球场坐标插值，并保留估计状态、端点和时间范围。过长遮挡、切镜、身份冲突不应强制补满。

### YOLOv8s-pose：能补脚踝候选，不能单独解决地面接触

官方资料：[YOLOv8 模型](https://docs.ultralytics.com/models/yolov8/)、[姿态任务与 17 个 COCO 关键点](https://docs.ultralytics.com/tasks/pose/)，采集于 2026-10-01。使用[官方预训练权重](https://github.com/ultralytics/assets/releases/download/v8.4.0/yolov8s-pose.pt)，未训练。

脚本：[benchmark_ground_anchors.py](../../scripts/benchmark_ground_anchors.py)；可共享摘要：[ground-anchor-probe.json](ground-anchor-probe.json)。硬件为本机 RTX 5070 Laptop 8 GB、Ryzen 9955HX、32 GB RAM；现有 PyTorch 2.11 CUDA 12.8 环境，输入尺寸 1280，GPU 推理。

- 抽取 9 帧，75 次已有跟踪观测中匹配到 67 次姿态；其中 63 次双脚踝置信度均 ≥ 0.5。按检测框 IoU ≥ 0.5 匹配；这不是全场真实球员召回率，也没有验证姿态身份全部正确。
- 预热后单帧 `predict` 调用中位耗时 13.7 ms；模型加载及预热 0.60 秒。遍历视频解码、仅对 9 帧推理及写预览约 0.89 秒，不包含加载预热，也不是 243 帧全量处理时间。
- 将两脚踝分别投到地面后求中点，与已有框底中心的球场坐标相比，中位差 1.02 米、P90 1.48 米。使用的场地参考本身未验收；**这表示两种代理不一致，不能解释为姿态改善了多少误差**。
- 首帧目视复核发现：遮挡处无候选或低分，也有蹲姿球员的高分脚踝明显高于鞋底。脚踝有离地高度；置信度高并不能证明它是地面接触点。所有实验观测的接触状态保持未知。

后续可比较 [MMPose WholeBody 预训练模型](https://mmpose.readthedocs.io/en/latest/model_zoo/wholebody_2d_keypoint.html)。其[官方关键点定义](https://github.com/open-mmlab/mmpose/blob/main/configs/_base_/datasets/coco_wholebody.py)包含左右脚趾与脚跟，可能更适合定位鞋部；仍需判定接触状态及独立验证。本次未下载运行 MMPose。

### KaliCalib：已有快速候选，但未达到可自动采用的条件

从[作者仓库](https://github.com/CEA-LIST/KaliCalib)的官方 GitHub API 获取源码归档，版本目录 `CEA-LIST-KaliCalib-3b3f52b`。读取 [网络](https://github.com/CEA-LIST/KaliCalib/blob/3b3f52b/kalicalib/model_resnet.py)、[场地点定义](https://github.com/CEA-LIST/KaliCalib/blob/3b3f52b/data/datasets/viewds.py)、[单应估计](https://github.com/CEA-LIST/KaliCalib/blob/3b3f52b/kalicalib/estimateHomography.py)，采集于 2026-10-01。

实验脚本 [probe_kalicalib.py](../../scripts/probe_kalicalib.py)加载作者网络和两份提供的权重，使用 960 × 540 输入、91 个地面类别的响应中心与 RANSAC 平面拟合，排除有高度的篮筐点。没有运行作者完整相机优化流程，也没有使用原实现中的默认相机兜底，因此结果仅评价这次局部接入。

| 权重 | 抽样帧 | 地面类别数 / RANSAC 内点数 | 与目视参考的归一化模板差异中位数 |
|---|---|---|---|
| `model_test.pth` | 0 / 90 / 242 | 17/6、34/23、31/11 | 1050.2 / 32.8 / 23.7 px |
| `model_challenge.pth` | 0 / 90 / 242 | 60/39、52/33、40/28 | 29.9 / 12.3 / 31.5 px |

这里原生模板是 **28 × 15 米**，本片 NBA 是 **28.6512 × 15.24 米**。表中仅按整场长宽归一化后比较参考点，没有完成 NBA 线语义适配；这些差异不能当作同一模板上的精度指标。challenge 权重预览能提出大致场形，仍有明显偏移；test 权重首帧形状严重错误，说明“能解出矩阵”不足以代表标定有效。

预热后的网络前向及输出回传约 6.9–8.8 ms；第一次调用约 200 ms。该计时不含图像解码、预处理、RANSAC、完整相机优化和人工校正，不能据此推算最终视频耗时。完整摘要与权重哈希见 [kalicalib-probe.json](kalicalib-probe.json)。本实验支持继续研究“自动提出候选 + 人工确认 + 几何核验”，尚未接入工作台正式映射。

### 已落地的误差检查

- 新增只作核验的参照点，明确不参与求解。在独立 QA 草稿里，A–D 四角拟合残差 0.0 px；将 E/F 留出核验后，两者分别差 19.1 / 86.3 px，对应 0.58 / 1.50 米。参考是目视点，尚不是真值。
- 所选球员显示 `(u,v)` 像素 → `(X,Y)` 米，以及框底、人工点或插值来源。
- 标出球员是否位于控制点地面凸包范围外。只标禁区再投到远端属于外推，更需要远处分散参照；范围内也不保证准确。
- 用映射的局部雅可比矩阵显示“脚点偏 5 px，最敏感方向局部可偏约多少米”。这只是固定像素扰动的近似响应，**不包含标定误差，不是误差上限或统计置信区间**。
- 28 项 JavaScript 测试通过；浏览器验证留出点不参与拟合、来源显示与撤销。未替用户确认正式结果，也未改变原草稿的选人、补点记录。
