## 2. 决赛评分：100 分，视觉与作品效果最高

组委会说明每项由评委给出 1–10 分，再按权重折算。以下列出原评分项名称，描述采用归纳；来源为 G3 的决赛表。

| 官方评分项 | 权重 | 官方关注点 | 我们应准备的内容（建议） |
| --- | ---: | --- | --- |
| 技术方案与架构 | **18 分** | 架构表达、输入到输出的完整性、AWS 服务选择及职责 | 一张产品流程图、一张实际部署图；说明每个服务承担什么 |
| 实现深度与难度 | **18 分** | 基础调用以外的算法、处理和工程工作，包括对识别结果加工、自定义指标等 | 证据绑定、姓名与位置分离、版本依赖、统一时间轴的真实例子 |
| 数据运用准确性 | **15 分** | 姓名、号码、球队和统计是否符合事实；数据是否对应画面 | 一个回合的来源、字段、人物、时间与成片对照；标明未知和推断 |
| 讲解与答辩表现 | **9 分** | 逻辑、时间控制、是否正面回应提问 | 5 分钟彩排、常见问答与证据备页 |
| 视觉与作品效果 | **40 分** | 画面表达、篮球叙事、感染力、视觉质量、交互与创新 | 优先展示完整作品，说明数据怎样帮助观众理解这次进攻 |
| **合计** | **100 分** | | |

官方路演指南 G5 建议解释设计原因及选择数据维度的原因，并兼顾最终呈现。该建议没有规定必须采用哪种算法或增加多少 AWS 服务。

**初赛分数不要搬进决赛：** 初赛是机器 35、人工 55（数据/内容 30＋UX/UI 25）、问答 4、投篮 6；决赛使用上表。人工评分→机器评分→数据/内容→UX/UI→问答的同分比较顺序位于**初赛**章节，本轮未见决赛同分细则，不能自行套用。[初赛原文](https://csdn.feishu.cn/wiki/B3NSwj16GiSCR7kcM5vc9RjMnQb#doxcnaLBxq3LEY1PoQKPk6TaH3c)

## 3. 赛题内容：必须做什么，哪些是可选项

| 类别 | 官方要求或边界 | 对本项目的影响（解释） |
| --- | --- | --- |
| 必须 | Agent 接收深度赛场历史/单场数据，把数据可视化叠加到真实比赛视频 | 只有解说、绘图编辑器或数据表格，不能替代官方数据进入比赛画面的闭环 |
| 期望效果 | 姓名对应正确位置，指标随回合出现，并能解释战术选择或局面 | 应能逐项核对“谁、哪次事件、什么值、画面哪里”，不能只做装饰 |
| 可选 | 人工或 AI 解说 | 现有解说能力可增强叙事，但不能挤占必需的数据可视化 |
| 必须声明 | 使用 AI 生成解说需明确说明 | 在作品说明或页面明确标识 AI 解说；具体标识位置是团队设计选择 |
| 素材 | 可收集训练视频及更多 NBA 深度数据；交付物不能含未授权录像，需披露来源 | 仓库中的素材、历史训练片不自动等于本次指定考试素材 |
| 数据粒度 | 深度数据只有出手瞬间点位，没有逐帧轨迹 | 不把模型跟踪或人工补线说成官方轨迹真值 |
| 排除项 | 实时信号接入、数字孪生、跑动轨迹复原、判罚认定、博彩类预测 | 答辩聚焦回合解读与原视频表达；完整轨迹复原不作为赛题主成果 |

来源：G1 的赛题形式、期望结果、数据提供与赛题边界；G6 的 AI 解说声明。官方列举投篮率、球员引力等维度，本轮未读到“每种指标必须全部展示”或要求自行重建官方算法的条款。

当前工程的绿/黄/红投篮机会及防守压力是视频推断，NBA 2K 是游戏能力背景，都不能替代官方深度指标。此区别属于本项目事实说明，详见[技术母稿的数据分层](../engineering/docs/finals-defense-technical-route-20261010.md#6-数据准确性四种来源分别说明)。

## 4. 技术准入与 AWS 使用

| 要求 | 官方定位 | 我们需要出示的完成证据（建议） |
| --- | --- | --- |
| Amazon Bedrock AgentCore 承载智能体能力 | 三项硬性技术要求之一；只在本地运行逻辑或仅做模型调用循环不算满足 | 当前版本的真实智能体入口、调用记录、输入到有效输出的链路 |
| Amazon CloudFront＋Web 交互界面 | 三项硬性技术要求之一；命令行、Notebook、录屏或纯 API 不能替代 | 可访问的本队作品页面、完整成片、实际交互 |
| AWS CDK 定义基础设施 | 三项硬性技术要求之一；手工控制台、纯 CLI 脚本、Terraform/SAM/裸 CloudFormation 不能替代 | 与真实部署匹配的 CDK 工程、依赖和复现步骤 |
| 赛事账号及 `us-east-1` | 全部资源的环境约束 | 当前账号/区域验收；凭据和私有资源定位不进入答辩公开页 |
| GitHub Private 仓库 | 组委会读取工程重跑；公开仓库会被拒绝读取与评分 | 绑定仓库、读取权限、有效提交及代码/CDK/说明；本轮未重新检查 Portal |
| AWS 服务使用深度 | 鼓励有效使用原生托管服务，重视协作与完整链路 | 解释真实服务的必要性与使用方式，不按数量堆服务图标 |

来源：Q1、Q2、Q3、G4、G6。官方推荐流程为 S3 输入 → AgentCore → Bedrock 理解 → FFmpeg 叠加 → CloudFront 展示；Polly 为可选语音示例。它不是“必须把每一种可用服务都接入”的要求。

资源限制按 Q4 的精确范围理解：**EC2 GPU 机型配额为 0**；GPU 可以通过 SageMaker 申请，数量/机型取决于当时资源，不保证可用。因此不能把“GPU 0”扩大成所有云端 GPU 服务均被禁止。当前项目是否实际申请或使用，应另外查运行记录。

仓库还保存了用户转发的[CDK 补充通知](cdk-deployment-notice-20261006.md)：不重复 bootstrap，新增角色使用指定权限边界。该通知原始发布 URL 未提供；其来源等级与本轮直接读取的两份飞书正文分开，不把通知中的示例服务列为必选项。
