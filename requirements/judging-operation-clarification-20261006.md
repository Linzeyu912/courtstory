# CloudFront 作品链接、私有仓库与两条评审路径

核验：2026-10-06 16:12（Asia/Shanghai）。本轮在浏览器实读 10 月 5 日版 Quick Start 第 1–5 节、终极指南“账号与环境开通”“在提交项目前”，以及 9 月 28 日培训纪要第 3.2、3.5 节。以下区分官方要求、通俗解释与仍缺的执行细节；未创建资源、部署应用或提交作品。

## 1. 官方明确的两条路径

| 路径 | 主办方取得什么 | 用来评什么 | 来源 |
| --- | --- | --- | --- |
| 人工评分 | Portal 最后有效提交的本队 CloudFront 作品链接 | 成片表达、数据准确性、交互和作品体验 | Quick Start 第 3、5 节；终极指南提交清单 |
| 机器评分 | Portal 绑定的私有 GitHub 仓库中的 Agent 代码与 CDK | 重跑工程，检查工程链路与 AWS 使用情况 | Quick Start 第 3、4 节 |

CloudFront 不负责读取或测试 GitHub 仓库。它负责将已经部署的网页与内容交付给浏览器。仓库绑定和作品 URL 提交是两件事，分别服务两条评审路径。

## 2. CloudFront URL 到底是什么

它是我们部署后获得的作品网站地址，通常使用 AWS 为本队 CloudFront 分配的域名，再加上实际页面路径。域名的作用类似网站门牌号；浏览器通过它取得网页、图片和视频。

- CloudFront 的源站可以是 S3 或 HTTP 应用服务；具体部署由团队工程实现。
- 这个地址应打开本队的作品页面，不能拿主办方 Portal 地址代替。
- GitHub 地址用于读代码；本机 localhost 地址只代表访问者自己的电脑；它们不能代替本队部署后的作品入口。
- CloudFront 网址产生于分发配置与部署。推送 GitHub 或把视频放进 S3，并不会自动让完整作品网页上线。

这里的 CloudFront 技术机制依据 [AWS 官方介绍](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Introduction.html)，不是赛事额外增加的条件。

## 3. 人工评审应看到成片，制作工作台另作理解

终极指南提交清单明确：本队自建的 CloudFront 公网链接应承载考试视频的完整作品成片，方便评审线上直接打开观看；链接有效期覆盖 10 月 10 日 20:00–22:20。Quick Start 同时要求 Web 交互界面，并排除以单独命令行、Notebook、录屏或纯 API 作为交付形式。

因此需要同时理解两点：完成的成片应直接可看，作品又应有 Web 交互界面。当前已读条款没有要求每位评委先上传视频、逐个标定球员、编辑箭头并等系统渲染，也没有证明“只有一个裸 MP4 链接”就满足交互要求。

对现有工作台的页面安排属于工程建议，见 [部署说明中的作品入口与制作流程](../engineering/docs/aws-workbench-deployment-guide.md#作品提交入口与制作工作台)。不能把开发人员完整制作流程当成官方要求评委执行的操作步骤。

## 4. 主办方怎样拿仓库，怎样重跑

10 月 5 日版 Quick Start 说明：Agent 代码和 CDK 放入已经绑定的 GitHub 仓库，主办方从该仓库统一拉取代码并重跑机器评分。终极指南要求仓库保持 Private。

9 月 28 日培训纪要第 3.2 节进一步描述，绑定时通过 GitHub App 授权赛事系统读取所选私有仓库；以 10 月 10 日 20:00 前最后一次仓库提交作为有效提交。该段是培训纪要口径，后续更具体通知优先。本轮未重新检查本队 App 安装权限或评分系统后台。

可以把“重跑”理解为主办方拿到工程，按约定入口再次执行并检查结果与工程链路。不能由此直接推断它会从零重建所有云资源、像人一样点击网页，或执行团队全部单元测试。

终极指南明确要求统一 Agent 接口、输入参数和产物路径，但本轮读到的上述相关章节没有提供完整机器可执行契约。仍需确认：

1. 评测读取的分支与提交锁定方式；精确抓取时点、时间戳解释和机制。
2. 具体如何调用：命令行、HTTP 接口，还是 AgentCore 调用；入口名称是什么。
3. 输入字段、示例请求、文件位置和数据格式。
4. 输出结构、成片路径、成功 / 失败表示、超时与允许重试规则。
5. 重跑是否复用现有资源，或会重新部署；人工确认步骤如何适配机器评测。

这些是尚未取得的操作细节，不应自行把项目内部 API 命名为官方统一接口。准备可复现说明、依赖和清晰入口有助于工程接续，但不等于已通过官方评测。

## 5. 提交操作的已确认范围

- 绑定私有 GitHub 仓库，让赛事系统可以取得工程。
- 作品在赛事 AWS 环境部署完成，生成可访问的本队 CloudFront 地址。
- 在 Portal 的“Submit your entry”提交作品 URL；可覆盖提交，相邻提交至少间隔 1 分钟。
- Quick Start 明确截止时间为 2026-10-10 20:00（北京时间），此前最后有效提交的 URL 用于评分，截止后不能修改提交。
- 按终极指南同时准备部署的 Agent、私有代码库、说明文档、演示视频与完整成片入口。

本段是已读指南的整理，不表示本轮已完成任一提交操作。

## 5.1 两小时窗口与截止后操作的边界

补充核验：2026-10-06 20:44（Asia/Shanghai）。重新在浏览器读取终极指南 Day 1 时间表、“在提交项目前”“参赛规则与纪律”，以及 Quick Start“二、时间与提交”。页面均显示最近修改于 10 月 5 日。

**两小时是考试视频发布至提交截止的窗口，不能理解为截止后还可继续制作两小时。**

| 时间（10 月 10 日，北京时间） | 原文确认的安排 | 对工作台流程的解释 |
| --- | --- | --- |
| 18:00 之前 | 白天用练习视频构建、调试 Agent；最终考试视频未发布 | 提前把工作台及云端链路调通是工程建议；手册没有写 18:00 冻结所有代码 |
| 18:00–19:45 | 发布最终考试视频并进行调优；时间表明确 19:45 结束调优 | 在此窗口运行工作台处理考试素材、检查结果并准备成片；具体人工校正范围仍需与 Agent 重跑要求一致 |
| 19:45–20:00 | 作品提交；提交内容包括部署的 Agent、私有仓库、文档、演示和承载完整考试成片的 CloudFront 链接 | 按此阶段完成最终产物和入口验收、提交；不要把还没处理完的视频留到审核阶段补做 |
| 20:00–22:20 | 作品链接需持续可访问，供评审查看 | 保持已提交作品可播放、可交互；这个可用期不构成继续改造成片的授权 |

Quick Start 明确了 20:00 后 Portal 提交按钮失效、不能再提交或修改。它没有逐项解释后台数据是否冻结、截止前已启动的渲染是否允许跨过截止时间、同一 URL 下何时锁定成片字节，或允许何种紧急维护。因此不能把“按钮冻结”扩大为已经证实“所有云端操作技术上都会被禁用”，也不能反向推导“只要不改代码，截止后修改标注、重新渲染并替换成片就合规”。

对当前问题的解释是：**在截止前用已部署工作台完成制作，再通过网页向评委展示，这一流程与上述交付安排相符；‘只冻结代码，20:00 后仍可加工最终评分视频’没有获得已读条款支持。** 网页还可以运行属于技术能力；是否能改变用于评分的产物属于赛事规则。

工程上建议将最终成片在 19:45 前准备好，19:45–20:00 检查并提交，之后保持展示版本稳定。这里是依据时间表的实施建议，不是新发现的官方逐项禁止清单。若需要跨截止渲染、截止后修改标注或替换成片，应先取得组委会明确口径；本轮未联系组委会，也未声称已经获准。
