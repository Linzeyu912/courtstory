采集日期：2026 年 9 月 17 日
用途：供团队了解赛事背景、比较其他比赛、讨论作品方向。本文件不包含报名答案。

## 本轮结论
通过 TinyFish 与 Exa，从本届比赛扩展到 NBA 官方数据资料、AWS 官方赛事、MLH 规则及篮球分析获奖案例。Exa 的 6 次查询返回 30 条结果（含重复和无关项），另做 TinyFish 定向检索；最终读取并登记 17 个不同页面的正文。这是一次有针对性的资料补充，不代表穷尽全网。

新增资料最有价值的部分，是 NBA 数据指标的正确含义、其他赛事对工程完成度的要求，以及获奖项目如何让评委快速理解和验证作品。未找到可核实的本届新增评分权重、数据下载包或补充报名筛选细则。

资料分为三层：
- 本届规则：仍以 Broadcast Code 12 官网和后续正式通知为准。
- 外部事实：NBA 指标说明、其他赛事规则和获奖案例，可用于学习。
- 团队建议：以下明确标注为“讨论建议”的内容，是根据资料作出的推论，不是官方要求。

## 一 NBA 官方指标说明

### 投篮难度 xFG%
xFG% 是在给定投篮追踪条件下，平均 NBA 球员的预期命中率；数值越低通常表示出手更难。它不是某位球员的个人命中概率，也不是实际命中率。官方模型说明列出投篮距离、身体朝向与平衡、移动速度、防守干扰等因素，并明确不纳入球员身份、进攻时钟和分差。

讨论建议：解说应区分“这次出手条件有多难”和“这名球员投得有多好”。制作指标词典时，记录定义和排除项；不要把一般篮球常识直接说成官方模型的输入特征。
来源：[S01 官方词典](https://www.nba.com/news/inside-the-game-stat-glossary)、[S09 xFG% 模型说明](https://www.nba.com/news/intro-to-expected-field-goal-percentage)。

### 球员引力 Gravity
Gravity 比较球员实际吸引的防守压力与位置条件下的预期压力，衡量超出预期的防守关注。官方介绍采用 -100 至 100 的标准化尺度，0 对应联盟平均。指标词典还限定其计算场景：五名进攻球员和球在前场，篮板争抢场景不计入。

讨论建议：展示某位无球队员如何吸引防守、给队友创造空间，比简单画一个“吸引范围圈”更有解释力；图形必须能对应到实际数据与时间点。
来源：[S03 Gravity 解释](https://www.nba.com/news/intro-to-gravity-stat-nba-2025)、[S01 官方词典](https://www.nba.com/news/inside-the-game-stat-glossary)。

### 防守压力 Defensive Pressure Score
官方说明的分值范围为 0 至 1。它结合距离、传球线路、球员间遮挡、速度及移动方向等因素，而不只是最近防守人距离。高压力不必然代表整体防守更好：包夹持球人可能同时放空篮下队友。

讨论建议：解说要同时观察“被压迫的人”和“因此获得机会的人”，避免将一个高数值直接评价为成功防守。
来源：[S10 防守压力说明](https://www.nba.com/news/understanding-defensive-pressure-score)。

### 关键度 Leverage
Leverage 比较真实事件与相反结果对应的赢球概率，而不是简单用回合结束概率减去回合开始概率。NBA 举例：命中后三分球对应 75% 赢球概率，若投失且对手抢到篮板则是 55%，比较的是这两个结果之间的 20 个百分点。事件贡献还会分配给相关球员，并考虑创造机会、防守和前后事件。

讨论建议：关键回合筛选不能只盯第四节最后两分钟；比赛较早阶段也可能发生高影响事件。若本届“关键度”字段实际采用其他定义，应服从赛事数据字典。
来源：[S02 Leverage 说明](https://www.nba.com/news/leverage-stat-explainer)。

### 官方平台能力不等于参赛数据权限
NBA 与 AWS 已介绍 Inside the Game 和 Play Finder，用于高级统计、相似回合检索及篮球理解。公开技术介绍提及每名球员 29 个身体点、每秒 60 次采集，但这不证明本届比赛会提供全部骨骼追踪数据、同样采样率或相关 API。公开介绍也不是数据下载授权。
来源：[S16 NBA 官方合作公告](https://www.nba.com/news/nba-aws-partnership)、[S11 AWS 中文介绍](https://aws.amazon.com/cn/sports/nba/)。

## 二 其他黑客松的规则比较

| 赛事或规则 | 官方公布的评审重点 | 能借鉴什么 |
|---|---|---|
| AWS AI Agent Global Hackathon 2025 | 价值与影响 20%，创意 10%，技术实现 50%，功能 10%，演示 10% | 架构、可复现性、真实运行及完整 Agent 流程 |
| Amazon Nova AI Hackathon 2026 | 技术实现 60%，企业或社区影响 20%，创意创新 20% | 技术集成和实际价值要有可验证证据 |
| 2026 云涌智生 | 创意度、技术可行性、商业应用性、主题切合度、完成度；各组权重在命题文件 | 主办方数据如何转化为可部署、可操作的展示 |
| MLH 标准规则 | 在其指定适用场景下，技术、设计、完成度、学习四项等权 | 真实 Demo、用户体验及对新技术的掌握 |

来源：[S04 AWS Agent 官方规则](https://aws-agent-hackathon.devpost.com/rules)、[S05 Nova 官方规则](https://amazon-nova.devpost.com/rules)、[S14 云涌智生官网](https://www.digitimes.com.tw/seminar/generativeai_hackathon_2026/)、[S12 MLH 标准规则](https://github.com/MLH/mlh-policies/blob/main/standard-hackathon-rules.md)。

这些比赛中，AWS Agent 2025 的提交期已于 2025 年 10 月结束，Nova 2026 于 2026 年 3 月结束，云涌智生 2026 的线下赛安排在 8 月。本表用于研究，不表示它们目前仍可报名。

### 具体交付要求有参考价值
AWS Agent 2025 要求公开代码仓库、架构图、项目文字说明、约 3 分钟运行演示和已部署项目链接，并强调可安装和稳定运行。Nova 2026 也要求展示实际运行，评委无需观看超过 3 分钟的部分。上述时长、公开仓库和部署要求属于对应赛事，不能直接套用到 Broadcast Code 12。
来源：[S04](https://aws-agent-hackathon.devpost.com/rules)、[S05](https://amazon-nova.devpost.com/rules)。

### 不存在一套通用的获奖公式
MLH 标准规则偏向学习与构建，对代码是否达到生产标准的要求不同于 AWS 的可复现性评分；MLH 也说明各活动可采用自己的规则。提前开发边界同样不同：MLH 标准通常要求比赛期间完成项目工作，而 AWS Agent 2025 允许符合条件的已有项目在赛期内显著更新。对本届能提前做什么，仍须单独确认。
来源：[S12](https://github.com/MLH/mlh-policies/blob/main/standard-hackathon-rules.md)、[S04](https://aws-agent-hackathon.devpost.com/rules)。

讨论建议：先练习读数据、同步视频与生成标注，再确认哪些代码允许带入正式比赛；不要因为其他赛事允许，就默认本届也允许。

## 三 值得阅读的获奖案例

### 2019 NBA Hackathon 篮球分析冠军
获奖者所在的圣母大学报道介绍了“何时使用教练挑战”的研究。团队用期望收益分析不同挑战情形，将结果表达为教练能实际使用的判断。报道列出的评审方向包括创意、统计严谨性和呈现质量。

讨论价值：一个边界清楚、篮球意义明确的问题，也能构成有说服力的作品。对本届而言，可以讨论“这一回合为何产生空位”这样的具体问题，而不是一开始就覆盖所有战术。此为案例启发，不是对其获奖原因的独立因果验证。
来源：[S08 大学报道](https://mendoza.nd.edu/news/notre-dame-business-student-wins-nba-hackathon/)。

### AWS Agent 2025 冠军 EcoLafaek
官方获奖公告介绍，其将垃圾图片识别、数据分析和热点可视化连接成环境管理应用。项目作者文档进一步给出多轮工具调用流程，以及面向评委的快速试用入口、架构说明和组件文档。

讨论价值：篮球作品也可以清楚展示“读取证据 → 分析 → 生成图形 → 给出解释”的过程。快速开始说明应告诉评委如何用一个输入复现一个结果。获奖身份由官方公告确认；技术实现细节来自作者文档，本轮未运行代码验证。

作者明确声明代码虽公开可见，但未授予任意使用、修改和分发许可。因此这里用于研究呈现方式，不作为可直接复用的开源模板。
来源：[S06 官方获奖公告](https://aws-agent-hackathon.devpost.com/updates/38140-congratulations-to-the-winners-of-the-aws-ai-agent-global-hackathon)、[S17 项目文档](https://docs.ecolafaek.com/getting-started.html)。

### AWS Agent 2025 亚军 AegisAgent
官方公告描述了面向保险审核的证据整理、条款解释和合规推理流程。值得借鉴的是输出结论时保留依据，而不是只有一段回答；公告中的性能和开发速度描述未在本轮独立复测。

讨论建议：每条篮球解说都可以关联回合编号、视频时间点及引用指标。对于证据不足的战术解释，应保留不确定性。
来源：[S06 官方获奖公告](https://aws-agent-hackathon.devpost.com/updates/38140-congratulations-to-the-winners-of-the-aws-ai-agent-global-hackathon)。

### 雄鹿队篮球分析黑客松
雄鹿官方公告显示，其赛事围绕球队篮球与商业问题开展分析，并向球队管理人员展示结果。这提供了另一种受众定位：专业球队决策者与普通球迷需要不同的解释深度。该赛事并非本届，也不能用于推断本届年龄、学生身份或队伍人数限制。
来源：[S07 雄鹿官方公告](https://www.nba.com/bucks/news/milwaukee-bucks-to-host-second-annual-analytics-hackathon)。

## 四 演示和呈现可以提前学习什么
MLH 主办方指南建议短时间内展示运行成果，并给出两分钟演示视频作为评审辅助材料的做法。它说明的是自身组织建议，不是本届路演时限。
来源：[S13 MLH 评审指南](https://guide.mlh.com/general-information/judging-and-submissions/judging-plan)。

结合本届已公布的“数据准确性、可视化表达、篮球叙事”等方向，可讨论以下展示结构：
1. 先让观众看一小段原始回合，明确“哪里看不懂”。
2. 再展示相同回合的标注与同步解说。
3. 选一处关键判断，打开数据依据和视频时间点。
4. 展示从输入到输出的运行过程，而不只播放预先制作的效果片。
5. 说明还存在的限制，例如遮挡、时间同步误差或数据缺失。

以上是我们的讨论建议。展示时长、视频格式和现场联网条件，以本届正式规范为准。

因此没有将报道中的名次、得分、导师人数或评分方式纳入“已确认事实”。多个网站转载同一篇稿件，也不构成多份独立证据。

## 六 团队下一次讨论可以聚焦的问题
以下是讨论问题，不是报名答案或已确定方案。
- 目标观众是谁：普通球迷、资深球迷还是解说员？
- 最想解释哪一种现象：高难度投篮、无球牵制、轮转失位还是关键回合贡献？
- 若只拿到事件级指标、没有球员坐标，是否仍能完成可信的可视化？
- 我们如何证明解说内容来自数据，而不是模型补写？
- 一段演示中最能体现优势的前后对比是什么？
- 需要准备哪些核验记录：时间偏差、球员匹配错误、事实性错误、生成耗时、重复运行结果？
- 哪些内容必须等组委会确认：数据格式、外部模型、提前开发、资产许可、代码公开与路演时长？

建议先读 NBA 的四个指标说明，再比较 AWS 的两份规则，最后看获奖案例的呈现方式。这一阅读顺序能让讨论先建立在正确的数据含义上。
