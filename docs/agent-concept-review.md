# 篮球解说 Agent 方案总结

- 整理日期：2026-09-29（Asia/Shanghai）。
- 状态：讨论稿，供团队继续审阅；技术方案与待确认事项见正文。
- 依据：2026-09-29 两轮方案讨论及 2026-09-28 赛前培训直播纪要。
- 实施状态：方案整理阶段；模型选型、数据采集、产品实现及效果验证待开展。

## 总体方向

- **产品目标**：通过少量动态图形与同步语音，解释回合中的战术配合、球员行为及攻防变化。
- **模块划分**：数据采集 → 数据处理 → 内容呈现。
- **设计方法**：明确叙事目标与呈现方式，结合可获取的数据，反推处理函数。
- **表达原则**：信息少而精、解释准确、重点突出、声画同步。
- **纪要核对**：当前方向与已核对的培训纪要未发现直接冲突；具体数据要求与技术规格待正式指南确认。

| 输入类别 | 本次需要盘点的内容 | 当前边界 |

| 从比赛画面提取的信息 | 尝试识别球员、球、位置、移动和持球状态，以及传球、出手、防守变化等 | 这是待测试的需求清单，不能直接写成现有模型已经具备的能力 |

### 1.2 方法与验证条件

- **候选方法**：官方文件读取、公开资料采集、国内多模态模型、YOLOv8 等可部署视觉模型；选型待定。
- **能力验证**：分别检查人物识别、跨帧关联、位置与轨迹提取、持球状态和关键动作识别。
- **环境验证**：分别检查珠海现场、澳门现场与比赛 AWS 后端的账号、服务支持、网络及实际调用结果。
- **可用性判断**：依据实测结果；不按比赛地点直接限定模型类别。口述中的具体多模态模型名称待核实。
- **数据清单**：记录来源、采集日期、版本、统计窗口、球员关联、时间基准及质量问题。

YOLOv8 属于专用视觉模型系列，包含检测、分割、姿态等不同任务变体；具体篮球素材效果尚未验证。[Ultralytics 官方说明](https://docs.ultralytics.com/models/yolov8/)（查阅：2026-09-29）。

## 2. 数据处理

### 2.1 设计原则

- **反推顺序**：叙事目标 → 呈现需求 → 所需证据 → 可用输入 → 处理函数。
- **运行顺序**：数据输入 → 关联与分析 → 标注及解说输出。
- **证据约束**：数据质量决定解释范围；区分直接观察、战术推断与数值估计。
- **输出一致性**：图形、文字与语音共用事件关联和时间轴。

### 2.2 处理职责

| 环节 | 主要内容 | 预期产出 |
|---|---|---|
| 数据关联 | 球员、事件与视频时间对齐 | 可追溯的关联结果 |
| 变化识别 | 跑位、持球、传球、出手及防守变化分析 | 回合事件与关系 |
| 战术解释 | 结合动作序列与攻防关系分析配合目的和选择依据 | 有证据支持的解读 |
| 指标使用 | 按官方口径读取指标，评估自算方法的适用范围 | 来源与方法明确的分析依据 |
| 呈现生成 | 编排图形、解说文字与语音时机 | 同步标注与解说方案 |

以上为功能职责划分，具体函数、接口及数据字段待验证。内部坐标或几何建模按实现需要决定。

### 2.3 数据口径与解释边界

- **历史统计**：保留来源、赛季、统计窗口与样本量；历史命中率不直接替代单次出手预期命中率。
- **2K 信息**：游戏属性与真实赛事统计分别记录；真实统计需追溯来源，当前未核验具体页面或字段。
- **官方指标**：按实际定义、单位、粒度及事件关联方式使用；不预设逐帧数值或未公布的计算公式。
- **自算结果**：标明方法与不确定性；自定义防守关注评分不直接标为官方球员引力。
- **战术与动因**：依据可见动作和攻防关系进行有限解释；避免将推断写成已知计划或球员内心事实。
- **证据不足**：缩小解释范围、保留不确定性或暂不展示具体数值。

### 2.4 函数反推示例

以下为讨论示例，尚未绑定实际比赛事件，未确定全部实现。

| 解释目标 | 所需证据 | 处理内容 | 呈现方式 |
|---|---|---|---|
| 吸引防守与空间形成 | 球员关联、持球状态、防守移动；可匹配的官方引力数据 | 防守关注对象与空间变化识别 | 人物高亮、移动方向、空位标记 |
| 传球利用空位 | 传球前后位置、球的转移、事件时刻 | 传球与空位的时间关系核对 | 接球点、传球方向、简短解释 |
| 出手所处的防守情境 | 出手事件、可见防守条件、可关联指标 | 事件关联、指标口径与解释依据核对 | 投手与防守人高亮、必要数据；具体指标后续再议 |

## 3. 内容呈现

### 3.1 产品定位与内容重点

- **受众**：普通篮球观众，包括缺少战术知识的观众。
- **主体**：保留原视频、球员外观、球衣号码与比赛情境，叠加必要的图形和说明。
- **视角**：以回合整体攻防关系为主，突出跑动、传球、防守变化与机会形成。
- **取舍依据**：优先解释配合过程与行为选择，减少孤立数值和无关信息。

| 内容 | 当前定位 | 表达重点 |
|---|---|---|
| 战术意图 | 重点呈现 | 多人配合的目的与机会形成过程 |
| 球员行为动因 | 重点呈现 | 当前攻防局面下的跑位、传球与出手选择依据 |
| 同步语音解说 | 与画面共同设计 | 图形含义、关注对象及动作作用 |

### 3.2 图形与语音

**拟采用方向**：虚线展示跑位示意，实线随实际执行推进，语音同步解释战术意义。

| 要素 | 表达用途 | 操作约定建议 |
|---|---|---|
| 虚线 | 跑位示意 | 明确示意或复盘属性；不表达已确认的球员预先计划 |
| 实线 | 已观察到的实际移动 | 相符路段覆盖虚线；偏离时保留真实走向 |
| 传球标记 | 球的转移方向 | 与球员跑位标记保持可区分性 |
| 局部高亮 | 关键人物、防守变化或空位 | 按当前解释重点少量使用 |
| 语音 | 对象、动作及战术作用 | 与对应图形同步出现，一次集中解释一个变化 |

具体样式与操作约定尚未完成效果验证。

### 3.3 信息控制与同步示例

- 单个时刻集中呈现一个主要解释点。
- 图形随讲解出现、推进与退出，避免路线持续累积。
- 仅展示理解当前回合所需的信息，中间计算与调试内容保留在开发环节。
- 遮挡、远景与切镜头场景仍需核验人物关联及标记位置。

以下为脚本结构示例，使用前需核对实际画面证据。

| 阶段 | 画面动作 | 解说重点 |
|---|---|---|
| 配合展开 | 跑位虚线及随执行推进的实线 | 切入动作与外线接应关系 |
| 防守变化 | 淡出旧标记，突出防守内收及外线空间 | 防守移动与空间形成 |
| 行为选择 | 短暂标出传球方向，随后淡出 | 传球对已出现机会的利用 |

## 核心指标定位与待讨论事项

### 指标定位

| 指标 | 当前定位 | 待确认内容 |
|---|---|---|
| 球员引力 | 可探索的战术分析支撑 | 官方定义与关联方式；视频中的防守变化；历史统计及 2K 信息的参考价值；处理函数与验证方法 |
| 预期命中率 | 保留后续专题讨论 | 官方数值供给、自算要求、姿态与失衡等特征提取可行性、概率估计依据 |
| 胜负影响率 | 保留后续专题讨论 | 官方定义、统计窗口、片段外比赛背景、回合贡献与整场胜负的关联边界 |

### 与呈现形式的关系

- **表达与依据**：战术标注及解说承担表达功能，核心数据提供分析依据；后台使用或画面展示方式待设计与规则核对。
- **球员引力应用**：围绕防守吸引与空间形成展开；官方指标、画面观察和背景资料分别保留来源与口径。
- **讲解粒度**：整体配合与单次出手可有不同侧重；粒度差异不构成交付方向冲突，也不意味着预期命中率必须用特写呈现。
- **计算要求**：现有纪要未要求参赛者从普通视频重建官方人体追踪及概率模型。[纪要 §1.2](https://csdn.feishu.cn/docx/FS05dToF1oUmTGxaEjdckPD1nwe#doxcnOBTvMVDgomCkGOmqssF58g)、[§2.2](https://csdn.feishu.cn/docx/FS05dToF1oUmTGxaEjdckPD1nwe#doxcneFc4oYhMVKp20Re9fYRijf)。

### 规则与判断边界

- **指标要求**：三项数据是否均需使用、是否必须显示数值、是否必须自算，待正式指南或明确答复。
- **评分判断**：当前产品取舍依据为解释价值与观看体验；“计算简单”“战术解读得分更高”等判断缺少验证或评分依据。[赛事资料整理 §4](../BroadcastCode赛事资料整理.md#4-评分与交付要求)。
- **素材范围**：两段训练视频合计约 48 秒；考试视频时长及片段外配套数据范围待确认。[赛事资料整理 §3](../BroadcastCode赛事资料整理.md#3-视频数据与平台资源)。
- **讨论范围**：本阶段不展开预期命中率与胜负影响率的计算方案，未确定实现或删去。
